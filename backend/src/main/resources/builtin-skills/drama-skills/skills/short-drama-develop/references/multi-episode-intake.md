# 多集剧本卡摄入与分集规划

用户提供多集整稿，要求补分集地图时读取本方法。输入是本轮绑定的剧本文字卡版本，保存方式见 [卡片工作流](agenvas-cards.md)。

## 建立剧集索引卡

1. read_artifacts 读取实际原文卡，确认 contentTruncated=false。正文只有预览时要求按集/场次拆卡，当前只处理完整可读范围。
2. 从明确的 EP/集标题和场次边界列出剧集，保存《剧集索引》卡：EP ID、原文 artifactId/versionId、起止行、场次范围、空集/重复/缺集/未识别段落。
3. 同一个 EP 有多个来源时不能静默选一份；显示冲突和两份版本。没有标题时给出分界候选，只把不明确部分交给用户判断。已明确授权整理的范围直接处理。
4. 索引与原文版本固定对应。重新编辑原稿生成新版本后，重建受影响索引，旧规划不能自动视为对应新版。

## 按批次补分集规划

读当前索引、已有分集规划和进度卡。按本轮实际可读的集选择批次；不要从全文摘要臆造未读集。每集写进入状态、目标/阻力、转折、回报、退出压力和下集继承事实，引用实际原稿版本及场次/行范围。

已有规划只补缺项或修订用户点名字段。完成本批核对后 create_text 建立新规划卡，或使用先前工具结果的 expectedVersion 完整 revise_artifact 现有卡。工具返回成功后才把 EP 与输出 versionId 记进进度卡；失败保存候选，避免新建同名卡掩盖失败。

## 覆盖核对与续接

对照索引列出已核对的 EP、缺集、重复候选、来源变化、未重新核对的历史记录。总数只包含明确提供的剧集。进度卡记录本批范围、实际产出版本、未规划 EP 与下一步；后续运行由用户绑定这些卡片版本继续。

把原稿分界与创作判断分开：索引只说明哪里是一集，规划才说明该集如何转折和兑现。不能为了统一集数改写用户原稿。
