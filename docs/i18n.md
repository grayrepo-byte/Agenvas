# i18n 配置

界面支持 `en`（English）、`zh`（中文）、`ru`（Русский）、`ja`（日本語）。初始化、登录、应用侧栏和系统设置共用 `LanguageSelect`，不创建语言专属页面或路由。首次访问按浏览器支持的语言顺序选择；用户选择保存在 `agenvas.locale.v1`，同源标签页同步。浏览器存储受限时仍可切换，本页提示偏好未保存。切换只刷新显示文案，保留表单与画布草稿。

语言入口使用地球按钮和四语言选择窗口，不使用下拉框。展开侧栏显示当前语言名称，折叠侧栏只保留图标，并以提示与无障碍名称说明当前语言；手机顶部导航恢复显示名称。窗口按当前界面语言展示四种语言名称，英文界面显示 English、Chinese、Russian 和 Japanese，标记当前选择，点击立即切换并关闭；偏好保存失败时保留窗口和错误说明，可再次点击重试。复用公共模态窗口的 Tab 焦点限制、Esc 关闭与关闭后焦点恢复。折叠导航与手机验证见 交互调整记录（开发记录不随源码公开）。

前端配置为 `frontend/src/shared/i18n/index.ts`，资源为其 `locales/{zh,en,ru,ja}.json`。消息使用稳定英文语义 key，按领域、功能和用途命名，例如 `auth.login.title`、`canvas.selection.count`、`media.editor.saveFailed`、`common.retry`。禁止使用任何语言的原文、整句转写或无含义的编号作为 key；修改文案只调整词典值，同一功能和用途的 key 保持不变。通用动作归入 `common`，领域专用消息归入对应领域，避免跨模块引用某个页面的内部消息。四份词典保持扁平的点分隔键，便于搜索与对照。

`MessageKey` 从中文词典的键集合推导；`t`、`translate` 与延迟显示映射只接受该类型，拼写错误、中文原文和任意字符串在类型检查时拒绝，不保留旧原文 key 的兼容层。组件通过 `useLocale` 订阅语言，避免模块初始化时固定语言。带变量的完整句子使用占位符，例如 `t("canvas.selection.count", { "0": count })`；翻译文件必须保持中文词典**值**中的全部占位符和数量，key 本身不包含插值。显示用常量表通过 getter 延迟调用 `t`。日期/数字使用 `getFormatLocale`、`formatDate`、`formatNumber`，不要固定 `zh-CN`。

新文案加入四份词典；`pnpm lint` 检查英文语义 key 格式、重复 key、资源键集合、词典值的插值变量、未登记消息、英文及俄语词典混入中文和新增中文界面硬编码（包括内置 prompt/instruction/text/value 默认值及插值模板）；`pnpm typecheck` 约束动态引用，`pnpm test:i18n` 运行检查器、语言切换与动态标签的专项回归。音色筛选使用稳定语言/场景标识和类型化显示映射，音色目录保留官方原名、Provider ID 和试听地址，以固定 ID 提供当前界面语言的显示别名，选择与提交仍只使用原 ID；外部未知名称保持原值；工作流按固定 ID 映射显示 key，原始协议标签、参数值与提交定义不携带界面 key。用户标题、文本、提示词、生成结果、错误码、音色名称及运行历史不是界面翻译模板，不对任意服务端数据调用 `t`。

产品安装的风格、功能提示词、Skill 和本地处理能力使用稳定身份及原始默认字段值识别显示文案，按当前语言在渲染时翻译。元数据已改名或来自个人/导入内容时保留原值；表单草稿、保存载荷、提示词正文、冻结来源和历史内容不进行批量翻译或迁移。内置音频助手指令与 MV 初始提示词从当前词典生成，用户原文按字面附加；语言切换不改写已保存的创作内容。

空白文字/图片/视频/音频节点在首次创建时固定标题；音频助手与 MV 创建动作同时固定完整输入。响应丢失后的重试沿用原动作身份和原请求，即使界面语言已切换；恢复已保存的草稿仍比较原输入，真实的用户修改继续报冲突，不覆盖现有内容。

Skill 搜索同时匹配原始元数据与当前请求语言的内置显示名称/说明；别名只用于已登记包及仍匹配原始默认字段的记录，不改变个人内容。总数、分页游标和分类继续使用同一过滤条件。语言加入三个 Skill 列表的缓存键，切换时保留搜索草稿并按新语言重新读取。固定版本尚未确认目录来源时，候选内置说明显示本地化加载/失败与重试反馈，确认个人副本后保留原文。`pnpm test:interface-locales` 使用合成数据在生产 CSS 的 Chromium 中检查英文默认界面、语言切换和俄语/日语布局，不连接真实模型或已有业务数据。

新建派生媒体节点时，图片/视频操作、上传用途和音频裁剪的默认后缀按当前请求语言解析后保存，来源用户标题不变；没有 HTTP 请求的后台操作使用英文默认值，不依赖 JVM 默认语言。已有标题不随语言切换重新命名。静音视频的系统提示在受理时固定进原任务，后台处理沿用该值。没有名称的工作流节点使用本地化后备标签，外部定义已有的节点名称保留原值。

所有 JSON 和 multipart 请求由共享 API client 添加当前 `Accept-Language`。原生 EventSource 不支持自定义语言请求头；项目 SSE 数据保持稳定枚举和原始业务内容，界面根据当前词典显示状态，因此语言切换不重连或改变游标。

后端 `shared/i18n` 使用 Spring MessageSource，资源在 `backend/src/main/resources/i18n/messages*.properties`。`messages.properties` 是唯一中文来源，不再维护重复的 `messages_zh.properties`；英文、俄语和日语分别维护 `_en`、`_ru`、`_ja` 文件。`ApiMessage` 从根资源包读取中文诊断，中文请求直接使用基础资源，避免双份中文词典更新不同步。公开异常的标题、详情统一使用 `ApiMessage`，只携带稳定资源键与参数；`ApiProblemException` 不接受原始字符串。动态说明使用完整句子模板，例如 `ApiMessage.of("api.video-generation-parameters.video-generation-parameters-contain-an-unknown-field", field)`，由 HTTP 层按请求语言渲染，保留具体字段、范围和上限，不拼接中文片段。参数只插值一次，ID、枚举和管理员填写的字段名称保持原值；不自动格式化数字或解释参数里的占位符。`getMessage()` 是中文诊断说明，不能用于 HTTP 本地化响应。

新增公开消息只需更新中文基础文件及三份翻译文件，保持同一键及占位符集合和数量一致。`MessageCatalogTest` 直接读取每种语言的资源，避免父词典回退掩盖翻译缺项；拒绝重复键、空翻译、占位符不匹配及英俄词典混入中文。测试按语言报告缺失或多余的键，并只输出有问题的条目，不打印整本词典。每个登记消息均通过真实 `ApiMessage` 构造与四语言渲染验证参数契约；不依赖 Java 源码的写法或未使用消息的数量，保留持久错误描述可能引用的历史键。Bean Validation 共用 MessageSource 和请求 Locale，自定义校验消息使用资源键；字段路径和稳定错误码不变。所有响应声明 `Content-Language` 并追加 `Vary: Accept-Language`；不支持或无效请求语言回退中文，`q=0` 不作为候选。服务器的 JVM 默认语言不会改变协商结果。

后端专项命令：在 `backend` 执行 `./mvnw -Dtest=MessageCatalogTest,ApiI18nTest,LocalizedResponseTest,SecurityI18nTest test`。删除旧资源文件后，本地曾构建过的工作区先执行 `./mvnw clean`，避免 `target/classes` 残留旧资源；全新 CI 和镜像构建无需额外处理。

认证/CSRF、普通业务异常、素材 416、资源转存失败和 RunningHub 导入警告都在返回边界本地化。转存失败在现有 `error_detail` 文本列保存 `{key, arguments}` 描述，读取时按当前请求语言渲染为公开的字符串；无需改表或更新历史记录。历史静态中文失败说明按已有模板匹配，无法识别的旧动态错误使用安全通用说明。系统原始日志、调试采集正文、已保存的 Run 对话及业务内容保留原值；意外实现异常只返回通用本地化错误，不回显堆栈、密钥或请求值。

词典最初由机器翻译建立，后续按实际界面上下文校正英文、俄语和日语入口、操作、默认元数据及错误提示中识别出的直译和术语问题。资源随应用打包，运行时不访问翻译服务、不需要翻译账户或 Key。此次审阅不等同于全部俄语、日语文案经过母语者审校；长篇专业设置和创作术语仍需进一步审阅。

升级只增加可选请求头和响应头及本地化显示文案，公开 API 数据结构、枚举及数据库表结构不变；客户端必须继续依赖稳定 code，不比较本地化 title/detail 字符串。转存失败详情的内部存储格式已改为消息描述；回退旧版代码时，旧版不能渲染新建记录中的描述，需要一并回退这些记录的展示逻辑。
