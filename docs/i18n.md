# i18n 配置

界面支持 `en`（English）、`zh`（中文）、`ru`（Русский）、`ja`（日本語）。初始化、登录、应用侧栏和系统设置共用 `LanguageSelect`，不创建语言专属页面或路由。首次访问按浏览器支持的语言顺序选择；用户选择保存在 `agenvas.locale.v1`，同源标签页同步。浏览器存储受限时仍可切换，本页提示偏好未保存。切换只刷新显示文案，保留表单与画布草稿。

语言入口使用地球按钮和四语言选择窗口，不使用下拉框。展开侧栏显示当前语言名称，折叠侧栏只保留图标，并以提示与无障碍名称说明当前语言；手机顶部导航恢复显示名称。窗口按各语言原名展示四个按钮，标记当前选择，点击立即切换并关闭；偏好保存失败时保留窗口和错误说明，可再次点击重试。复用公共模态窗口的 Tab 焦点限制、Esc 关闭与关闭后焦点恢复。折叠导航与手机验证见 交互调整记录（开发记录不随源码公开）。

前端配置为 `frontend/src/shared/i18n/index.ts`，资源为其 `locales/{zh,en,ru,ja}.json`。`t` 的消息 ID 是中文源文案；组件通过 `useLocale` 订阅语言，避免模块初始化时固定语言。带变量的完整句子使用占位符，例如 `t("已选 {0} 个节点", { "0": count })`；翻译文件必须保持全部占位符和数量。显示用常量表通过 getter 延迟调用 `t`。日期/数字使用 `getFormatLocale`、`formatDate`、`formatNumber`，不要固定 `zh-CN`。

新文案加入四份词典；`pnpm lint` 检查资源键集合、插值变量、未登记消息和新增中文界面硬编码。语音/工作流的固定协议元数据保持原始参数值，只在显示入口翻译注册过的标签。用户标题、文本、提示词、生成结果、错误码、音色名称及运行历史不是界面翻译模板，不对任意服务端数据调用 `t`。

所有 JSON 和 multipart 请求由共享 API client 添加当前 `Accept-Language`。原生 EventSource 不支持自定义语言请求头；项目 SSE 数据保持稳定枚举和原始业务内容，界面根据当前词典显示状态，因此语言切换不重连或改变游标。

后端 `shared/i18n` 使用 Spring MessageSource，资源在 `backend/src/main/resources/i18n/messages*.properties`，默认中文。公开异常的标题、详情统一使用 `ApiMessage`，只携带稳定资源键与参数；`ApiProblemException` 不接受原始字符串。动态说明使用完整句子模板，例如 `ApiMessage.of("api.video-generation-parameters.video-generation-parameters-contain-an-unknown-field", field)`，由 HTTP 层按请求语言渲染，保留具体字段、范围和上限，不拼接中文片段。参数只插值一次，ID、枚举和管理员填写的字段名称保持原值；不自动格式化数字或解释参数里的占位符。`getMessage()` 是中文诊断说明，不能用于 HTTP 本地化响应。

新增公开消息须在基础文件与四份语言资源中添加同一键，并保持占位符集合和数量一致。`MessageCatalogTest` 直接读取资源文件，避免父词典回退掩盖缺项；使用 JDK 语法树检查全部生产 `ApiMessage.of` 引用和参数数量。Bean Validation 共用 MessageSource 和请求 Locale，自定义校验消息使用资源键；字段路径和稳定错误码不变。所有响应声明 `Content-Language` 并追加 `Vary: Accept-Language`；不支持或无效请求语言回退中文，`q=0` 不作为候选。服务器的 JVM 默认语言不会改变协商结果。

认证/CSRF、普通业务异常、素材 416、资源转存失败和 RunningHub 导入警告都在返回边界本地化。转存失败在现有 `error_detail` 文本列保存 `{key, arguments}` 描述，读取时按当前请求语言渲染为公开的字符串；无需改表或更新历史记录。历史静态中文失败说明按已有模板匹配，无法识别的旧动态错误使用安全通用说明。系统原始日志、调试采集正文、已保存的 Run 对话及业务内容保留原值；意外实现异常只返回通用本地化错误，不回显堆栈、密钥或请求值。

本次词典以机器翻译建立，已校正主要入口与安全/任务提示。资源随应用打包，运行时不访问翻译服务、不需要翻译账户或 Key；长篇俄语/日语专业文案仍需要母语审校。相关验证和未运行项见 验证记录（开发记录不随源码公开）。

升级只增加可选请求头和响应头及本地化显示文案，公开 API 数据结构、枚举及数据库表结构不变；客户端必须继续依赖稳定 code，不比较本地化 title/detail 字符串。转存失败详情的内部存储格式已改为消息描述；回退旧版代码时，旧版不能渲染新建记录中的描述，需要一并回退这些记录的展示逻辑。
