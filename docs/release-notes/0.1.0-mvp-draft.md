# Agenvas 0.1.0 MVP — release notes draft / 发行说明草案

Status: **not released**. This document is a review artifact, not a claim that the MVP or production gates have passed. The authoritative open items remain in [the development checklist](../DEVELOPMENT-CHECKLIST.md).

## Current supported scope

- Self-hosted, single-administrator application with React canvas, Java 21/Spring Boot server, PostgreSQL 17, local media volume, and REST/SSE APIs.
- Default account-free Mock path: three-shot planning, separate image and video plan approvals, exact keyframe selection, local single-shot redo, an export proposal that requires approval, and ordered silent MP4 export. Mock outputs are marked as demonstrations. [Browser Mock golden-path evidence](../evidence/T-browser-mock-golden-path.md).
- Persistent Run/Task, immutable ArtifactVersion, private Asset, approval, lease/fencing, UNKNOWN recovery, and project event replay paths have PostgreSQL integration coverage. See [the evidence index in the checklist](../DEVELOPMENT-CHECKLIST.md).
- OpenAI-compatible chat and fixed ComfyUI image/video adapters are **candidate integrations** tested with fake HTTP services and real PostgreSQL. No selected real LLM/GPU/model has passed an end-to-end generation test. They must not be advertised as verified Provider support.

## Upgrade and recovery boundary

This is a development snapshot with no compatibility guarantee. Back up PostgreSQL, the local media volume, and all current and historical credential-encryption keys before changing the image or database. For a restored old snapshot, first run with `AGENVAS_RECOVERY_MODE=true`, inspect unresolved/UNKNOWN external attempts and assets, then deliberately allow Flyway and workers to resume. Do not bulk-reset running tasks or blindly resubmit Provider requests. Follow the [backup/restore runbook](../operations/backup-restore.md). Flyway migrations are append-only; there is no automatic schema rollback. The current source contains migrations through V35; old video assets have no persisted duration and must be re-archived before starting a new sequential export. A production upgrade/recovery rehearsal for this candidate is not complete.

Run creation now accepts an optional model-configuration source/version pair from the preflight response. The current canvas always supplies both and receives HTTP 409 if configuration changed before confirmation; API callers that omit both retain the previous create/replay behavior. `RunPolicySnapshot` now explicitly documents these already-persisted identity fields. No database migration is required for this contract change.

During application shutdown, new Run creation now returns HTTP 503 with `APPLICATION_STOPPING`, and scheduled workers stop claiming new Tasks. Existing persisted work is not bulk-reset; it remains subject to lease/fencing and UNKNOWN recovery. This adds a documented error response to `createRun` without changing its successful response or database schema. An isolated packaged JVM SIGTERM test and a fresh Compose server-container stop/restart have passed; shutdown with an active external submission remains open. See [shutdown evidence](../evidence/T29-shutdown-admission.md) and [fresh Compose smoke evidence](../evidence/T29-fresh-compose-smoke.md).

Fresh Compose deployments now require explicit nonempty database and bootstrap secrets; the documented command uses `--env-file .env` because the root example file is not implicitly loaded by the current `-f deploy/compose.yaml` invocation. Historical public example values are rejected at application startup. An existing installation that used those values needs coordinated credential rotation before upgrading, not merely an edited `.env`. See [installation-secret evidence](../evidence/T03-bootstrap-secret-fail-closed.md).

## Known release blockers

- Real LLM, ComfyUI image and video compatibility and combined golden path remain unverified; the default Mock path is not evidence of real generation.
- The full failure/security gates and sustained SSE-memory/performance gates remain open. An isolated 300-card/600-relation canvas slice has been measured, but it does not prove all media-card distributions or API latency targets. See [canvas-capacity evidence](../evidence/T28-canvas-capacity.md) and [HTTP p95 instrumentation](../evidence/T28-http-p95-instrumentation.md).
- Container FFmpeg is built with GPL-enabled options; its redistributable license obligations and the media workflow/model/Custom Node licenses need a separate release review. See [dependency baseline](../dependency-baseline.md) and [MVP specification §16.5](../MVP-SPEC.md).
- A verified private vulnerability-reporting channel, formal project license decision, NOTICE, and reviewed release SBOM/license inventory are still pending. See [SECURITY.md](../../SECURITY.md) and T30 in the checklist.
- Fresh-machine installation, backup/restore including keys, and production recovery time have not passed the full release gate.
- Credential rotation of existing installations that used historical public defaults has not been performed automatically.

## Verification reference

CI defines frontend typecheck, lint, tests, build; backend `./mvnw verify`; Compose config checks; Trivy source/image vulnerability scans; and per-image CycloneDX SBOM/license inventory. These commands and workflow definitions are not substitutes for inspecting a specific release run. The latest local code checks and their limitations are recorded in the linked `docs/evidence/` files. Release publication must record exact commit, built image digests, CI run, SBOM files, and real-provider test configuration/results separately.
