# Agenvas 0.1.0 MVP — release notes draft / 发行说明草案

Status: **not released**. This document is a review artifact, not a claim that the MVP or production gates have passed. The authoritative open items remain in [the development checklist](../DEVELOPMENT-CHECKLIST.md).

## Current supported scope

- Self-hosted, single-administrator application with React canvas, Java 21/Spring Boot server, PostgreSQL 17, local media volume, and REST/SSE APIs.
- Account-free Mock development path for text, image, video, and audio cards. Users run individual media drafts and select immutable results; Agent media batches require approval. Mock images, video clips, and audio are marked as demonstrations. Project export produces a manifest; shot planning, keyframe selection, and video concatenation have been removed.
- Persistent Run/Task, immutable ArtifactVersion, private Asset, approval, lease/fencing, UNKNOWN recovery, and project event replay paths have PostgreSQL integration coverage. See [the evidence index in the checklist](../DEVELOPMENT-CHECKLIST.md).
- OpenAI-compatible chat and fixed ComfyUI image/video adapters are **candidate integrations** tested with fake HTTP services and real PostgreSQL. No selected real LLM/GPU/model has passed an end-to-end generation test. They must not be advertised as verified Provider support.

## Upgrade and recovery boundary

Default `deploy/compose.yaml` now selects configured LLM/media providers; `deploy/compose.dev.yaml` explicitly enables Mock with a separate default project and volumes. Existing deployments using Mock must choose the development file or explicitly retain their mode overrides. These mode overrides alone do not alter settings or task history. Media configuration now uses only the administrator capability catalog. The environment ComfyUI route and one-time legacy configuration import have been removed; diagnostics media modes are `MOCK` and `CONFIGURED`. Existing media requests retain their pinned catalog connection and capability versions.

Before the first release, the V1–V77 development migrations (76 files; no V61) have been consolidated once into `V1__initial_schema.sql`, containing 67 business tables and 28 required seed rows without user data or credentials. Every business table, column, constraint, index, trigger, and function has a persisted database comment. Retired creative-reset and legacy-media-import markers, the old ComfyUI configuration registry, task dependencies, and redundant fields have been removed. Startup has no development-reset runner or environment-media importer. Installation timestamps use `now()`. Future changes start at V2 and remain append-only; the new V1 must not be rewritten. See the [ADR 0012 supplement](../adr/0012-jooq-persistence.md#2026-10-02-未发布基线重建).

The rebuilt version requires an empty database and asset volume. For a retained environment, use a separate installation; a developer may instead reset an explicitly identified local Compose project after creating and verifying a consistent backup. Resetting discards its online data and does not import old business data into the new baseline. A database with the old V1–V77 Flyway history cannot be directly upgraded; do not use `repair`, delete history rows, or automatically baseline it to hide the mismatch. Preserve a consistent backup of PostgreSQL, archived media, current and historical encryption keys, configuration, and the matching old image/Git revision. Restore old history with that old version and `AGENVAS_RECOVERY_MODE=true` to inspect unresolved/UNKNOWN attempts and original Provider requests before resuming compatible workers. The current version provides no automatic old-database migration or data import; the project export is only a manifest. Do not bulk-reset running tasks or blindly resubmit Provider requests. Follow the [backup/restore runbook](../operations/backup-restore.md). Historical migration checks retain their original scope; they are not verification of the consolidated V1. A production upgrade/recovery rehearsal for this candidate is not complete.

The unreleased API contract also removes unused `Task.providerId`, the `ASSET_INGEST` task kind, `Asset.status` and its pending/ready markers, `AgentBinding.bindingType`, `UsageQuantity.exportCount`, and generated-media content `providerConfigVersion`. Consumers must regenerate API types and remove those fields; old generated-media content is not accepted by the new whitelist. Usage ledger `providerConfigVersion` remains and now records the actual pinned media connection version or LLM configuration version. The retired global `AGENVAS_PROVIDER_CONFIG_VERSION` is no longer used. These changes accompany the empty-database baseline and have no automatic compatibility layer.

Run creation now accepts an optional model-configuration source/version pair from the preflight response. The current canvas always supplies both and receives HTTP 409 if configuration changed before confirmation; API callers that omit both retain the previous create/replay behavior. `RunPolicySnapshot` now explicitly documents these already-persisted identity fields. No database migration is required for this contract change.

During application shutdown, new Run creation now returns HTTP 503 with `APPLICATION_STOPPING`, and scheduled workers stop claiming new Tasks. Existing persisted work is not bulk-reset; it remains subject to lease/fencing and UNKNOWN recovery. This adds a documented error response to `createRun` without changing its successful response or database schema. An isolated packaged JVM SIGTERM test and a fresh Compose server-container stop/restart have passed; shutdown with an active external submission remains open. See shutdown evidence (development record omitted from source distribution) and fresh Compose smoke evidence (development record omitted from source distribution).

Fresh Compose deployments now require explicit nonempty database and bootstrap secrets; the documented command uses `--env-file .env` because the root example file is not implicitly loaded by the current `-f deploy/compose.yaml` invocation. Historical public example values are rejected at application startup. An existing installation that used those values needs coordinated credential rotation before upgrading, not merely an edited `.env`. See installation-secret evidence (development record omitted from source distribution).

## Known release blockers

- Real LLM, ComfyUI image and video compatibility and combined golden path remain unverified; the development Mock path is not evidence of real generation.
- The full failure/security gates and sustained SSE-memory/performance gates remain open. An isolated 300-card/600-relation canvas slice has been measured, but it does not prove all media-card distributions or API latency targets. See canvas-capacity evidence (development record omitted from source distribution) and HTTP p95 instrumentation (development record omitted from source distribution).
- Container FFmpeg is built with GPL-enabled options; its redistributable license obligations and the media workflow/model/Custom Node licenses need a separate release review. See [dependency baseline](../dependency-baseline.md) and [MVP specification §16.5](../MVP-SPEC.md).
- A verified private vulnerability-reporting channel, formal project license decision, NOTICE, and reviewed release SBOM/license inventory are still pending. See [SECURITY.md](../../SECURITY.md) and T30 in the checklist.
- Fresh-machine installation, backup/restore including keys, and production recovery time have not passed the full release gate.
- Credential rotation of existing installations that used historical public defaults has not been performed automatically.

## Verification reference

CI defines frontend typecheck, lint, tests, build; backend `./mvnw verify`; Compose config checks; Trivy source/image vulnerability scans; and per-image CycloneDX SBOM/license inventory. These commands and workflow definitions are not substitutes for inspecting a specific release run. The latest local code checks and their limitations are recorded in the linked development records omitted from source distribution files. Release publication must record exact commit, built image digests, CI run, SBOM files, and real-provider test configuration/results separately.
