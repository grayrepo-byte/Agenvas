# JVM 媒体工作流动态接入设计（第二阶段）

日期：2026-09-25

状态：待用户审阅书面规格；依赖[第一阶段规格](./2026-09-25-media-capability-foundation-design.md)

## 1. 目标与适用范围

管理员给出有文档、可从自托管服务访问的工作流平台 HTTPS API 资料、账号凭证和允许接入的远端应用或工作流；接入 Agent 自动生成能力草案和 Groovy 钩子脚本。管理员审阅、用模拟响应测试并发布后，普通创作 Agent 才能在计划步骤中选择该能力。一个平台连接可发布多条用途不同的图片或视频能力。新增符合本设计约束的 RunningHub 类工作流平台及其工作流，应通过配置和发布完成，不改计划、审批、画布或 Java 平台适配代码。

支持自定义请求签名、鉴权交换、上传、提交、轮询、多步分支及结果映射。范围限于 HTTPS；浏览器交互、WebSocket、gRPC、任意本地协议、任意 URL 导入和服务器 Custom Node 安装不在本阶段。外部 API 必须有可固定的服务身份和可执行的输入输出约束；无法从文档与模拟测试证明语义正确的发布版本标记“未实测”，不能声称真实平台兼容。平台 API 若无可靠原请求核对手段，仍可接入，但提交不确定时保持 UNKNOWN。

第一阶段的 Mock/ComfyUI 内置适配器继续可用。OpenAI GPT Image 2 和 Google Nano Banana 2 是后续 BUILTIN 代码适配器，不使用本设计的 Agent 生成 Groovy 脚本；Seedance 等直接模型 API 也优先走 BUILTIN。普通 Agent 工具仍无任意 HTTP 或生成代码执行权；新权限仅属于管理员已发布、版本固定、隔离运行的 SANDBOXED_GROOVY 工作流能力。该受控例外是对旧 P0 “不得动态插件/任意 HTTP”约束的明确产品变更，实施时同步主规格、AGENTS.md、ADR、检查清单和安全验收，不把旧禁令静默删除。

## 2. 草案、审阅与发布

管理员在设置页新建或选中平台连接，输入精确 HTTPS 主机/路径范围与服务端加密凭证，提供 API 文档/OpenAPI 内容或受控文档链接，以及需要接入的远端应用、模型或工作流 ID。若平台提供列表/Schema 接口，管理员可授权只读发现以选择若干工作流；没有机器可读发现接口时由管理员提供文档和 ID。文档链接仅由管理员提交，经独立的公共 HTTPS 安全抓取器检查 DNS、重定向、大小与类型，不递归抓取，也不作为项目素材导入。文档及返回内容均视为不可信数据，只用于产生草案，不能指令 Agent 扩大权限。

接入 Agent 读取文档的安全摘要和脱敏测试反馈，为每条所选工作流生成独立草案：用途、主输出类型、类型化输入输出端口、参数约束、远端身份及版本/指纹检查、Groovy 钩子、请求地址/方法/路径允许列表、所需凭证与签名方式、费用来源、超时/并发上限、可核对/幂等声明及模拟响应夹具。它不能读取明文密钥、发布能力或发起付费测试。管理员在界面查看文档来源、生成源码差异、请求与凭证权限、输出数据流向以及静态检查结果，可编辑草案并反复模拟测试。

发布必须由管理员执行，要求 Schema/Groovy 脚本静态校验、受限解析和模拟 API 测试通过；真实能力调用可选，不是发布门禁。发布生成不可变 media_capability_version，保存脚本源码 hash 与 Groovy 运行时版本、源文档摘要、审核者与时刻、模拟测试证据及 LIVE_VERIFIED 或 UNTESTED 标记。LIVE_VERIFIED 只能由记录了真实请求及结果的验收流程产生，管理员不能手工勾选。管理员更改 Groovy 脚本、工作流身份、端口或能力请求权限时须发布新能力版本；更改地址或凭证值须生成新连接版本，若同时改变能力允许的地址/凭证范围，还须发布新能力版本。旧版本保留供原任务核对；旧任务需要旧密钥时从历史密钥环读取，缺失则 BLOCKED。

远端可变工作流必须提供可核对的稳定版本、不可变 ID 或内容指纹；发布时固定并在新提交前检查。若平台不能提供任一种可验证身份，草案可保存但不能发布为可执行能力。管理员可停用能力以阻止新提交，已受理任务继续按原版本尝试核对。真实测试缺失不等于身份固定要求豁免。

## 3. Groovy 钩子契约与隔离

接入脚本采用 Groovy，运行在 Java 21 JVM 上。接入 Agent 为每条能力生成一份短脚本，管理员直接审阅和修改。脚本以固定基类或 Binding 暴露 prepare、submit、query、reconcile、resolveOutput 等钩子及受控 ctx 接口；可使用条件、循环和自定义签名计算，但只能通过 ctx 请求平台 HTTP 动作。钩子返回标准化的 COMPLETED、ACCEPTED、WAITING、REJECTED 或 UNKNOWN 结果及经校验的输出句柄。输入输出经版本化 JSON 契约传递，脚本不能直接修改计划、Task、Asset、Artifact、用量或审批状态，也不能把平台原始响应当作可信业务 DTO。

GroovyShell 可在现有 Java 21 JRE 上解析脚本；无需把生产镜像换成 JDK，但须增加并固定经过构建测试的 Groovy 运行时依赖。草案在受限运行时中解析并用模拟 API 测试；发布仅保存不可变脚本源码、源码摘要、Groovy 运行时版本及测试证据。运行时按固定版本重新解析，不动态下载依赖；升级 Groovy 运行时须保留旧版本直到引用它的任务终结，历史版本缺失时任务 BLOCKED，不能用新运行时猜测重放。禁止 @Grab/Grape、外部 JAR、自定义 AST 变换和脚本加载其他代码。Groovy 的 SecureASTCustomizer 可用于限制语法，但其官方文档明确说明它不是沙箱，不能代替进程和 OS 隔离。[Groovy 集成文档](https://docs.groovy-lang.org/latest/html/documentation/guide-integrating.html)；[SecureASTCustomizer 说明](https://docs.groovy-lang.org/latest/html/api/org/codehaus/groovy/control/customizers/SecureASTCustomizer.html)。

脚本只在由同一 Spring Boot 部署单元启动和监管的独立受限子 JVM 中解析、模拟测试和执行，绝不由主进程 GroovyShell 或 ClassLoader 加载。子进程仅装入固定 Groovy 运行时和窄钩子 SDK，不装入 Spring 应用及数据库驱动；默认无数据库、项目文件卷、环境变量、直接网络或执行其他进程的权限。OS 隔离负责阻断脚本通过 Groovy/Java 标准库直接访问文件和网络，类路径限制与静态检查只是补充。脚本只通过有类型、受限额的进程间接口请求 HTTP 代理、签名/凭证服务、稳定时钟/nonce 与媒体句柄。每次调用限制 CPU、内存、墙钟时间、动作次数及请求/响应大小；子进程结束即释放类与内存，避免长期缓存动态类。

标准签名由受控签名接口处理；特殊算法确需密钥材料时，仅向该子 JVM 隔离内存提供短寿命、最小权限材料，审核页明确展示其可见范围。密钥不得进入 Agent、浏览器读取响应、日志或项目导出。管理员若发布了可读取明文密钥的恶意脚本，它仍可能把密钥送往允许的服务端，因此优先使用签名接口、最小权限密钥和审阅脚本的数据流。

隔离运行时先通过可行性门禁：恶意 Groovy 脚本尝试读取文件/环境、直连网络、执行命令、无限循环、内存膨胀及向非允许目标发送数据，均不能越过边界；同时验证自托管目标平台的打包与重启。门禁未过时不能发布动态能力，也不能退回主 JVM 直接执行。此门禁不影响第一阶段内置能力运行。[Oracle 不可信代码隔离建议](https://www.oracle.com/java/technologies/javase/seccodeguide.html)。

## 4. HTTPS 代理与逐次动作账本

生成代码只提交结构化请求描述，不自行创建 socket。代理按发布版本检查主机、端口、方法、路径模板、凭证范围、请求体/响应大小、媒体源与目的；每次解析 DNS 都拒绝私网/环回/元数据地址和地址漂移，默认拒绝重定向。ComfyUI 的精确本地地址例外只给内置适配器，不从一个管理员生成代码扩展成整个内网许可。媒体下载、OAuth 令牌交换和上传同样走代理及独立的允许规则。代理流式处理媒体，子 JVM 只持有不透明句柄。

每次外部动作以 taskId、attemptNo、钩子调用序号和稳定 actionKey 形成唯一身份。发请求前在短事务保存请求摘要、权限/连接/能力版本、租约 epoch、关联键和动作类型；网络在事务外执行。返回后持久保存脱敏结果摘要，以及供生成代码确定性回放的有界加密响应载荷或受控暂存句柄，再继续 Groovy 钩子。子 JVM 重启并从头运行钩子时，同键同摘要的已完成动作回放保存结果；同键不同摘要为冲突，不能静默发送变化请求。时间与 nonce 由代理按动作键固定，避免重放构造出不同签名。诊断 API 只返回安全摘要和所需原请求 ID，不返回明文密钥或原始响应；内部加密载荷至少保留至任务终结和恢复窗口结束。

非幂等提交若在调用后、持久确认前崩溃或超时，动作和 Task 进入 UNKNOWN；有可靠原请求 ID/预先关联键时只调用已发布的 reconcile/query 钩子核对原请求。查询为空不证明未受理。没有可靠核对时等待人工决定是否承担潜在重复费用，绝不自动重提、换能力或运行下游。已保存 ACCEPTED 的动作只查原外部任务。只读查询、结果下载和本地归档可在固定原请求下有限重试；归档失败不触发新的生成提交。旧 Worker 的动作/Task 结果必须通过 epoch 与状态 CAS，取消后的晚到结果按原输入版本归档历史。

Groovy 钩子的多步流程每一个可能产生外部副作用的请求都受上述检查点约束，包括远端上传、创建临时资源及发起生成。只要某步状态不确定，后续有副作用的步骤不得继续。平台声明的幂等只有在相应协议经过专门测试后才能让代理自动安全重放；模拟测试不能证明真实平台具有幂等保证。

## 5. 计划使用、界面与 API

运行时 Agent 仅收到已发布能力的用途、适用输入输出、约束、成本来源和测试标记。它为每一步提出能力 ID 与端口绑定；沿用第一阶段的计划服务，并为 SANDBOXED_GROOVY 步骤额外固定脚本源码 hash 与运行时版本、输入版本和出站数据范围。用户逐步骤查看和确认，改选或补输入生成新计划修订；批准前不执行平台生成请求。若未实测，审批页与任务详情均显示该事实及费用未知时的风险。管理员发布、默认值更改不修改已经批准的步骤；被停用能力的未提交任务 BLOCKED，已受理任务仍按原版本核对。

管理员 API 增加草案创建、文档导入/受控发现、草案版本、Groovy 解析诊断、静态检查、模拟测试、发布、停用及历史审计；项目 API 只暴露安全能力候选和逐步骤计划修订。所有修改受管理员身份、CSRF、Idempotency-Key 与 expectedVersion 约束；同键异载荷 409。项目 SSE 只发布计划/任务状态与脱敏能力摘要。同步更新 OpenAPI、Java DTO、生成的 TS 类型、Flyway、主规格、ADR 与部署备份说明。备份必须包含能力版本、不可变脚本源码与对应运行时、动作账本、Asset 卷、主密钥和历史密钥环。

## 6. 验收与非承诺

用真实 PostgreSQL 和至少两种差异明显的本地假 HTTPS 工作流平台验收：一种同步图像并使用自定义签名，另一种多步上传/异步视频任务；再覆盖同一连接多工作流、动作迁移所需视频输入、文档注入、生成代码越权/资源耗尽、SSRF/DNS/重定向、密钥泄漏、同键请求冲突、并发审批、进程中断各检查点、UNKNOWN 人工核对、取消晚到、归档失败及 SSE 重连。模拟测试能证明本系统的编排与安全行为，不能证明某真实供应商实际兼容。真实 RunningHub 类平台案例各自标注是否做过真实调用；未调用的一律保持 UNTESTED，不在验收报告中声称真实生成完成。GPT Image 2、Nano Banana 2 的真实协议验收属于各自 BUILTIN 适配器的后续工作。

本设计的“无需改代码”适用于可从自托管服务访问、能用受控 HTTPS 动作与受支持媒体端口表达、具有可固定远端身份的工作流平台 API。缺乏文档、只能浏览器操作、需要新媒体类型或不可固定远端定义的工作流，需要补充产品能力或暂不发布；不能让生成代码绕开审批、素材授权或网络限制来勉强接入。例如，一个 RunningHub 连接可分别发布图像风格转换和动作迁移能力，固定各自的应用/工作流身份、输入端口与 Groovy 脚本版本；其 API 文档区分 Model、AI App 和 Workflow 调用类型，不能仅凭同一平台名称套用一种请求格式。[RunningHub API 文档](https://pre.runninghub.ai/runninghub-api-doc-en/)
