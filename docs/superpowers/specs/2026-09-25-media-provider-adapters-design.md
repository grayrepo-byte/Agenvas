# 媒体渠道配置与统一适配层设计

日期：2026-09-25

状态：待书面规格审阅

## 1. 目标与已确认的选择

管理员在界面中维护多个图片和视频渠道，并分别指定默认渠道。有项目审批权限的用户可在批准媒体计划前，为整份图片计划或整份视频计划改选一个已启用、能力匹配的渠道。计划、审批、画布和 Agent 工具不依赖具体供应商协议；后续增加 GPT Image 2、Nano Banana 或 Seedance 时，新增受控适配器及其配置表单即可，不改前述业务链路。

首轮交付统一媒体执行层、管理员配置界面、审批前改选，以及现有 Mock 和 ComfyUI 的迁移。GPT Image 2、Nano Banana、Seedance 的真实适配器分阶段实现、验证后才出现在可选渠道列表。Mock 仍可在无外部模型的自托管安装中独立运行。一个执行计划只使用一个媒体渠道；系统不做跨渠道自动故障切换。

本设计沿用单体 Spring Boot、PostgreSQL、Flyway、REST + SSE 和现有任务状态机。它不引入远程代理服务、动态插件、管理员自定义 HTTP 请求模板或任意 ComfyUI 工作流执行。

## 2. 当前实现与改动原因

当前 `agenvas.provider.mode` 在启动时选择 Mock 或 ComfyUI；ComfyUI 地址及固定模板模型名来自环境变量。`/settings/providers` 复用 LLM 配置页，只展示媒体配置布尔状态。`GenerationGateway` 目前只承载 Mock 提交，ComfyUI 图片、视频的提交、轮询、UNKNOWN 核对和归档分布在专用 Worker 中。计划只存一个数字 `providerConfigVersion` 及 `workflowVersion`，没有稳定的渠道配置身份。因此仅添加前端表单或路由选择器，仍会让每个新供应商重复实现恢复与审批安全规则。

主规格 §7.2 已提出 `provider_config` 与不可变 `provider_config_version`，§13 已要求能力声明和媒体适配边界，§11 要求计划哈希、版本固定与审批后再提交。实现应沿这些约束收敛，而非为新供应商建立并行任务系统。

## 3. 边界与职责

### 3.1 业务入口

`MediaProviderCatalog` 从数据库读取已安装适配器对应的配置、当前版本、启用状态和每类默认值，返回管理员可见的脱敏状态以及计划选择所需的安全能力摘要。只有服务端注册的适配器键可被保存。模型提案和普通用户请求都不能传入 endpoint、凭证、工作流或执行版本。

`MediaPlanResolver` 在生成计划时选该媒体类型的当前默认渠道，校验每个步骤的参考图、画幅、时长和输出类型。它将渠道 ID、配置版本、适配器键、能力/执行映射版本与估算信息放入计划哈希。工作流版本字段对 ComfyUI 表示固定模板版本；对其他适配器表示服务端请求映射版本，不暗示供应商有 ComfyUI 工作流。

估算必须注明来源：可验证的供应商价格、管理员设定的上限或仅有数量/时长的本地资源预算。没有可靠金额时显示“费用未知”，不能伪造精确价格；仍以任务数量、时长和管理员上限限制批准范围。

`MediaExecutionService` 是媒体任务的唯一调度入口，复用数据库认领、短事务、租约、fencing epoch、attempt、用量预留、Asset 归档和 Artifact CAS。适配器不能直接更新计划、Task、Artifact 或用量账本，也不接触 Controller 或 React Flow。首轮维持当前保守的全局媒体提交并发限制；以后只有在对应适配器通过限流与故障测试后才调整。

### 3.2 适配器协议

每个内置 `MediaAdapter` 声明媒体类型、支持的参考图数量、尺寸/时长范围、同步或异步结果、按原请求查询/核对能力、幂等与取消能力，以及输出获取约束。未验证的能力为 false。它只实现受控配置校验、将规范化输入映射为供应商请求、一次提交、可支持时的原请求查询/核对，以及受限结果读取。返回值区分 `COMPLETED`、`ACCEPTED`、`REJECTED`、`UNKNOWN`，并带原请求 ID、稳定错误分类和经验证的输出句柄；不向业务层暴露任意供应商响应 JSON 或临时 URL。

Mock 和 ComfyUI 均走该协议。ComfyUI 继续使用安装在服务端的固定图片/视频模板，保留候选 prompt ID、原 origin 指纹及历史查询规则。同步图片 API 可直接返回生成字节，异步视频 API 可返回任务 ID；两种形式共用任务账本，不能假设每个供应商都支持轮询、取消或请求幂等。适配器新增时必须有协议与故障契约测试，不能仅因产品名称相似就复用另一个供应商的 HTTP Schema。

## 4. 渠道配置与数据模型

新增稳定的 `media_provider_config`：UUID、单一媒体类型 `IMAGE`/`VIDEO`、适配器键、显示名称、启用状态、当前配置版本、管理元数据版本及创建/更新时间。新增只追加的 `media_provider_config_version`：配置 ID、正整数版本、适配器校验过的非敏感参数、加密凭证及密钥版本、密钥掩码、endpoint 身份摘要、执行映射版本、创建时间。该表不存任意工作流正文。配置版本发布使用数据库行锁与 expectedVersion/CAS；旧版本在被计划、任务或 attempt 引用时保留。显示名称、启用状态与默认选择也使用 CAS，但不伪造新的连接配置版本。

`media_provider_default` 对每种媒体类型只允许一个已启用的默认配置。新安装默认创建 Mock 图片与 Mock 视频配置。设置默认值和停用当前默认值在一个事务中校验；若停用会造成该类没有默认值，则要求先选替代值。配置项可以存在但不可用：缺少模板参数、适配器未安装、凭证不可解密或能力不匹配时不得作为新计划候选。

计划新增非空 `providerConfigId`，其现有 `providerConfigVersion` 在该 ID 内编号；计划哈希覆盖两者、适配器映射版本、输入快照和估算。媒体 Task 使用现有 `provider_id` 固定配置 ID，并在不可变输入中固定版本及映射版本；attempt 关联 Task 的固定配置身份和原请求，补足必要的外键及 `(provider_id, provider_request_id)` 非空唯一约束。新生成内容、用量账本与对外响应增加配置 ID；历史 ArtifactVersion 保持不可变，缺少配置 ID 的旧内容明确按旧格式展示，不原地补写。原有版本号仍保留，不能脱离配置 ID 单独解释。所有结构变更用新的 Flyway 迁移，不修改旧迁移文件。

管理员的云渠道密钥只在提交表单时由浏览器内存传到受保护 API，服务端用现有主密钥机制加密；列表、事件、日志、项目导出和普通用户响应只返回掩码或安全摘要。更新带密钥的连接参数需要提交新凭证并生成新版本。主密钥及历史密钥环仍由部署环境管理，它们不进入网页配置。

## 5. 管理员页面与审批交互

`/settings/providers` 展示图片、视频两组渠道。管理员可新增同类多个 Mock/ComfyUI 配置，编辑受控字段、设置默认值、启用或停用并查看配置版本和状态。ComfyUI 表单收集精确服务地址和固定模板所需模型文件名；服务端验证地址、协议、允许的本地例外及字段格式。云适配器在实现和测试后才注册对应的模型/密钥表单；云出站使用适配器限定的官方服务地址或明确允许的区域地址，不把 URL 输入变成通用网络代理。

页面区分“已保存”“连通性检查结果”和“真实生成验收状态”。不产生费用的连通检查不能证明模板、参考图映射或实际生成可用。首轮 ComfyUI 的真实生成验收状态固定显示为“未验证”，管理员不能手动勾选通过；只有后续真实任务与参考图路径的验收证据进入交付记录后，才能调整这一产品声明。配置读取失败、保存中、版本冲突、未授权、禁用和空列表均有明确状态。密钥不进浏览器持久存储。

服务端创建图片或视频计划时固定该类默认渠道。审批面板显示渠道名称、适配器/模型或模板、配置版本、能力约束、媒体数量与估算来源。用户从已启用且能满足整份计划的渠道中改选时，调用受保护的“改选渠道”命令：以旧 `planHash` 和目标配置 ID 为条件，在同一项目事务中重新验证固定输入、每个步骤的能力、额度及估算，生成同一 stage 的新 `PENDING` 修订，并将旧修订标为已有的 `STALE`。Run 保持 `WAITING_APPROVAL`；新修订返回给页面展示，用户再按新哈希独立批准。改选动作本身不产生媒体任务或费用预留。目标配置版本在此期间变化，返回 409 并要求重新选择；不能用旧审批批准新渠道。

管理员仅修改默认渠道，不改变已有待审批或已批准计划。已选配置被编辑或停用时，尚未批准的计划审批失败并要求新修订；已批准但尚未发出的 Task 停止新提交并显示配置阻断。已受理的 Task 则始终按其原配置版本查询和归档，不受当前默认值或启用状态影响。

## 6. 提交、恢复与错误规则

媒体 Worker 先在短事务中认领 Task，复核项目授权、取消、输入版本、批准范围、配置版本、适配器能力和剩余额度，再持久化 `SUBMITTING` attempt 与关联键；事务提交后才调用供应商。网络调用不持有数据库事务。返回后使用预期状态、版本和 fencing epoch 写入结果，旧 Worker 不得回写成功。

明确拒绝进入稳定失败分类；已受理只按原请求 ID 查询。提交超时或响应丢失进入 `UNKNOWN`，只有适配器明确声明并经测试可按原请求安全核对时才执行核对；查询为空不是未受理的证明。无法核对的同步图片请求保持 UNKNOWN，用户可在看到重复成本提示后走现有显式新尝试流程，不自动重提或切换渠道。状态查询、下载与归档的技术重试不等于重新提交生成请求。

已收到的同步媒体字节先按 Task/attempt 键写入受控、大小受限的持久暂存，并验证 MIME、像素或视频元数据；再原子归档为 Asset 和不可变 ArtifactVersion。暂存已完成而数据库尚未确认时，恢复只重用暂存字节。响应在暂存前丢失且供应商无法按原请求查询时，保留 UNKNOWN。异步结果的临时地址只按适配器允许的来源和逐次 DNS/重定向规则下载，随后走同一归档路径。归档失败只重试获取已完成结果或归档，不重做生成。

取消阻止后续提交与依赖编排；已受理请求的晚到结果仍按原版本进入历史，不自动成为当前选用版本，也不唤醒下游。旧内容结果同样受 Artifact CAS 约束。凭证旧版本失效、原端点不可达、历史协议未知或原请求身份无法确认时进入明确的 BLOCKED/UNKNOWN 状态，提示人工处理，不使用新渠道猜测补偿。

## 7. 旧部署迁移

新安装在首次启动时先执行导入判定；没有旧媒体配置及旧任务时，创建数据库中的 Mock 图片与视频默认配置，不需要媒体环境变量。升级时，在新调度器启动前执行一次性、带完成标记的导入：将现有媒体模式和当前 ComfyUI 地址/固定模板模型名导入新配置；把 V34 保存的历史 ComfyUI origin 版本映射为仅供原请求查询的只读历史版本。旧计划和 Task 根据已固定的工作流版本、Provider 数字版本、原 origin 指纹和 attempt 记录关联到唯一旧配置 ID；旧 Mock 任务按原 Mock 工作流版本映射。无法唯一核对的历史记录关联到禁用、不可提交的内部 `LEGACY_UNRESOLVED` 身份，旧待审批计划标为 `STALE`，旧任务明确阻断核对，不自动重提。完成回填后，新计划的 `providerConfigId` 必须非空且有外键约束。

导入完成后，数据库成为媒体配置的唯一运行时来源；后续媒体环境变量变化不改写配置。升级说明要求管理员在页面核对导入结果，并说明备份需同时保留数据库、Asset 卷、主密钥与历史密钥环。保留旧 Flyway 表与数据供审计和恢复，不修改历史迁移。迁移测试需要覆盖空库、已有 Mock、当前 ComfyUI、多个历史 origin、歧义和缺失原地址。

## 8. API、契约与兼容影响

在 `/api/v1/settings/media-providers` 下提供管理员列表与创建；`/{id}/versions` 发布新配置版本，`/{id}` 更新名称或启用状态，`/defaults/{kind}` 设置默认值，`/{id}/probe` 执行不产生付费生成的连通检查。创建使用 Idempotency-Key；其余写操作带 expectedVersion，响应禁用缓存且不返回凭证明文或密文。项目计划提供受保护的 `GET /api/v1/projects/{projectId}/plans/{planId}/media-provider-candidates` 与 `POST /api/v1/projects/{projectId}/plans/{planId}/select-media-provider`；改选提交旧 planHash、目标配置 ID 和目标版本。候选列表只包含安装且能力匹配的配置，不暴露凭证或内部网络细节。错误使用 ProblemDetail 和真实 HTTP 状态：输入/能力校验 400，匿名 401，越权 403，旧版本/旧哈希/配置漂移 409，恢复模式 503。管理员配置变更不广播到项目 SSE；计划改选与后续任务状态通过 project_event 的安全摘要通知，不发送密钥、完整 endpoint 或原始供应商响应。

这是开发期 API 与数据模型扩展：`ExecutionPlan`、媒体 Task/Artifact 的对外 Schema 增加配置身份，改选会使旧计划成为 `STALE`。同步更新 `contracts/openapi.yaml`、Java DTO、生成的 TypeScript、前端调用和契约测试。已有客户端须按新字段识别配置版本；新媒体配置 API 不承诺兼容旧环境变量编辑流程。`docs/MVP-SPEC.md`、`docs/DEVELOPMENT-CHECKLIST.md`、部署与备份说明及必要 ADR 同步记录该决策和迁移方式。

## 9. 首轮验收

1. 真实 PostgreSQL 下验证同类多配置、唯一默认、管理员权限、密钥加密/脱敏、CAS 更新和一次性旧配置迁移；无外部模型的 Mock 安装仍可完成黄金路径。
2. 计划改选生成新哈希与修订，旧计划不能批准；能力不匹配、配置漂移或越权不能创建任务。并发批准仍只创建一组 Task 与用量预留。
3. 切换默认值不改变已固定的计划/Task；禁用或编辑配置阻止未发出任务的新提交，已受理 ComfyUI 请求仍按原版本、origin 和请求 ID 查询与归档。
4. 模拟提交响应丢失、崩溃、租约接管、同步响应暂存、归档失败、取消晚到与旧 Worker 回写。没有安全查询能力的 UNKNOWN 不自动提交第二次；归档故障不重新生成。
5. 前端覆盖配置空态、保存、冲突、密钥清空、改选后的二次确认、UNKNOWN、未授权；OpenAPI 生成类型与 Java 响应一致。断线重连后从项目快照和 SSE 可看到新计划与任务状态。
6. ComfyUI 假 HTTP + PostgreSQL 协议回归通过后仍标为候选适配器。只有真实 ComfyUI 固定模板任务及参考图路径现场验证后，相关门禁才可勾选；后续每个云适配器也分别需要真实调用与恢复测试。

## 10. 分阶段接入后续云渠道

每增加一个渠道，先基于官方 API 文档确定端点、身份、能力与费用表达，再实现受控配置 Schema、适配器、错误映射和可核对能力；通过假服务故障契约测试及真实供应商端到端任务后才在 UI 标为可用。GPT Image 2 和 Nano Banana 属于图片候选，Seedance 属于视频候选；具体模型 ID、地区、能力和价格在实施各适配器时以当时官方文档与实际账户验证为准，不写死进统一执行层。新渠道不得修改计划审批语义、任务状态机或画布产物模型。
