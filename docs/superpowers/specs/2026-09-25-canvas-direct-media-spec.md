# 画布交互重构与直接媒体运行规格

状态：历史实施规格；已发布为 [GitHub Issue #1](https://github.com/grayrepo-byte/Agenvas/issues/1)。其中角色/场景/镜头与审批范围已由 ADR 0013 撤回，项目/能力/ComfyUI 并发配额又由 2026-09-28 的 ADR 0006 修订撤回；当前行为以 `docs/MVP-SPEC.md`、ADR 与 `docs/DEVELOPMENT-CHECKLIST.md` 为准。

## Problem Statement

现有项目工作区的左栏承担创建、上传、对齐等操作，挤占画布空间。图片和视频生成依赖镜头及 Agent 提出的待审批计划，用户无法在独立媒体卡片上直接填写提示词并运行。现有界面也没有清楚区分工作草稿、当前选用结果和正在执行的任务；当用户编辑、回看历史、并行生成或从画布移除卡片时，容易误解哪些内容会保存、展示或被外部 Provider 使用。

## Solution

项目工作区采用深色点状画布，取消左栏。用户在空白处双击或使用悬浮“+”选择现有七类创建入口；选中卡片后，在底部按类型编辑内容。图片和视频卡片创建时获得稳定的 Artifact 身份，并将可自动保存的媒体草稿与不可变结果版本分开。用户查看能力及费用信息后点击“运行”，系统直接受理一个固定输入的 `USER_DIRECT` Task，无需 AgentRun、ExecutionPlan 或审批。Agent 提出的付费媒体计划继续人工审批。

不同卡片的媒体任务可以并行，也可以与一个 AgentRun 同时进行。同一卡片的排队、执行和 UNKNOWN 任务互斥。系统通过持久队列、项目及能力容量限制、用量账本和结果版本历史，保证刷新、失败、重启、取消及晚到结果后的状态可信。

## User Stories

1. 作为创作者，我想在整个项目工作区使用深色点状画布，以便把注意力放在卡片关系上。
2. 作为创作者，我想取消左侧固定创建栏，以便获得更大的画布空间。
3. 作为创作者，我想在画布空白处双击打开创建菜单，以便直接在工作位置添加内容。
4. 作为使用触屏或不熟悉双击的创作者，我想点击悬浮“+”打开同一菜单，以便发现创建入口。
5. 作为创作者，我想从文字、图片、视频、角色、场景、镜头和 Agent 七类入口中选择，以便沿用项目已有的业务类型。
6. 作为创作者，我想让菜单避开视口边缘，并可用键盘操作及 Esc 关闭，以便在不同窗口尺寸下完成选择。
7. 作为创作者，我想让新卡片出现在触发创建的位置，以便保留我的空间布局意图。
8. 作为创作者，我想在画布右下角缩放并适配视图，以便快速定位内容。
9. 作为创作者，我想在未选中卡片时隐藏底部编辑区，以便画布保持简洁。
10. 作为创作者，我想在单选时看到该类型的编辑字段，以便直接修改所选内容。
11. 作为创作者，我想在多选时看到批量操作与对齐入口，以便整理多个卡片。
12. 作为创作者，我想分别保存 Agent 的长期配置指令和本次运行指令，以免本次输入意外覆盖配置。
13. 作为创作者，我想从顶部打开可搜索的项目资源抽屉，以便找到已从画布移除的草稿和历史产物。
14. 作为创作者，我想把项目资源中的产物重新放回画布，以便恢复其空间展示而不重新生成。
15. 作为创作者，我想从顶部进行素材导入与导出，以便在取消左栏后继续完成现有工作。
16. 作为创作者，我想在右侧查看选中对象的版本和引用，以便精确选择历史结果与输入。
17. 作为创作者，我想在底部查看 Agent 待审批计划、失败与 UNKNOWN 任务，以便处理需要我介入的事项。
18. 作为创作者，我想先创建空的图片或视频卡片，再填写生成参数，以便逐步组织画布。
19. 作为创作者，我想让尚未生成媒体的卡片保留 Artifact 身份和位置，以便刷新后继续工作。
20. 作为创作者，我想让媒体草稿在短延迟后自动保存并显示状态，以便知道修改是否已经持久化。
21. 作为创作者，我想在保存失败或版本冲突时保留本地输入，以便手动处理而不丢失提示词。
22. 作为创作者，我想独立填写图片提示词并运行文生图，以便不必先创建镜头。
23. 作为创作者，我想在视频草稿中选择同项目已归档图片的精确版本并设置时长，以便固定视频生成输入。
24. 作为创作者，我想保存尚未填写完整的视频草稿，但只有字段完整后才能运行，以便分阶段准备任务。
25. 作为创作者，我想在运行按钮旁看到所选能力及预计费用或“未知”，以便在提交前了解本次消耗。
26. 作为创作者，我想点击图片或视频卡片的“运行”后直接受理任务，以便不经历 Agent 计划审批。
27. 作为创作者，我想继续审批 Agent 提出的付费媒体计划，以便保持 Agent 行为的授权边界。
28. 作为创作者，我想在任务排队或运行期间继续修改草稿，以便准备下一次生成且不改变已提交输入。
29. 作为创作者，我想让不同卡片的任务并行，并与 AgentRun 并行，以便减少等待。
30. 作为创作者，我想在同一卡片已有未结束任务时得到原任务，而不是重复提交，以便避免重复费用。
31. 作为创作者，我想在超过项目、能力或 ComfyUI 容量时看到持久排队状态、前方待处理数量及原因，以便理解等待；排位变化也应明确提示。
32. 作为创作者，我想取消尚未提交到 Provider 的排队任务，并释放未消耗的预留，以便停止不再需要的请求。
33. 作为创作者，我想在任务处于 UNKNOWN 时看到核对或明确风险的新尝试入口，以便避免盲目再次提交。
34. 作为创作者，我想在卡片上查看新结果和全部历史版本，以便回看并手动选用旧结果。
35. 作为创作者，我想在选用旧结果后仍默认编辑保留的工作草稿，以便展示与下一次生成互不干扰。
36. 作为创作者，我想在从草稿发起运行后看到草稿占位，同时保留旧结果于历史，以便识别当前正在处理的内容。
37. 作为创作者，我想在运行失败或取消后看到草稿占位和原因，并能手动选回旧结果，以便清楚知道当前展示状态。
38. 作为创作者，我想在生成成功后继续看到本次使用的提示词和参数，以便修改后生成下一版。
39. 作为创作者，我想让晚到结果只追加历史、不静默覆盖我后来选用的版本或草稿，以便保留我的最新选择。
40. 作为创作者，我想在移除媒体卡片后让已受理任务继续执行，并在项目资源中找到结果，以免布局操作意外取消生成。
41. 作为管理员，我想配置每种媒体能力的全局并发上限，以便适配 Provider 的实际容量。
42. 作为项目成员，我想看到直接媒体任务的次数与金额预留及最终结算，以便理解消耗；价格未知时不能显示为零。

## Implementation Decisions

- 使用现有七类业务对象创建入口；参考图中的音频、3D 等菜单项不加入本轮。深色主题仅覆盖项目工作区。
- 空白画布双击与悬浮“+”共用创建菜单。选择类型后按触发时的画布坐标创建卡片，菜单按视口空间避让。
- CanvasItem 只负责空间展示；移除 CanvasItem 不删除 Artifact、ArtifactVersion、Asset、媒体草稿或 Task。资源抽屉可搜索并重新放置产物。
- 图片与视频 Artifact 在创建卡片时建立；首次生成前允许当前内容版本为空。媒体草稿独立持久化，带版本检查；它不充当 ArtifactVersion 或媒体 Asset。
- 媒体卡片的展示状态与当前选用结果、底部工作草稿分离。选用旧结果不丢弃草稿，底部默认草稿；从草稿运行时切换占位，旧结果保留于历史。
- 图片直接生成仅支持文生图。视频直接生成固定同项目已归档图片的精确 ArtifactVersion 和时长；草稿可不完整，运行前校验完整性与作用域。
- 用户点击“运行”创建来源为 `USER_DIRECT` 的持久 Task，不创建 AgentRun 或 ExecutionPlan，也不走审批。Task 固定草稿版本、目标 Artifact、能力版本、输入版本及预期选用状态。Agent 发起的付费媒体 Task 继续由已审批计划创建。
- 一张卡片在排队、执行或 UNKNOWN 中至多关联一个未终结媒体 Task，跨用户直接与 Agent 来源生效。重复提交幂等返回原任务；UNKNOWN 的额外尝试必须经显式风险流程。
- 直接媒体 Task 不占用项目唯一的 AgentRun 活动槽。每项目默认最多三个占用中的媒体 Task；每种能力有管理员可配置的全局上限。容量在数据库认领中执行，跨 Worker 有效。UNKNOWN 占项目与能力名额，ComfyUI 继续叠加现有单槽门禁。
- 超出容量的 Task 持久排队；前端显示当前前方待处理数量、排队原因及排位可能变化。队列不是浏览器内存状态。
- 受理时预留任务次数额度；价格已知时还预留估算金额，未知时明确记录为未知。排队取消且可证明尚未外部提交时释放未消耗预留；UNKNOWN 保持预留并继续核对。取消不承诺 Provider 停止或退款。
- Task 继续遵守短事务认领、租约、fencing epoch、固定输入和外部提交核对规则。崩溃或提交结果不明时不得盲目重提。归档失败只重试归档。
- 成功结果在同一 Artifact 追加不可变 ArtifactVersion，旧 Asset 和版本保留。只有仍符合预期选用状态时才自动展示新结果；否则结果进入历史，用户可手动选用。
- 后端扩展媒体草稿、空媒体 Artifact、直接 Task 来源及目标、容量与用量的持久模型；同步迁移、API 合约、生成客户端类型、项目快照及可靠事件。现有 Agent 路径继续维持其 Run 与计划语义。
- 前端通过服务器快照、变更 API 与项目 SSE 反映任务状态；本地状态只保存交互与未保存输入。一个项目保持一个 SSE 连接，断线后从水位补发。

## Testing Decisions

### 2026-09-26 视觉实施补充

- 以用户提供的黑色画布图稿细化媒体显示：空图片图标与上传、有图缩略图、外置操作栏、约 680px Prompt 编辑区、模型菜单、只读参数摘要和圆形运行按钮，不复制标注序号。
- 卡片布局尺寸与实际生成尺寸分开。草稿合约未提供画幅/分辨率/画质覆盖字段；当前显示所选能力真实配置或模型/模板默认，不用本地未持久化值假装改变生成请求。
- 上传空图片卡片复用同一 Artifact，通过上传 Asset、修订内容版本及选用该版本切到 RESULT；阶段失败保留已确认进度。视频空态使用生成入口，因为现有 API 没有视频上传能力。
- 未接入的图片扩展在菜单中明确禁用。工作区已有锁定、移除、版本选用、打开原文件等操作保持可用。
- Beautiful UI 加载态按实际任务状态展示；UNKNOWN 显示待核对而非无限转动。来源与 MIT 许可保存在组件旁。
- 本轮验收与浏览器限制记录于 开发记录（不随源码公开） 和根目录 开发记录（不随源码公开）；不能以组件测试替代浏览器视觉验收。

- 好的测试从项目成员或管理员可观察的结果出发，覆盖 HTTP 状态、持久记录、事件、画布展示和 Provider 调用次数；不锁定内部方法调用顺序或组件私有状态。
- 主要测试入口沿用项目级 API 与真实 PostgreSQL 集成测试，覆盖空 Artifact 与草稿刷新、版本冲突、权限、视频精确输入版本、同卡片互斥、不同卡片并行、AgentRun 并行、项目及能力限额、排队取消、额度预留/释放、UNKNOWN 占槽、Worker 失效与晚到结果。已有 Artifact、TaskLease、TaskRecovery、TaskArtifactSelection、AgentRun、用量及事件集成测试可作为先例。
- 前端沿用工作区及卡片组件测试，覆盖双击与“+”共用菜单、坐标创建、选择态编辑、自动保存失败、本地输入保留、资源重新放置、能力费用提示、队列原因、版本切换、失败与 UNKNOWN 提示；现有工作区、版本编辑、审批与 UNKNOWN 面板测试可作为先例。
- 用浏览器验收核对深色画布、菜单视口避让、缩放位置、键盘操作与不同窗口尺寸。Mock 模式验证端到端流程；真实 Provider 联调单独记录，不用 Mock 成功证明真实生成。
- 合约测试验证直接运行无需计划审批，同时确保 Agent 付费媒体计划仍要求审批。SSE 重连和快照竞争测试验证任务与版本状态不会丢失。

## Out of Scope

- 参考图编辑、图片上传后编辑、音频、3D、任意 Provider 工作流及动态插件。
- 第二个活动 AgentRun、多 Agent 协商或为直接点击创建通用 Run 实体。
- 项目列表、设置页等非项目工作区的深色主题改造。
- 取消后保证外部 Provider 停止或退款；UNKNOWN 自动重试提交。
- 用画布连线直接触发生成，或把媒体草稿当作已归档结果供视频输入。

## Further Notes

- 本规格综合已确认的画布交互与直接媒体 Task 决策；现有实现仍以左栏和 Agent 计划媒体生成路径为主，不能把目标行为标为已完成。
- 数据库迁移只增不改；API 变更需同步权威合约、生成类型与调用方。用真实 PostgreSQL 验证并发语义。
- 本规格按 `ready-for-agent` 交付；实施前应复核当前代码与相关 ADR，不能把目标行为视为现有实现。
