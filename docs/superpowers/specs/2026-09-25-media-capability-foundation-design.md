# 媒体能力目录与统一执行内核设计（第一阶段）

日期：2026-09-25

状态：待用户审阅书面规格

## 1. 目标、范围与边界

管理员在界面维护平台连接及其多条图片或视频能力，不再依赖媒体环境变量切换 Mock/ComfyUI。Agent 为计划的每个步骤选择已发布能力；审批人可逐步骤改选、补输入并确认。计划、审批、任务和画布只依赖能力契约，不依赖平台 HTTP 协议。一个连接可同时承载图片和视频，也可承载多种用途的工作流。

本阶段交付能力目录、版本与默认值、通用输入端口、管理员配置界面、逐步骤计划绑定、统一媒体执行内核，以及现有 Mock/ComfyUI 迁移。只允许内置适配器执行。本阶段不宣称新云渠道已接通；隔离 Groovy 钩子、Agent 接入草案和工作流平台的通用 HTTPS 调用见同日的[第二阶段规格](./2026-09-25-scripted-media-integrations-design.md)。两阶段均属于通用能力的最终目标。OpenAI GPT Image 2 和 Google Nano Banana 2 后续分别通过专门编写、测试的内置代码适配器接入，不走动态生成代码；Seedance 等直接模型 API 也优先按其正式协议实现内置适配器，具体渠道逐个验收。

保留单体 Spring Boot、PostgreSQL、Flyway、REST + SSE、数据库任务状态机、不可变 ArtifactVersion 和 Mock 独立启动。普通 Agent 工具仍不能执行任意 HTTP、Shell、SQL 或加载代码。管理员发布 Groovy 钩子脚本的受控例外只在第二阶段建立，不能借本阶段放开 ComfyUI 任意工作流或 Custom Node。

## 2. 现状与设计原因

当前媒体模式、ComfyUI 地址和模型名由环境变量选定。设置页只显示媒体状态。Mock 与 ComfyUI 的执行路径分开，ComfyUI 图片、视频各有提交和恢复组件。计划记录一个 Provider 数字版本和一个工作流版本，步骤无法固定不同能力。这不足以表达同一 RunningHub 类平台下的风格转换、动作迁移等独立工作流，也无法让审批人核对每一步的选择。

主规格已有两阶段图片/视频审批、计划哈希、输入版本固定、Task 租约和 UNKNOWN 规则。本设计在这些规则上增加能力维度，不另建任务系统。旧规格中“P0 禁止任意工作流/动态插件”继续适用于本阶段的普通用户、Agent 和内置 ComfyUI；第二阶段的管理员审阅后隔离执行是后续明确的产品决策变更，须同步主规格和 ADR。

## 3. 模型与职责

- 平台连接是稳定身份，保存名称、状态和版本；不可变连接版本保存精确地址、加密凭证、密钥版本及地址摘要。连接不带单一 IMAGE/VIDEO 类型。
- 能力是连接下的稳定身份，保存名称、启用状态、用途描述、主输出类型和当前发布版本。不可变能力版本保存执行方式 BUILTIN 或 SANDBOXED_GROOVY、操作标识、类型化输入输出端口、参数约束、远端模型/应用/工作流身份、内置适配器映射版本或 Groovy 脚本源码摘要与运行时版本、费用来源、并发限制与可核对声明。第一阶段只允许 BUILTIN，第二阶段才允许 SANDBOXED_GROOVY。一个连接可有任意多条能力；一个远端工作流若输出两种媒体，须分别定义并验证能力。
- 用途标识与文字说明由管理员维护，既可表示通用文生图，也可表示风格转换或动作迁移；不将用途封死为代码枚举。服务端只把已发布的安全摘要交给 Agent，绝不交付地址、凭证或适配器内部请求。能力名称和说明是数据，不能授予权限。
- 每种主输出类型可有一条默认能力，供通用步骤初选。Agent 可按用途选择其他已发布能力；默认值不强制覆盖专用选择。无匹配能力时不生成可执行任务。

统一媒体执行内核负责权限、审批、用量预留、Task/attempt、短事务认领、租约与 fencing epoch、UNKNOWN、输入版本与 Asset/Artifact 归档。内置适配器只实现该能力版本的参数验证、请求构造、提交、原请求查询/核对和受限结果读取；不得写业务表或自行决定重试提交。Mock 与 ComfyUI 共用内核和状态机。ComfyUI 仍只有已安装、固定且版本化的图片和视频模板，历史 origin 查询规则保留。

## 4. 输入端口与计划

能力输入用受限、版本化的 Schema 表达文本、整数/小数、布尔、枚举、图片素材、视频素材、可选字段、有界数组/对象及上游步骤输出；输出声明一个主 IMAGE 或 VIDEO 产物及可选结构化元数据。端口要写明必填、数量、媒体 MIME/尺寸/时长、作用和可接受的上游类型。平台特有 JSON 由适配器映射，不把任意 URL、本地路径或生成代码变成普通用户参数。当前图片上传可复用；为了让动作迁移类能力可用，本阶段增加受限视频输入上传、解码探测、大小/时长限制与项目授权。没有适配的媒体类型不能伪装成通用文件端口。

Agent 提案每一步只给能力 ID、用途所需的参数和已授权素材引用；服务端选择并固定该能力当前版本、所属连接版本和执行映射摘要。模型不能选择 endpoint、凭证、预算或发布版本。服务端检查端口类型、素材归属及版本、关键帧选择、DAG、数量、预算和能力状态。缺少用户素材的计划进入 NEEDS_INPUT，Run 保持 WAITING_APPROVAL 且不可批准；补齐后生成新 PENDING 修订。图片与视频仍按原有两个阶段分别审批，阶段内各步骤可以选不同能力。

审批页逐步骤展示能力/连接、版本、用途、输入素材范围、参数、输出、费用来源及测试标记。用户可单独改选兼容能力或补输入；每次变化创建新计划修订与哈希，旧 NEEDS_INPUT/PENDING 修订标 STALE，所有逐项确认清空。批准请求携带 planHash 和完整 confirmedStepKeys；服务端核对集合恰好等于当前步骤，在一个事务中再次验证输入/配置/额度，写 Approval、用量预留、全部 Task 和项目事件。勾选只是用户交互，不能替代服务端校验。布局改动不使内容计划失效；管理员只改默认值不改已有计划。

计划步骤和 Task 固定连接 ID/版本、能力 ID/版本、执行映射摘要、输入版本、输出槽位与预算类别，全部进入计划哈希。批准前连接或能力版本变化、停用、权限或输入变化使计划失效。批准后尚未向外提交的 Task 遇到停用或不安全漂移进入 BLOCKED，不静默换能力；已受理 Task 始终按历史固定版本核对和归档。任何结果不得覆盖用户后续编辑选用的版本。

## 5. 持久化、迁移与接口

新 Flyway 迁移建立 media_provider_connection、media_provider_connection_version、media_capability、media_capability_version、media_default，并给计划步骤、Task、attempt 和生成来源增加两级身份与版本。连接/能力管理字段用 expectedVersion/CAS；版本只追加，被计划或任务引用的版本不能删除。历史 ArtifactVersion 不原地改写。API 与表字段采用稳定 UUID、明确定义的版本和 Schema 版本，避免继续用单个 providerConfigVersion 表达全部媒体配置。

新安装自动创建 Mock 连接及图片、视频能力和默认值，无外部模型也能运行。升级在媒体 Worker 启动前一次性导入当前 Mock/ComfyUI 设置：ComfyUI 同一地址形成一个连接，固定图片/视频模板形成两条能力；V34 历史 origin 和原 attempt 映射为只供原请求核对的历史版本。旧计划和 Task 按已保存的工作流版本、Provider 版本、origin 摘要关联；无法唯一映射的记录保留为 LEGACY_UNRESOLVED，待审批计划 STALE，待核对任务 BLOCKED/UNKNOWN，绝不猜测重提。导入带完成标记，可重启；导入后数据库是运行时媒体配置真相，改变环境变量不会改写已导入版本。备份须保留数据库、Asset 卷和全部历史密钥。

管理员 API 在 /api/v1/settings/media-connections 下管理连接、能力、版本、启停、默认值和无付费连通检查。项目计划 API 提供每步骤候选能力与“修改一步并生成修订”的命令；批准接口增加逐项确认集合。创建使用 Idempotency-Key，同键不同载荷返回 409；更新带 expectedVersion。列表、SSE、项目导出只包含脱敏摘要。同步更新 contracts/openapi.yaml、Java DTO、生成的 TypeScript、契约测试与主规格；这是开发期破坏性 Schema 变更，部署升级须先运行迁移再启动新 Worker。

设置页按连接展示其图片和视频能力、两级版本、默认标记、启停、配置完整性、连通结果和实际测试状态。密钥仅在表单提交时短暂留在浏览器内存，服务端加密保存；读取只返回掩码。页面显示保存中、失败、冲突、未授权、空态和禁用原因。连通检查不能标记真实生成成功；当前 ComfyUI 真实任务未验证的项目状态不得因迁移而变成已验证。新增视频输入限 MP4、200 MiB、60 秒，并以实际解码结果和 FFmpeg 元数据校验；第二阶段生成代码只能引用已经归档并授权的输入素材。

## 6. 错误与验收

提交前短事务保存 SUBMITTING attempt 与关联键，网络请求在事务外。接受后只查询原请求。超时/响应丢失且无法证明未受理时为 UNKNOWN；没有实测可靠核对的适配器不自动重提。状态查询、下载、归档可按原请求做有限重试，归档失败不重新生成。取消只阻止后续编排；晚到结果归档历史，不启动下游。旧 Worker 写入受 epoch 和预期状态限制。

验收使用真实 PostgreSQL、Mock、ComfyUI 假 HTTP 服务和前端交互测试，覆盖：一个连接下图片与视频、多连接多能力、逐步骤异构能力、默认值/CAS、密钥脱敏与越权、输入端口及视频上传、计划修订与并发审批、旧配置/历史 origin 迁移、提交崩溃/UNKNOWN、旧 Worker、取消晚到、归档恢复、SSE 重连。ComfyUI 的假服务测试不等于真实模板与模型联调；未运行真实测试的交付说明必须写明。

本阶段的扩展入口是能力版本与窄执行接口。后续 OpenAI GPT Image 2、Google Nano Banana 2 等正式模型渠道实现 BUILTIN 代码适配器；第二阶段的工作流平台 Groovy 子 JVM 执行器实现 SANDBOXED_GROOVY 路径。两类执行器共用内核、计划绑定、端口和归档，不在审批或画布增加供应商分支。每个真实云渠道另行做协议、故障和真实调用验收；通用内核完成不等于这些渠道已接通。
