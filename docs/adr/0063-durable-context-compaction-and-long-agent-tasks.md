# ADR 0063：持久上下文交接与长时间导演任务

用户要求导演支持十几个小时的任务，并用自动上下文压缩替代固定字符窗口。新请求按 Spring AI 自带 tokenizer 估算文本、工具 Schema、参数和结果的 Token，占用计入额外余量及媒体预留；达到窗口的压缩触发比例或消息数保护线时，把语义压缩作为一个没有工具的持久模型回合执行。目标、创作约束、已完成工作、待办、下一步、阻塞和精确引用形成结构化公开交接摘要，初始指令、已激活 Skill 主说明与当前媒体引用独立保留。近期完整工具配对按预算保留，压缩后为后续工作留出空间；超大的来源分块处理，不用字符截断冒充摘要。该决定替代 ADR 0038 对新请求的确定性历史裁剪，既有检查点原样保留。

压缩复用原 `llm_turn`、Task、配置身份、租约 fencing、调用记录和用量账本，无网络事务、自动工具执行或独立内存任务队列。请求同时固定当前压缩片段、剩余来源、恢复消息与工具定义；响应保存后才能创建后继回合。摘要不进入公开回答流或对话消息，不携带私有推理，不构成权限、批准、当前 CAS 或媒体成功证据；读取内容与写入仍走原应用服务。进程在响应提交后退出，只重放响应，不再调用模型；提交前退出可能重复产生 LLM 用量，与普通模型回合相同。无效摘要走有界修复，不能执行其中的工具，也不能以静默丢弃来源恢复运行。

整个 Run 继续没有累计轮次、工具次数或自然时长上限。临时模型故障默认在首次失败起 24 小时内最多重试 288 次，退避从 2 秒增长到最多 5 分钟；等待依赖数据库调度并释放线程。部署可调整窗口、次数、退避和局部修复次数（默认 4 次）；首次失败的次数上限、截止时间以及修复链上限持久化，重启或调整配置不能重置。已有恢复中的请求继续使用已保存的期限和次数。单次 HTTP/Worker 的有限超时、取消、配置与鉴权错误、媒体审批及 UNKNOWN 规则保持原义，恢复不重提媒体。

2026-11-15 检查点修复：摘要计划内嵌的 requestBudget 与外层请求复用同一 JSON 数字序列化规则，避免 Java long 的小版本号写入 JSONB 后读成整数节点，被误判为请求已改变。请求相等、配置版本和 CAS 校验继续执行，不通过放宽比较规避冲突；已保存摘要的恢复仍只重放原响应。可纠正工具失败的修复优先规则见 ADR 0039 的同日修订。

2026-11-15 开源压缩方案修订：按用户决定，采用 Codex 本地压缩的历史替换主流程，删除摘要 Token 目标和近期工具回合配置。普通已完成的 assistant/tool 历史交给交接摘要覆盖，续接仅重建固定任务、显式必须保留的指令/Skill/媒体引用与交接摘要，不保留固定数量的旧工具回合。摘要不再带数值长度提示或生成后的独立 Token 上限；模型请求仍遵守所选模型容量和已固定的响应额度，摘要提交前按实际后继请求的输入容量及压缩进展验证。格式错误、无法续接或 `finishReason=length` 走原持久有界摘要修复，原无效响应与已提交业务结果保留。旧压缩请求不改写，新修复可恢复原计划保存的响应预留；普通回合和文字生成的截断响应仍终止，不能执行半截工具调用。

源码固定提交、两方案比较与未照搬的运行环境边界见[开源方案核验](../research/agent-compaction-summary-budgets.md)。Codex 的本地历史替换策略移植到原 Spring AI 持久回合；项目特有的结构化交接、分块、权限和媒体不确定性边界保留。该决定替代原独立摘要上限、近期回合保留及 60% 规划规则；不宣称直接运行 Codex Runtime 或依赖其专属远程压缩接口。

取舍是压缩增加模型调用和费用，语义摘要也可能遗漏事实；原始检查点及业务内容保留，关键内容按精确版本重读。当前默认应用窗口为 32,768 Token，达到窗口的 50%（16,384 个估算 Token）触发压缩，响应预留 4,096 Token；所选模型实际容量与输出上限继续约束请求。部署者应按实际模型容量配置，估算器不是 Provider tokenizer，也不代表已测得真实模型窗口；固定指令与主说明超出预算时明确结束并给出配置提示。此工作不新增数据库迁移或专属远程服务，Mock 保持离线可运行；升级需同步部署后端及生成类型后的前端，以接受可配置的重试次数和跨日时间显示。

设计参考：[Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 的 compaction 与结构化记录，以及 [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) 的持久任务交接；实现使用现有 Spring AI ChatGateway，不依赖这些厂商的专属运行服务。验证范围与未完成的真实长时间验收见开发清单。

## 管理员界面修订

按用户明确决定，运行预算改由独立“导演设置”页统一管理，取消环境变量入口。V41 新增单例 `director_settings`，初始化 1M / 50% 及现有恢复默认值；旧环境值不自动导入，升级后自定义安装需在界面重新保存。运行时读取数据库，不缓存进程级可变配置；设置保存通过 expectedVersion/CAS，过期页面不能覆盖新值。管理员 GET/PUT `/api/v1/settings/director`，写请求仍受 CSRF 保护，不触发模型调用或授予业务权限。

该修订替代上文的部署参数来源及“无迁移”范围。普通新模型请求读取一份一致设置快照；已保存的请求/压缩计划、首次失败固定的恢复期限与次数、既有修复链上限继续原样消费。前端草稿固定开始编辑时的版本，保存失败或后台刷新不覆盖草稿，冲突须显式载入最新版。取舍是运行配置读取依赖数据库，与任务持久状态的可用性一致；不保留环境变量与数据库双重来源。

V64 删除 `summary_tokens` 与 `recent_tool_rounds`，保留其他设置并推进版本，使升级前设置草稿失效。GET/PUT 导演设置合约、生成 TypeScript 与 jOOQ 同步移除字段，升级应同时部署前后端。历史模型请求保留旧 JSON 原文，读取其预算时仅忽略已删除的两个规划字段，不放宽模型容量或版本校验。
