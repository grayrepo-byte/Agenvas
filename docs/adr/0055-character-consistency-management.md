# ADR 0055：项目角色档案与镜头的一致性管理

状态：接受，按用户要求实现研究报告中的角色一致性管理；验证范围见开发清单。

此前角色只是个人资产分类，剧本里的角色、造型与镜号仍由普通文字描述。新增项目角色档案和不可变修订，维护多个稳定造型、有用途的图片精确版本、音频精确版本及可选指定音色。以现有媒体 CanvasItem 作为出场镜头，不在本次引入完整分镜制作台或媒体执行 DAG。这扩展 ADR 0026 的分类资产边界和 ADR 0054 的纯文字角色设定，保留四种 Artifact 类型和原有生成执行路径。

角色应用不是动态引用。用户先预览角色改动的影响范围，再保存档案；已有镜头只标记待复核，不修改草稿、已受理任务或选用结果。用户在一个镜头中选定多个角色、各自造型及外观/声音用途，通过服务端预览及确认摘要，把固定参考和说明写入既有媒体草稿。绑定、档案和草稿的 CAS 在项目事件事务中核对，重复命令返回原成功结果，不重新应用或创建生成任务。

角色功能追踪自己新增的参考来源 ID、完整说明块和指定音色。替换时只处理仍由自己持有的贡献，保留手动素材、连线和其他角色仍需的参考；用户手动修改过的说明块不能被自动覆盖。清空全部关联可明确选择保留输入成为普通草稿，或移除仍由角色功能拥有的输入。模型数量、模式、命名槽及音频约束沿用真实媒体校验，不静默丢弃不兼容素材。

角色应用与结果复核分别持久化。复核固定当前草稿版本和选用结果，后续档案、草稿或结果变化重新标记；切走再切回结果也不恢复先前的复核结论。修改角色不意味着下游媒体应自动重新生成，不承诺模型绝对保持外观、台词、声音或口型一致。

受理生成时固定已应用且仍与草稿相符的角色快照，加入审批预检摘要及结果来源；Provider 继续读取 Task 的固定提示词与精确媒体输入，不读取实时角色档案。导演的 `read_canvas` 只增加安全目录及节点角色摘要，角色资料中的媒体身份本身不扩大读取权限。项目导出清单在本项独立实现时升级到 schema 9，合并分镜制作台后统一为 schema 10，同时包含角色档案、关联、安全贡献记录及分镜板和不可变修订历史；媒体 Task 受理输入升级到 schema 7。追加 V35，不改写历史迁移或现有用户内容。

导演角色目录有独立游标，默认每页 10 个、最多 20 个角色，只返回短摘要。`characterId` 可按最多 4000 个 Unicode 码点读取安全文字详情，续页须固定 `expectedCharacterVersion`；角色绑定摘要省略长正文。角色目录分页不依赖画布是否还有节点，文字详情不包含媒体版本 ID，不因长档案破坏模型上下文预算。

普通镜头复制保留固定角色关联但重新复核，只转移仍由角色功能独占的素材来源。批量和晚到的额外结果从 Task 已冻结的角色快照及安全贡献恢复关联，不从实时源节点猜测；源节点后来更换造型、清空关联或切换结果，不影响旧任务的角色来源。
