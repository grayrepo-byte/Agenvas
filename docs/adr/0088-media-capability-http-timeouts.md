# ADR 0088：能力版本中的媒体 HTTP 超时

- 状态：接受
- 日期：2026-11-15
- 依据：用户要求将连接、写入、读取和整次调用的超时集成到能力发布，并明确覆盖所有网络媒体能力。

## 问题与目标

现有媒体客户端将超时固化在 Java 中。管理员不能按模型或工作流调整；只设置较长的读取和总调用上限也不能避免默认写入上限提前截断大参考图。改动应使管理员能在现有能力发布及编辑流程配置实际生效的超时，并保留版本、CAS、幂等和 UNKNOWN 规则。

覆盖 OpenAI、Google 图片与视频、Seedream、Seedance、Seed Audio、Wan、Kling、MiniMax、AutoDL、RunningHub 和 ComfyUI。LOCAL 和 Mock 不提供 HTTP 超时设置。LLM 连接、存储连接和媒体中继的配置不属于本次能力配置。

## 配置归属与方案

采用用户指定的能力级配置，保存在既有 `media_capability_version.spec_json.settings.httpTimeouts`。每个能力可以独立调整，提交、查询、输入上传和 Provider 结果下载均使用任务固定的能力版本。修改配置发布新的不可变版本，不修改已经受理的请求、原任务或历史版本。

全局配置不能表达不同模型的等待时间；连接级配置会让共享连接的多个能力互相影响，因此不采用这两个方案。协议的地址、认证、重定向、禁止自动重发和媒体大小限制继续由适配器管理，不能通过超时配置改变。

## 管理界面与合约

现有能力发布和编辑表单增加“请求超时”分区；RunningHub 的发布流程也能填写。沿用现有 shadcn 输入、分区导航、提交校验及保存失败保留草稿的行为，不增加独立保存操作。

四个字段统一使用整数秒：

| 字段 | 含义 | 拟定范围 |
| --- | --- | --- |
| `connectSeconds` | 建立连接的等待上限 | 1–120 |
| `writeSeconds` | 请求体单次写入阻塞上限 | 1–3600 |
| `readSeconds` | 等待及读取响应时单次读取阻塞上限 | 1–3600 |
| `callSeconds` | 一次完整 HTTP 请求的总期限，包含连接、发送和读取 | 1–3600 |

连接、写入和读取上限均不得大于总期限。总期限不会因为持续传输或进入下一阶段而重置；四个值不能解释为四段可相加的等待时间。不接受 0、负值、小数或无上限配置。

范围按本次确认的设计采用。接口与界面均校验，服务端是权威来源。默认值沿用各协议现有连接、读取和总调用配置；新发布表单的写入默认值与总调用上限对齐，避免遗漏客户端默认写入限制。

默认值由服务端随媒体设置返回，前端不再维护另一份超时默认表。`FixedMediaAdapterSettings` 增加可选的完整 `httpTimeouts` 对象，OpenAPI、Java 实现、生成 TypeScript、契约测试及四语言文案同步。

## 执行与版本

执行时从 `MediaCapabilityBinding` 指定的不可变版本读取配置，通过显式的调用配置传入 Provider HTTP 客户端及其下载路径，不修改 Spring 单例客户端，不使用跨调用共享的可变配置，也不依赖线程局部业务配置。

管理员发布新超时后，新受理任务使用新版本；原请求的轮询、归档和结果下载继续使用原版本。即使一个连接并发运行两个不同超时的能力，也不会相互覆盖。配置读取和网络调用分别发生在短事务及事务外。

总期限针对每次实际 HTTP 请求，不是整个异步生成任务的时长。轮询间隔、Provider 作业期限、结果下载次数及原请求查询规则仍由各协议管理。没有能力版本的元数据发现、工作流导入、模型列表或连接检查继续使用既有有界默认，不为读取这些信息隐式发起生成。

## 租约与失败

可配置的网络等待可能长于部署租约，因此媒体 Worker 在执行提交、查询和归档期间使用独立的有界心跳线程调用现有 Task 应用接口续租，不让 HTTP 等待阻塞续租。状态写回继续检查 taskId、leaseEpoch 和预期状态。续租失败不能被解释为 Provider 拒绝或触发重新生成；旧 Worker 写回仍由 fencing 拒绝，不承诺取消上游或退款。

媒体续租必须区分真正失去租约与 `cancelRequested`，不能直接复用拒绝取消标记的模型心跳。原 ID 轮询及归档所处状态必须可续接；已受理请求取消后仍按既有规则核对并归档晚到结果，不自动选用，不允许以续租或恢复为由创建新的生成。

调用超时继续沿用现有协议的稳定错误分类；提交受理结果不确定时保留 UNKNOWN。调整配置、保存能力、查询和归档都不重新提交 UNKNOWN 的生成请求。管理员主动新建尝试仍受当前业务入口及费用规则约束。

## 历史数据与升级

复用既有 JSONB，无表结构迁移或 jOOQ 重新生成。历史能力没有 `httpTimeouts` 时保留既有协议默认和专用下载默认，不回写旧快照。编辑旧能力时显示可配置的默认值；只有管理员明确修改超时才随新版本保存，避免仅修改名称就悄悄改变历史配置。

GPT Image 沿用此次能力配置开发前已修正的 5 分钟缺省写入上限；其缺省读取和整次调用同为 5 分钟。其他历史协议的默认值不因新增发布表单而统一改写。

需要同步升级前后端，以便新字段校验、保存、展示及执行一致。旧任务不自动恢复、不自动重新生成，也不根据现在的能力配置推导历史超时。

## 验收

1. 发布和编辑所有网络能力均可保存、刷新并再次修改四个值；本地和 Mock 不显示且拒绝无效的 HTTP 配置。
2. 前后端覆盖空值、零、负数、小数、超界、阶段上限超过总期限、失败保留草稿及 CAS 冲突。
3. 各协议使用受控 HTTP 服务证明能力配置进入实际请求；覆盖同步图片大请求体、异步提交和轮询、输入上传、结果下载及 ComfyUI，不以只检查配置对象代替网络行为。
4. 并发使用不同能力配置互不污染；真实 PostgreSQL 验证新旧能力版本、任务绑定、租约续接及租约丢失后的 fencing。
5. 慢发送和慢响应均受配置约束，总期限不能因持续传输而延长；提交超时不自动重发，原 UNKNOWN 不改写。
6. 无迁移、生成代码手改、依赖升级或真实素材进入公开资料；真实 Provider 付费调用与模拟验收分列，部署和未运行范围据实报告。
