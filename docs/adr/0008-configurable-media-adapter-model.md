# ADR 0008：媒体适配器的模型名与端点可配

状态：接受（2026-09-26；2026-09-30 补充 Gemini 版本说明；2026-10-03 补充远程 ComfyUI）。

## 背景

ADR 0002 确立「固定适配器」路线：每个适配器把模型版本、请求路径与请求体格式固化在代码里，`OPENAI_GPT_IMAGE_2` 与 `GOOGLE_NANO_BANANA_2` 的模型名分别硬编码为 `gpt-image-2` 和 `gemini-3.1-flash-image`，Google 平台还禁止配置自定义端点。

但实际部署中，管理员需要把这两个适配器指向第三方中转站：中转站提供与官方不同的域名和模型名，而模型名无法预知。这带来两类阻塞：

- 模型名写死，中转站上同协议但不同名的模型无法使用；
- Google 平台的端点被 `validatedOrigin` 与 `MediaCapabilityService` 两处显式拒绝，中转站地址存不进去。

此外，`OpenAiImage2Client` 与 `GoogleNanoBananaClient` 各自带一个 `testOrigin` 构造参数，用于让集成测试把请求指向本地假 API。它是测试策略与出口校验规则冲突的产物，却以「仅测试可用」的分支形式留在了生产代码里。

## 决策

- **模型名可配**：作为能力参数存放于 `specJson.settings.model`，与既有 `quality` 同机制，因此不需要数据库迁移。留空时回退到客户端声明的 `DEFAULT_MODEL`。校验保持从宽——非空、长度上限 120、字符集 `[A-Za-z0-9._:/-]`——因为中转站的命名格式不可预知，严格格式校验只会挡住合法取值。
- **Google 端点放开**：与 OpenAI 共用一套规则（HTTPS 公网根地址，或字面 `127.0.0.1`），并在 `validatedOrigin`、能力发布校验、`apiEndpoint` 三处保持一致。此前只有 OpenAI 被豁免。
- **Gemini 请求格式明确展示**：Google 连接的 API Base URL 保留版本与路径前缀；空值或裸主机默认 `/v1`，显式 `/v1beta` 使用兼容格式。它们仍属于同一个固定 Gemini 适配器，与能力中配置的模型名分开。连接列表显示当前格式，新建/编辑连接显示两种地址后缀的区别、完整调用地址与供应商自定义 draw 接口的边界、已验证中转站示例；发布/编辑能力提示中转站须使用其模型名。配置说明不新增可任意组合的请求模板或自动探测，详见真实验证（开发记录不随源码公开）。
- **回环例外**：`http://127.0.0.1:port` 被显式允许，与 ComfyUI 分支的既有规则一致。DNS 校验相应放行回环，但仍按 hostname 判定，因此域名被解析到回环依然会被拒（防 DNS 重绑定）。
- **移除 `testOrigin`**：客户端改为无状态——端点由每次调用传入，来自能力配置。测试不再需要构造专用客户端，集成测试改为把本地假 API 地址配置为连接端点即可。

## 2026-10-03：远程 ComfyUI 与通用代理地址

本地 `127.0.0.1` 限制阻止管理员使用远程 ComfyUI。按用户决定保留一个完整地址字段，不拆分代理地址中的 Key，以兼容标准 ComfyUI 的不同代理路径。允许远程 HTTPS 和本地精确 HTTP IPv4/端口；所有固定 API 路由追加到已配置前缀，执行与保存共用校验，逐次 DNS 检查、禁止重定向与提交自动重试。

路径可能包含凭据，因此在线配置将整个地址加密保存在已有媒体凭据列，不新增表或明文 Key 字段；摘要按完整规范化地址计算。API 返回主机及路径存在标记 `/[configured-path]`，编辑时原样提交标记保留旧地址，替换则提交完整新地址。历史无密文本地根地址仍可读，有路径的环境配置要求主密钥。调试采集提前登记路径片段，移除请求地址和响应回显中的对应值。

代价是保存后不能再次查看完整路径，更换时需重新填写；交换条件是通用代理兼容性与凭据保护。固定工作流、文件名、UNKNOWN 与历史版本边界保持。协议假服务、配置持久化及图片/视频历史归档用于验证；真实 RunningHub 代理和 GPU 未实测。

## 2026-10-04：ComfyUI 受理 ID 以服务端回执为准

RunningHub 的原生 ComfyUI 代理可以返回数字字符串 `prompt_id`，与提交请求中的本地 UUID 不同。此前强制解析 UUID 并要求相等，使成功受理的请求在提交阶段抛出协议异常：Task 保持 SUBMITTING，无法保存原远程 ID 或进入历史查询，租约到期才转 UNKNOWN。官方教程将代理地址作为 ComfyUI 基地址使用，不保证代理保留客户端指定的任务 ID。协议参考：[RunningHub 原生接入指南](https://www.runninghub.ai/runninghub-api-doc-en/doc-8287466)、[ComfyUI 路由文档](https://docs.comfy.org/development/comfyui-server/comms_routes)。

成功回执中的 `prompt_id` 是远程任务身份，按最多 240 字符的安全字符串保存并贯穿图片、视频、导入工作流的查询与结果来源；不要求 UUID、不要求等于本地请求键，也不依赖附加状态字段。路径校验只接受 ASCII 字母、数字、下划线和连字符，禁止改变固定查询路由。数据库与应用 API 的原远程请求 ID 本已使用字符串，因此无需迁移或合约变更。

本地 UUID 继续承担提交前持久检查点、client_id、候选 prompt_id、种子及上传命名。代价是不能把该候选值视为远程身份保证；没有保存合法受理回执时仍按 UNKNOWN 处理，禁止自动重提。既有已保存 UUID 字符串的历史任务按原值继续查询；此前因校验错误而缺失远程 ID 的任务不会自动修复。验证使用合成 HTTP 与真实 PostgreSQL，不以合成结果声明真实 RunningHub 生成已验证。

## 2026-10-04：ComfyUI 代理历史终态与文件下载兼容

实际原生代理历史响应可以只提供 `status_str=success` 与发布节点的单个媒体结果，省略 `completed`。此前把该布尔字段当作必填，成功受理并完成的任务会在结果查询中被阻断。按明确终态接受缺失的完成标志，但字段存在时仍校验其布尔类型；非终态或未知状态不因字段缺失而被当作成功，输出数量、发布节点、媒体类型及安全文件路径继续独立校验。

该代理的固定 `/view` 还可通过同源跳转再转向 HTTPS 媒体下载地址。按用户明确决定，取消 ComfyUI 各固定路由的一律禁止重定向限制；上传、提交、查询与结果下载都允许跟随最多三次 301/302/303/307/308，各跳重新验证且关闭前一响应。307/308 保留方法与正文；301/302 的 POST 和 303 的非 HEAD 请求改为 GET，移除正文及其 Content-Type。同源保留管理员地址策略，跨源限制为 HTTPS 默认端口并显式检查字面 IP 和 DNS 答案，拒绝私网、环回、链路本地、元数据、多播与非路由目标，保留已有 fake-IP DNS 兼容。新请求只保留协议必需的 Accept 和正文 Content-Type，不复制认证、Cookie 或 Referer，原路径凭据不得进入跨源地址，跳转凭据不记录到日志。各调用入口仍由固定协议路由确定，结果下载仍从 `/view` 与发布输出规则确定，模型与用户不能提供下载 URL；跟随服务端跳转不等于重新提交，网络失败或响应丢失仍保持既有 UNKNOWN 行为，不自动重做生成。此条替代上文对重定向的统一禁止。

定向验证使用脱敏结构重放、合成 HTTP 与真实 PostgreSQL；另外只读取得一个已完成代理任务的原图片，确认缺失完成标志、两次 302 和最终可解码 PNG。未重新提交付费生成，也未以此声明全部模型、工作流或完整部署验收完成。

## 取舍与影响

本决策放松了 ADR 0002 的「固定」程度：模型标识与主机由编译期常量变为运行期配置，请求体中的模型名不再可静态断言，契约测试因此改为验证「请求携带配置值」。

保留的约束：协议、请求路径形状与响应解析仍由代码固定，可换的只有模型标识与主机。这满足中转站需求，又不引入任意请求模板。

代价是管理员可以配错模型名而得到 Provider 侧的 404/400，失去「配不错」的保障。交换条件是自托管场景下能使用任意同协议网关——这与项目「可开源独立运行」的定位一致。

集成测试的结构也因此更诚实：它们验证的是任务编排（Worker 提交、租约恢复、UNKNOWN 流转、引用鉴权），此前却需要一个生产代码里的测试分支才能跑通；现在只需按正常路径配置端点为本地假 API。

2026-10-04 补充：自托管 ComfyUI 能力改为管理员导入 API JSON、按节点映射并发布，图及固定参数也随能力版本保存；这取代本 ADR 对 ComfyUI 仅可配置模型文件名的限制。地址、凭据与历史任务边界继续适用，见 [ADR 0030](0030-comfyui-imported-workflow-capabilities.md)。
