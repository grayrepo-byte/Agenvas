# ADR 0025：RunningHub 固定协议与版本化输入契约

状态：接受（2026-10-01，用户要求实施 RunningHub API 接入及动态表单）。覆盖 [ADR 0002](0002-fixed-media-adapters-before-workflow-platforms.md) 中暂缓 RunningHub 平台接入的决定；动态脚本、Agent 媒体工具及任意工作流执行的禁令继续有效。

RunningHub 工作流和 AI 应用共享任务协议，但每个目标的节点输入、素材和输出不同。采用项目维护的 Java V2 协议实现，管理员将真实目标 ID、开放字段、固定值和输出映射发布为现有媒体能力版本。新增同协议目标只增加数据配置；不执行远程 JSON、cURL、表达式或用户脚本，也不提交完整 ComfyUI 工作流。

2026-10-24 用户要求智能判断默认创作参数和类型，并确认默认推荐提示词、素材、时长、画幅/尺寸及常用创作选项。扩展 `recommendedFieldKeys` 至用途明确的负向提示词、分辨率、帧率与画质；采样器、调度器、种子、模型及步数等内部参数保持手动选择，模糊普通文本不任意绑定主提示词。结合字段名、节点类型、标签/说明识别用途；带序号的参考素材槽位与独立文本输入可被识别，负向文本始终为普通参数。前端采纳服务端普通参数建议，继续按节点/字段身份保留既有配置及手工取消，已有主提示词优先。

使用真实公开 H3 工作流继续核对后，工作流类型补充采用明确 PrimitiveFloat 声明：即使 API JSON 的当前值序列化为整数，也保留 NUMBER。已知标量 Primitive 直接连接画幅、尺寸或分辨率等创作端口时，可将明确用途传给源 value 字段并取消它的主提示词资格；只读取一跳数据，不计算表达式或沿任意图推演。尺寸对齐 multiple 与模型预览参数保持手动，避免从节点标题或字段后缀误推荐。公开工作流缺少枚举定义时，画幅字符串继续保留 STRING，不从一个默认值制造下拉选项。

类型推断首先采用明确协议类型；缺失、未知或泛型 STRING 类型可采用有类型的控件元数据，唯一明确的上传标记可补充媒体语义，冲突标记不猜测。保留数字、整数、布尔、枚举值的类型，以及有效的数值范围、文本长度和明确必填规则；有效当前值优先于控件默认值，否则无默认，不从标签数字制造值。FLOAT 时长即使当前值为整数也保持 NUMBER，不自动绑定仅支持整数的 DURATION_SECONDS；下拉按真实选项保留类型和顺序，不静默去重、不制造枚举。原始导入 JSON 和历史能力版本不自动改写，同目标重新发现不会覆盖管理员手改类型或约束。仅更新既有发现合约说明，无 API 结构、schemaVersion、数据库或依赖变更。

2026-10-24 用户要求将能力发布的字段数量限制从 64 放宽至 1024，以支持包含较多常量输入的工作流自动发现。自动发现、离线导入、重新解析合并、手动添加及发布校验统一采用 1024 项开放字段上限，固定映射与发现建议字段键的合约上限同步。超过上限仍保留原配置与 JSON 草稿，错误文案显示当前上限。ComfyUI 复用标量解析但继续独立限制最多 64 个参数；源 JSON、完整定义大小、嵌套深度与媒体输入数量边界沿用现有规则。同步 OpenAPI 并重新生成 TypeScript，schemaVersion 仍为 1，无数据库迁移。

2026-10-24 修复 AI 应用发现将上传控件文件列表当作下拉选项的问题：只为声明为 LIST 的字段解析 `fieldData` 枚举，图片、音频、视频与普通标量不携带该元数据产生的候选选项。素材控件可包含重复文件名，不应因此触发“下拉选项值重复”；真实下拉字段的值唯一性校验继续保留。保留原始导入 JSON、现有媒体类型识别和清空远程默认值的规则，无 API 结构、数据库或依赖变更。验证区分公开应用输入的只读回放与合成 HTTP 回归，不代表付费生成验收。

候选发现和发布分开。AI 应用元数据生成表单候选；ComfyUI API-format 只抽取普通常量输入，管理员必须核对类型、默认值、范围和素材语义。发现失败可导入脱敏 JSON。Key 不进入 URL；AI 应用公开详情发现不携带 Key，需要鉴权的调用示例发现仅发送 Bearer。目标必须是真实 workflowId / webappId，目录 SKU ID 不自动推断。

2026-10-06 用户追加要求在自动发现参数时填入功能名称。发现预览新增可空 `targetName`，AI 应用从公开详情 `data.name` 或调用示例 `data.webappName` 提取；工作流在成功读取输入契约后，以不携带 Key 的固定公开详情接口 `POST /api/portal/workflow/detail` 查询同 ID 的 `data.name`。名称去除首尾空白并安全截短到现有 160 字符限制，单独返回而不写入导入原文。工作流名称查询总超时 5 秒；私有目标、兼容站点或缺失名称不影响参数发现。前端仅填空白能力名称，保留已有及请求期间手动输入的名称；离线 JSON 不改名。名称只是显示草稿，需随能力显式保存，不授予执行权限。OpenAPI、Java 和生成 TypeScript 同步，无迁移或依赖变化。

2026-10-06 用户要求参数发现按用途自动整理，覆盖此前不推测语义及默认选择全部候选节点的规则。采用确定性识别，结合节点类型、字段名和标题/说明识别常见文本及图片、视频、音频加载输入；媒体值转为资源槽位，移除文件名与 URL 默认值。主提示词仅在用途明确时绑定画布 PROMPT：明确提示词优先于普通文本，正向 conditioning 路径优先；负向名称或负向路径的上游文本排除。同优先级多个文本不自动指定主提示词，保留供手动配置。连线只辅助识别，不成为开放字段或本地图执行能力。种子、模型名、采样设置和枚举等参数保留类型与原默认值，默认不暴露。

每个候选字段独立勾选“暴露”，默认选择识别出的主提示词和素材及其节点。保存、发布和离线预览使用节点与字段选择的交集；固定参数继续按节点选择。未暴露控件不参与原生校验，重新勾选恢复本次标量草稿；失败重试保留选择。相同目标重新发现保留已有映射与手动选择，只为新增识别字段应用默认建议；按节点/字段身份匹配，键冲突重命名仍保留正确建议，已有提示词映射优先。条件引用未暴露字段时阻止保存并要求修复。`recommendedFieldKeys` 新增于发现预览响应，选择仅存在编辑草稿，不写入能力版本；OpenAPI、Java 与生成 TS 同步，schemaVersion 仍为 1，无迁移或新依赖，前后端一起升级。旧能力需管理员显式重新发现/调整并保存，新规则不自动改写历史任务。验证使用合成配置和本地假 HTTP，不表示真实 Provider 兼容性。

2026-10-05 用户要求支持带点号的节点输入名称，覆盖此前仅允许字母、数字和下划线的映射限制。工作流与 AI 应用的开放字段、固定参数统一接受 `[A-Za-z_][A-Za-z0-9_.]{0,79}`，完整字段名作为不透明名称保存并原样提交，例如 `sampling_mode.top_p`。点号不授予 JSON 路径遍历或嵌套对象编辑能力；继续只导入标量，不更改稳定字段键、重复映射和保留名称检查。无数据库迁移或 schemaVersion 变化，前后端及 OpenAPI/生成 TS 同步升级；被旧导入器跳过的字段由管理员重新解析保存源或重新导入后发布，既有能力版本与任务不自动修改。合成参数和本地假 HTTP 回归不代表真实远程工作流效果。

2026-10-04 用户要求 AI 应用显示名称使用应用节点描述，以区分多个同类素材输入。候选名称优先取去除首尾空白的非空 `description`，再回退到非空 `nodeName` 和 `fieldName`；显示名称按已有 160 字符限制安全截短，完整描述仍保留在说明中。公开发现、调用示例回退和离线导入统一处理；节点选择及创作者槽位沿用候选名称。已发布能力不自动重写，管理员仅改名并保存即可保留稳定字段键和节点绑定；无需 API 或数据库迁移，不根据节点顺序推断参考图编号。

2026-10-01 用户明确取消域名白名单：管理员可填写 HTTPS API 根地址，素材上传返回值和结果下载不按域名名单拦截。固定请求路径、URL 结构和现有 DNS 地址检查、禁止重定向、Key 仅发往配置的 API 连接、下载不携带 Key 的边界继续有效。

草稿支持文字、数字、整数、布尔、枚举和具名图片/音频/视频槽位，保存精确内容版本；仅执行时补默认值并检查活动必填字段。提示词与时长按目标契约决定，不强制所有工作流提供它们。视频时长来源最多 60 整数秒；未声明时长的 SECOND 估算保持未知。外部提交前沿用当前配置和草稿核对，变化时阻断；外部已受理后按原绑定查询与归档。来源摘要和能力版本只冻结本地契约，不能承诺云端工作流不可变；本次没有运行前远程摘要核验。

一次远程任务按发布输出映射最多选取 16 个媒体结果，Provider 可以返回更多候选。先在数据库保存私有结果清单，再按任务和稳定序号恢复归档；所有内容版本、额外节点与任务完成同事务提交。主输出首个结果留在当前节点，同类额外输出复制冻结草稿，混合类型额外输出使用新产物身份和空白草稿。取消或选择冲突保留历史；提交结果未知保持 UNKNOWN，仅用户显式创建新尝试可再次生成。

2026-10-01 新目标 MinimaxH3 应用真实返回 MP4 与附带 ZIP，即使关闭“仅 ZIP 输出”。当时采用跳过附带 ZIP 的规则；2026-10-04 已被下述用户决定覆盖。

代价是管理员需要整理契约，真实目标的输入兼容性仍需单独验证；本地假服务测试不能证明云端生成。文本结果、旧式生成协议、Webhook、远程取消和通用脚本不在本次范围。协议事实与 SDK 审阅见 [研究文档](../research/runninghub-api-integration.md)，验收见 专项证据（开发记录不随源码公开）。

## ZIP 输出解包归档（2026-10-04，结果选择规则由下节修订）

用户要求发现 `outputType=zip` 时直接解压并将成员存为资源，覆盖此前跳过附带 ZIP 的决定。沿用 IMAGE/VIDEO/AUDIO 输出映射，不增加 ZIP 产物类型或 UI 输出枚举。ZIP 成员以扩展名发现候选，继承容器结果的节点 ID；同节点/通配映射和数量上限继续有效，真实媒体内容由 Asset 归档解码验证。ZIP 可以是唯一结果，也可与普通直出结果共存；两种结果都计入上限，不自动截断或按猜测忽略重复内容。普通附件与目录不成为创作资源，不递归解压其他 ZIP。

下载上限 500 MiB，单成员上限 500 MiB，累计解压上限 1 GiB，所有成员最多 256 个；额外保留原有各类媒体限制及最多 16 个媒体输出。拒绝绝对路径、驱动器路径、反斜线、空/点/父目录路径分段、重复名字、嵌套 ZIP、损坏 CRC 和截断包。远程成员名只存为私有描述，临时文件路径由服务端生成，尝试结束统一清理，不执行成员内容。

展开后的成员名、SHA-256 和稳定序号在归档前进入原私有结果清单，仍使用 schemaVersion=1 的可空成员描述扩展；旧直出清单没有该字段时沿用原下载行为，不改数据库或公开 API。归档尝试内按 ZIP URL 共用下载和解包，核对固定成员字节，复用已有 READY Asset。失败只重试原任务归档，不重新生成；取消、CAS、fencing、内容版本和额外节点规则不变。私有下载地址和成员名不进入公开事件或项目导出。

验证使用合成 ZIP、回环 HTTP、真实 PostgreSQL 和本地媒体解码；未进行本轮真实 RunningHub 下载、付费生成或部署验收。具体检查结果见开发清单。

## 结果选择与阻断后的显式新尝试（2026-10-05）

用户明确要求数量上限为 1 时取第一个结果，不能因额外 MP4 或附带 ZIP 直接阻断。这覆盖上节“所有结果必须计入上限、不自动截断”的规则：按 Provider 返回顺序扫描普通媒体与 ZIP，ZIP 内按成员顺序扫描；只保留符合已发布媒体类型和节点映射的前 `maxCount` 个结果。未映射媒体、未知输出类型和超出的结果跳过，不根据名称猜测合并内容。某 ZIP 可匹配的映射已取满时不下载该 ZIP；只有 ZIP 时仍解包选取。所选结果仍须包含主输出，固定私有清单、归档身份与顺序，并执行媒体解码和安全校验。

16 个限制属于选用清单，不能作为原始响应或 ZIP 媒体候选数量的拒绝条件。ZIP 仍受 256 成员、500 MiB 压缩/单成员、1 GiB 解压及路径、CRC、嵌套包限制约束；取满可跳过后续容器，但不放宽实际读取容器的安全边界。

直连媒体卡片对已受理 `BLOCKED` 任务复用现有 `/tasks/{taskId}/new-attempt` 接口和“重试”交互。用户点击后创建 READY 新任务，保留原输入、能力绑定、输出目标与独立费用预留；原任务、外部请求 ID、提交账本和错误历史不覆盖。新旧任务建立原有替代关联，旧任务退出卡片互斥和近期卡片任务列表。重复命令只返回同一新任务，其他命令键不能为原任务再次创建替代；版本、权限、取消、当前能力和目标归档前提继续校验。重试不恢复原请求查询，未受理阻断任务仍可修改草稿后直接运行。Agent 媒体审批与 AgentRun 的阻断路径未在此修订中取消。

公开 API 无结构性变化，更新描述并重新生成 TypeScript；无数据库迁移或 jOOQ 生成变化。针对旧的固定任务配置也使用新的结果选择规则，能力版本与原 Task 输入保持不可变；旧阻断记录不自动复活，不自动创建付费生成。


## AI 应用参数发现修复（2026-10-04）

旧实现只调用 `GET /api/webapp/apiCallDemo` 并发送 Bearer，但官方示例同时要求 query Key，因而部分 AI 应用无法导入参数。沿用 Key 不进入 URL 的决定，优先调用应用公开页面使用的固定 `POST /api/webapp/detail`，Body 只含 `webappId`，不发送凭据。从匹配目标 ID 的 `data.inputNodes` 提取非空候选；详情不可用、ID 不匹配或输入为空时回退到原 Bearer 调用示例。两条路径都只保留输入字段，不保留 cURL、作者或其他元数据；均失败时明确报错并保留本地脱敏导入。

公开详情是网页实现使用的发现协议，不承诺远程接口或工作流不可变。没有调整 V2 提交、用户审批、生成重试、发布合约或数据库。验证区分合成 HTTP 回归与真实公开应用只读发现；未进行本轮付费生成或部署验收。

## 参数映射编辑体验修订（2026-10-03）

2026-10-21 按完整设置重构要求更新呈现：RunningHub 发布与编辑采用最大 1360px、随视口收紧的工作台；目标来源、输入参数、输出运行、预览费用通过编号锚点导航，正文独立滚动，标题和底部操作固定。开放字段、固定参数及输出改为响应式卡片，按节点组织，接口身份与高级约束分层；窄屏重排字段而不依赖十列横滚。折叠只改变呈现，保留草稿和原有字段校验；隐藏约束校验失败自动展开该行。发现期间阻止旧契约提交，保留名称编辑；明确加载新版本时清除本地源文本与校验并忽略旧会话迟到响应。关闭重开保留未解析 JSON 的页面内草稿，原文不自动成为已发布契约。

此修订同时适用于共享编辑器的图片/视频/音频工作流与 AI 应用。不修改 schemaVersion、协议、发布 API、导入范围、归档或生成授权；不需要迁移。验证使用合成契约与本地表单，不代表真实远程工作流兼容性。

2026-10-04 用户澄清：删除“已核对开放字段、素材格式与输出映射”二次确认选项及其状态、校验和自动提交逻辑。配置仅通过底部“发布能力”或“保存能力”按钮提交；字段编辑、导入和输出类型切换只修改草稿。保留原有字段校验、CAS、权限与草稿保护；成功后关闭窗口，校验或保存失败保留草稿，用户点击按钮显式重试。该交互复用现有保存/发布 API，不提交生成，也不需要迁移。
