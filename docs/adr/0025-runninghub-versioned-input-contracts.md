# ADR 0025：RunningHub 固定协议与版本化输入契约

状态：接受（2026-10-01，用户要求实施 RunningHub API 接入及动态表单）。覆盖 [ADR 0002](0002-fixed-media-adapters-before-workflow-platforms.md) 中暂缓 RunningHub 平台接入的决定；动态脚本、Agent 媒体工具及任意工作流执行的禁令继续有效。

RunningHub 工作流和 AI 应用共享任务协议，但每个目标的节点输入、素材和输出不同。采用项目维护的 Java V2 协议实现，管理员将真实目标 ID、开放字段、固定值和输出映射发布为现有媒体能力版本。新增同协议目标只增加数据配置；不执行远程 JSON、cURL、表达式或用户脚本，也不提交完整 ComfyUI 工作流。

候选发现和发布分开。AI 应用元数据生成表单候选；ComfyUI API-format 只抽取普通常量输入，管理员必须核对类型、默认值、范围和素材语义。发现失败可导入脱敏 JSON。Key 不进入 URL；AI 应用公开详情发现不携带 Key，需要鉴权的调用示例发现仅发送 Bearer。目标必须是真实 workflowId / webappId，目录 SKU ID 不自动推断。

2026-10-04 用户要求 AI 应用显示名称使用应用节点描述，以区分多个同类素材输入。候选名称优先取去除首尾空白的非空 `description`，再回退到非空 `nodeName` 和 `fieldName`；显示名称按已有 160 字符限制安全截短，完整描述仍保留在说明中。公开发现、调用示例回退和离线导入统一处理；节点选择及创作者槽位沿用候选名称。已发布能力不自动重写，管理员仅改名并保存即可保留稳定字段键和节点绑定；无需 API 或数据库迁移，不根据节点顺序推断参考图编号。

2026-10-01 用户明确取消域名白名单：管理员可填写 HTTPS API 根地址，素材上传返回值和结果下载不按域名名单拦截。固定请求路径、URL 结构和现有 DNS 地址检查、禁止重定向、Key 仅发往配置的 API 连接、下载不携带 Key 的边界继续有效。

草稿支持文字、数字、整数、布尔、枚举和具名图片/音频/视频槽位，保存精确内容版本；仅执行时补默认值并检查活动必填字段。提示词与时长按目标契约决定，不强制所有工作流提供它们。视频时长来源最多 60 整数秒；未声明时长的 SECOND 估算保持未知。外部提交前沿用当前配置和草稿核对，变化时阻断；外部已受理后按原绑定查询与归档。来源摘要和能力版本只冻结本地契约，不能承诺云端工作流不可变；本次没有运行前远程摘要核验。

一次远程任务可以返回最多 16 个受约束媒体结果。先在数据库保存私有结果清单，再按任务和稳定序号恢复归档；所有内容版本、额外节点与任务完成同事务提交。主输出首个结果留在当前节点，同类额外输出复制冻结草稿，混合类型额外输出使用新产物身份和空白草稿。取消或选择冲突保留历史；提交结果未知保持 UNKNOWN，仅用户显式创建新尝试可再次生成。

2026-10-01 新目标 MinimaxH3 应用真实返回 MP4 与附带 ZIP，即使关闭“仅 ZIP 输出”。当时采用跳过附带 ZIP 的规则；2026-10-04 已被下述用户决定覆盖。

代价是管理员需要整理契约，真实目标的输入兼容性仍需单独验证；本地假服务测试不能证明云端生成。文本结果、旧式生成协议、Webhook、远程取消和通用脚本不在本次范围。协议事实与 SDK 审阅见 [研究文档](../research/runninghub-api-integration.md)，验收见 专项证据（开发记录不随源码公开）。

## ZIP 输出解包归档（2026-10-04）

用户要求发现 `outputType=zip` 时直接解压并将成员存为资源，覆盖此前跳过附带 ZIP 的决定。沿用 IMAGE/VIDEO/AUDIO 输出映射，不增加 ZIP 产物类型或 UI 输出枚举。ZIP 成员以扩展名发现候选，继承容器结果的节点 ID；同节点/通配映射和数量上限继续有效，真实媒体内容由 Asset 归档解码验证。ZIP 可以是唯一结果，也可与普通直出结果共存；两种结果都计入上限，不自动截断或按猜测忽略重复内容。普通附件与目录不成为创作资源，不递归解压其他 ZIP。

下载上限 500 MiB，单成员上限 500 MiB，累计解压上限 1 GiB，所有成员最多 256 个；额外保留原有各类媒体限制及最多 16 个媒体输出。拒绝绝对路径、驱动器路径、反斜线、空/点/父目录路径分段、重复名字、嵌套 ZIP、损坏 CRC 和截断包。远程成员名只存为私有描述，临时文件路径由服务端生成，尝试结束统一清理，不执行成员内容。

展开后的成员名、SHA-256 和稳定序号在归档前进入原私有结果清单，仍使用 schemaVersion=1 的可空成员描述扩展；旧直出清单没有该字段时沿用原下载行为，不改数据库或公开 API。归档尝试内按 ZIP URL 共用下载和解包，核对固定成员字节，复用已有 READY Asset。失败只重试原任务归档，不重新生成；取消、CAS、fencing、内容版本和额外节点规则不变。私有下载地址和成员名不进入公开事件或项目导出。

验证使用合成 ZIP、回环 HTTP、真实 PostgreSQL 和本地媒体解码；未进行本轮真实 RunningHub 下载、付费生成或部署验收。具体检查结果见开发清单。

## AI 应用参数发现修复（2026-10-04）

旧实现只调用 `GET /api/webapp/apiCallDemo` 并发送 Bearer，但官方示例同时要求 query Key，因而部分 AI 应用无法导入参数。沿用 Key 不进入 URL 的决定，优先调用应用公开页面使用的固定 `POST /api/webapp/detail`，Body 只含 `webappId`，不发送凭据。从匹配目标 ID 的 `data.inputNodes` 提取非空候选；详情不可用、ID 不匹配或输入为空时回退到原 Bearer 调用示例。两条路径都只保留输入字段，不保留 cURL、作者或其他元数据；均失败时明确报错并保留本地脱敏导入。

公开详情是网页实现使用的发现协议，不承诺远程接口或工作流不可变。没有调整 V2 提交、用户审批、生成重试、发布合约或数据库。验证区分合成 HTTP 回归与真实公开应用只读发现；未进行本轮付费生成或部署验收。

## 参数映射编辑体验修订（2026-10-03）

用户要求扩大 ComfyUI 工作流能力配置窗口，并将参数绑定改为逐行映射。发布和编辑使用最大 1480 px、随视口收紧的大窗口，保留独立正文滚动和固定底部操作。开放字段、固定参数、输出映射均使用表格；开放字段的常用映射在同一行直接编辑，其他约束可展开。折叠只改变呈现，保留草稿和原有字段校验；隐藏约束校验失败自动展开该行。窄屏在表格内横向滚动。

此修订同时适用于共享编辑器的图片/视频/音频工作流与 AI 应用。不修改 schemaVersion、协议、发布 API、导入范围、归档或生成授权；不需要迁移。验证使用合成契约与本地表单，不代表真实远程工作流兼容性。

2026-10-04 用户澄清：删除“已核对开放字段、素材格式与输出映射”二次确认选项及其状态、校验和自动提交逻辑。配置仅通过底部“发布能力”或“保存能力”按钮提交；字段编辑、导入和输出类型切换只修改草稿。保留原有字段校验、CAS、权限与草稿保护；成功后关闭窗口，校验或保存失败保留草稿，用户点击按钮显式重试。该交互复用现有保存/发布 API，不提交生成，也不需要迁移。

2026-10-04 后续用户决定：参数区支持多选节点，同时展示所选节点的开放字段与固定参数，并提供全选与清空选择；取消选择保留未提交标量及所有草稿，隐藏节点仍参与保存校验，错误自动补选对应节点并展开、聚焦首个错误，保留其他节点的选择。手动新增节点使用待配置节点组；单选时添加参数沿用该节点，多选时必须明确选择参数所属节点。节点选择仅控制参数展示，不修改输入契约或保存配置；离线表单预览默认折叠。

2026-10-04 编辑回显修复：打开已有能力时默认选中全部已保存的输入节点（包括仅有固定参数的节点），直接展示已保存的字段、固定参数与输出映射，无需重新发现。发现或导入成功后默认展示全部候选节点。后续手动筛选或清空选择继续只控制呈现，编辑时不自动调用远程发现接口；沿用已保存契约和发布版本，无 API 或数据库迁移。

2026-10-04 节点名称展示：用户要求选择节点时显示序号和名称。节点列表、已选摘要及新增参数目标菜单统一显示“节点 ID · 名称”，复用同节点首个有效开放字段的当前标签；工作流导入标签仅移除准确匹配的字段名后缀，保留节点标题或类型名。已保存配置无需重新导入，管理员修改标签后展示同步变化；固定参数独占节点或无有效名称时保留 ID，待配置节点保持原提示。长名称在菜单中换行并保留完整提示。没有独立原始节点名称元数据，因此展示当前配置名称；不新增 API 字段、数据库迁移或远程发现请求，实际映射和生成授权不变。

输出映射的媒体类型允许保存后继续修改。主输出变更同步调整 RunningHub 适配器及能力类型，保留目标与字段，清空计费单位不兼容的估算价格；服务端仍要求主输出与能力类型一致。新版本不覆盖旧版本和已受理任务。若原类型默认选择指向该能力，保存事务内清空选择并递增默认版本，不自动移到新类型，也不改写其他默认或旧类型草稿。能力修改与默认选择按能力行锁串行，防止并发操作重新选入类型不匹配的能力；原有 CAS 继续执行。其他固定适配器维持类型不可变。新增 V10 仅放开默认能力的空值，不清理既有配置；jOOQ 从隔离 PostgreSQL 重新生成，OpenAPI 与生成 TS 同步，前后端一起升级。


## 2026-10-04 视频功能绑定

视频高清、深度提取与音频分离可以绑定已有 RunningHub 能力，但契约必须只声明一个无条件 VIDEO 媒体字段，主输出分别匹配 VIDEO 或 AUDIO。普通参数继续按白名单契约校验，来源槽只能使用用户当前选用且服务端重新鉴权的视频版本。多媒体输入生成能力不冒充单视频处理。

功能绑定通过独立设置 CAS 保存；运行还核对已展示的能力版本，冻结完整输入契约、目标、能力版本、来源版本和参数后复用现有上传、提交、查询、归档、用量及 UNKNOWN 语义。无时长来源字段的工作流保留未知时长与按秒未知费用，不用零秒伪造估算。此绑定不开放任意 ComfyUI 工作流、URL、HTTP 模板或第三方脚本。具体工作流的 AI 超分语义由管理员核验，不因输出类型为 VIDEO 就声称模型效果已经验证。

## 2026-10-04 图片功能绑定

图片后处理可绑定匹配 IMAGE 主输出且仅有一个无条件 IMAGE 媒体字段的已发布契约。应用固定选用的来源版本，表单不能替换来源；普通参数只按白名单字段读取，操作指令由服务端填入 PROMPT，完整契约及能力版本冻结到原任务。透明输出工具仅使用已声明透明支持的适配器；当前 RunningHub 契约没有该声明，不能仅凭工作流名称当作透明能力。幂等重放读取原任务并保留 UNKNOWN 显式重试边界，不接任意 HTTP 模板或工作流执行。

## 2026-10-04 统一画布编辑栏

用户要求工作流和普通模型使用一致的资源缩略图、提示词及底部配置布局。已发布 IMAGE/AUDIO/VIDEO 字段声明具名槽位，已分配素材在资源栏显示具名缩略图，一个槽位对应一个精确内容版本，数量和类型按契约限制；同一版本仍可用于多个槽位。PROMPT 映射使用共享提示词，没有此映射时保留置灰区域并说明原因。其余开放文字、LoRA、seed、开关、枚举及声明的时长通过底栏“扩展参数”表格弹窗逐行编辑；不再将全部动态字段放入主提示词面板。

条件、类型、默认值、必填与运行锁定继续按已发布契约执行；选择或上传媒体后明确记录槽位分配，替换和删除同步维护精确输入与相关来源。此布局不改变 RunningHub V2、30 MiB 上传限制、去重版本上限、任务冻结、用户生成授权或 UNKNOWN 边界；ComfyUI 安全输入目录扩展见 ADR 0030。没有数据库迁移，前后端与生成合约类型一起升级；本轮 UI 验证使用合成数据，不声称真实工作流效果。

2026-10-04 后续用户明确要求与全能参考一样，只保留一个共享添加入口，避免把全部未使用槽位显示为空上传框。通过上传、资源库、画布或个人资产选择新增素材时，按素材类型和发布顺序自动分配第一个活动且同类型的空槽位；音频和视频可直接填入自己的空槽，不必先填完其他类型的可选槽位。没有活动空槽时禁用入口，不增加槽位选择弹窗。共享上传归档完成时重新核对活动空槽，期间被画布连线填入的素材不被覆盖；若同类型槽位已满，保留归档结果并提示用户移除素材后显式重试，不重复上传字节。已分配缩略图继续提供具名替换与清空，多槽复用精确版本、条件、类型、数量、必填、CAS、运行锁定及上传失败重试边界保持不变。个人资产选择沿用现有 `slotKey`，在选择时确定并固定到原导入请求；此次入口调整没有 API 合约或数据库迁移变更。

## 画布连线与个人资产赋槽（2026-10-04）

RunningHub 的已发布媒体槽位接受画布 IMAGE / VIDEO / AUDIO 精确版本，输入类型按字段契约校验，与输出类型独立。普通拖线按发布顺序填第一个活动、同类型且未占用的槽位，不新增槽位选择交互；已赋槽精确版本只追加来源并保持原分配。没有槽位、条件未启用、容量已满、重复端点或 CAS 冲突时不留下部分连线或引用。连接只准备输入，不受理生成。断开最后来源同步清除使用该版本的槽位，存在手动或其他线来源时保留。

个人资产选择扩展 `ReferenceLibraryRequest.slotKey` 为可选字段，导入出的同项目新版本在原完成事务内写入该槽位。明确替换允许覆盖该槽的旧分配；旧版本仍被其他槽位使用时保留其去重引用与来源，独占旧版本则清除引用、连线和结构化标签。所有步骤受同一草稿 CAS 和导入事务保护，冲突整体回滚；命令键包括槽位，重复提交复用原结果，同键异参返回冲突。普通引用省略该字段保持原请求；画布连接 API 沿用原字段，不新增槽位参数。没有数据库迁移，合约生成 TypeScript 与前后端同步部署；验证使用合成资产及真实 PostgreSQL，不证明真实 Provider 生成效果。

## 2026-10-04 输出节点下拉选择

用户要求把不可用的输出节点文本输入改成下拉选择。沿用现有 Select，主输出和额外映射均显示“节点 ID · 名称”，并明确提供按媒体类型匹配的通配选项。完整工作流导入在可选 `nodeOptions` 中保存最多 2048 个唯一数字 ID 与受限名称，包含只有连线或没有标量输入的节点，避免仅从开放字段推导候选而遗漏实际输出节点；不保存连线、原图或其他元数据。名称优先取管理员当前字段标签，缺少时回退导入标题、类型名或 ID。目录、输入/固定映射及已保存输出 ID 合并后按数字顺序展示；参数区筛选不影响候选，旧输出 ID 在本次编辑中切换后仍能选回。长名称在菜单内换行。

AI 应用只公开输入列表时不能可靠发现输出节点，因此保留按媒体类型匹配；旧配置没有目录时保留原输出映射，可重新发现或导入完整工作流补齐。节点目录仅为显示元数据，不推断结果类型，不作为绑定白名单，也不提升权限。继续由管理员选定实际输出映射，沿用数量、通配重叠、主输出、CAS 与版本校验。Java、OpenAPI 和生成 TypeScript 同步扩展，schemaVersion 仍为 1，原 JSON 无需迁移；部署须一起更新前后端。定向验证使用合成配置和本地浏览器，不代表真实远程工作流效果。

## 2026-10-04 导入 JSON 随能力版本保留

用户指出仅保存映射或节点目录不足以恢复完整候选，后续修改不应要求重新找文件。本决定扩展前述输出节点目录的保存范围：新增可选 `importSource`，保留经过相同凭据检查并解开请求包裹后的完整工作流 API JSON；AI 应用只保留输入节点数组，不保留请求演示、cURL 或外层作者信息。它是管理员编辑资料，原导入值与修改后的映射分别保存；不将它作为提交模板，修改不能改变 RunningHub 云端工作流。源与映射保存在原能力版本 JSON，不覆盖历史，不新增表或迁移。旧版本省略源仍可使用原映射；已丢弃的源无法无损还原，可由管理员显式发现一次后保存补齐。

编辑器打开即回显源 JSON。同一目标重新解析按节点 ID 与字段名匹配，保留管理员字段键、名称、类型、默认值、约束、固定参数、输出和执行选项；固定绑定不再变成开放字段，新候选分配唯一键。切换目标后首次解析沿用新导入契约，不将原目标映射混入。解析失败或合并超过 64 个字段保留现有配置和输入草稿，等待管理员修正；没有自动保存或重新生成。保留单独的自动发现按钮，缓存源重新解析只走本地预览校验，不访问 Provider。

源限制仍为 256 KiB，完整定义提升为 1 MiB 以容纳源与映射，嵌套限制 64。直接能力写入也拒绝凭据字段。普通创作者/Agent 目录剔除源与节点目录，任务公开执行契约只冻结实际映射，避免把导入原文带入公开任务、导出或模型上下文；管理员设置和不可变能力版本继续保留源。Java、OpenAPI、生成 TypeScript 与前后端同步升级，schemaVersion 仍为 1。验证使用合成 JSON、本地表单与真实 PostgreSQL，不代表真实云端效果。
