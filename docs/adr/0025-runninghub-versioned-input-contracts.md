# ADR 0025：RunningHub 固定协议与版本化输入契约

状态：接受（2026-10-01，用户要求实施 RunningHub API 接入及动态表单）。覆盖 [ADR 0002](0002-fixed-media-adapters-before-workflow-platforms.md) 中暂缓 RunningHub 平台接入的决定；动态脚本、Agent 媒体工具及任意工作流执行的禁令继续有效。

RunningHub 工作流和 AI 应用共享任务协议，但每个目标的节点输入、素材和输出不同。采用项目维护的 Java V2 协议实现，管理员将真实目标 ID、开放字段、固定值和输出映射发布为现有媒体能力版本。新增同协议目标只增加数据配置；不执行远程 JSON、cURL、表达式或用户脚本，也不提交完整 ComfyUI 工作流。

候选发现和发布分开。AI 应用元数据生成表单候选；ComfyUI API-format 只抽取普通常量输入，管理员必须核对类型、默认值、范围和素材语义。发现失败可导入脱敏 JSON。Key 不进入 URL；AI 应用公开详情发现不携带 Key，需要鉴权的调用示例发现仅发送 Bearer。目标必须是真实 workflowId / webappId，目录 SKU ID 不自动推断。

2026-10-01 用户明确取消域名白名单：管理员可填写 HTTPS API 根地址，素材上传返回值和结果下载不按域名名单拦截。固定请求路径、URL 结构和现有 DNS 地址检查、禁止重定向、Key 仅发往配置的 API 连接、下载不携带 Key 的边界继续有效。

草稿支持文字、数字、整数、布尔、枚举和具名图片/音频/视频槽位，保存精确内容版本；仅执行时补默认值并检查活动必填字段。提示词与时长按目标契约决定，不强制所有工作流提供它们。视频时长来源最多 60 整数秒；未声明时长的 SECOND 估算保持未知。外部提交前沿用当前配置和草稿核对，变化时阻断；外部已受理后按原绑定查询与归档。来源摘要和能力版本只冻结本地契约，不能承诺云端工作流不可变；本次没有运行前远程摘要核验。

一次远程任务可以返回最多 16 个受约束媒体结果。先在数据库保存私有结果清单，再按任务和稳定序号恢复归档；所有内容版本、额外节点与任务完成同事务提交。主输出首个结果留在当前节点，同类额外输出复制冻结草稿，混合类型额外输出使用新产物身份和空白草稿。取消或选择冲突保留历史；提交结果未知保持 UNKNOWN，仅用户显式创建新尝试可再次生成。

2026-10-01 新目标 MinimaxH3 应用真实返回 MP4 与附带 ZIP，即使关闭“仅 ZIP 输出”。ZIP 作为附带归档文件跳过，不下载、解压或创建产物；仍要求合法映射的主媒体结果，其他未知类型继续拒绝。此规则不增加 ZIP 产物类型或执行能力，原任务查询与媒体归档不重新生成。

代价是管理员需要整理契约，真实目标的输入兼容性仍需单独验证；本地假服务测试不能证明云端生成。文本结果、旧式生成协议、Webhook、远程取消和通用脚本不在本次范围。协议事实与 SDK 审阅见 [研究文档](../research/runninghub-api-integration.md)，验收见 专项证据（开发记录不随源码公开）。

## AI 应用参数发现修复（2026-10-04）

旧实现只调用 `GET /api/webapp/apiCallDemo` 并发送 Bearer，但官方示例同时要求 query Key，因而部分 AI 应用无法导入参数。沿用 Key 不进入 URL 的决定，优先调用应用公开页面使用的固定 `POST /api/webapp/detail`，Body 只含 `webappId`，不发送凭据。从匹配目标 ID 的 `data.inputNodes` 提取非空候选；详情不可用、ID 不匹配或输入为空时回退到原 Bearer 调用示例。两条路径都只保留输入字段，不保留 cURL、作者或其他元数据；均失败时明确报错并保留本地脱敏导入。

公开详情是网页实现使用的发现协议，不承诺远程接口或工作流不可变。没有调整 V2 提交、用户审批、生成重试、发布合约或数据库。验证区分合成 HTTP 回归与真实公开应用只读发现；未进行本轮付费生成或部署验收。

## 参数映射编辑体验修订（2026-10-03）

用户要求扩大 ComfyUI 工作流能力配置窗口，并将参数绑定改为逐行映射。发布和编辑使用最大 1480 px、随视口收紧的大窗口，保留独立正文滚动和固定底部操作。开放字段、固定参数、输出映射均使用表格；开放字段的常用映射在同一行直接编辑，其他约束可展开。折叠只改变呈现，保留草稿、原有字段校验和重新核对要求；隐藏约束校验失败自动展开该行。窄屏在表格内横向滚动。

此修订同时适用于共享编辑器的图片/视频/音频工作流与 AI 应用。不修改 schemaVersion、协议、发布 API、导入范围、归档或生成授权；不需要迁移。验证使用合成契约与本地表单，不代表真实远程工作流兼容性。

2026-10-04 用户要求核对后直接保存：勾选“已核对开放字段、素材格式与输出映射”即提交当前表单，新建能力发布、已有能力保存，成功后关闭窗口。保留原有表单校验、CAS、权限与草稿保护；校验或保存失败不关闭、不自动重试，契约修改继续清除核对状态。该交互复用现有保存/发布 API，不提交生成，也不需要迁移。

2026-10-04 后续用户决定：参数区先选节点，再展示该节点的开放字段与固定参数；节点切换保留未提交标量及所有草稿，隐藏节点仍参与保存校验，错误自动切回对应节点并展开、聚焦首个错误。手动新增节点使用待配置节点组，添加参数沿用所选节点；离线表单预览默认折叠。

输出映射的媒体类型允许保存后继续修改。主输出变更同步调整 RunningHub 适配器及能力类型，保留目标与字段，清空计费单位不兼容的估算价格；服务端仍要求主输出与能力类型一致。新版本不覆盖旧版本和已受理任务。若原类型默认选择指向该能力，保存事务内清空选择并递增默认版本，不自动移到新类型，也不改写其他默认或旧类型草稿。能力修改与默认选择按能力行锁串行，防止并发操作重新选入类型不匹配的能力；原有 CAS 继续执行。其他固定适配器维持类型不可变。新增 V10 仅放开默认能力的空值，不清理既有配置；jOOQ 从隔离 PostgreSQL 重新生成，OpenAPI 与生成 TS 同步，前后端一起升级。


## 2026-10-04 视频功能绑定

视频高清、深度提取与音频分离可以绑定已有 RunningHub 能力，但契约必须只声明一个无条件 VIDEO 媒体字段，主输出分别匹配 VIDEO 或 AUDIO。普通参数继续按白名单契约校验，来源槽只能使用用户当前选用且服务端重新鉴权的视频版本。多媒体输入生成能力不冒充单视频处理。

功能绑定通过独立设置 CAS 保存；运行还核对已展示的能力版本，冻结完整输入契约、目标、能力版本、来源版本和参数后复用现有上传、提交、查询、归档、用量及 UNKNOWN 语义。无时长来源字段的工作流保留未知时长与按秒未知费用，不用零秒伪造估算。此绑定不开放任意 ComfyUI 工作流、URL、HTTP 模板或第三方脚本。具体工作流的 AI 超分语义由管理员核验，不因输出类型为 VIDEO 就声称模型效果已经验证。

## 2026-10-04 图片功能绑定

图片后处理可绑定匹配 IMAGE 主输出且仅有一个无条件 IMAGE 媒体字段的已发布契约。应用固定选用的来源版本，表单不能替换来源；普通参数只按白名单字段读取，操作指令由服务端填入 PROMPT，完整契约及能力版本冻结到原任务。透明输出工具仅使用已声明透明支持的适配器；当前 RunningHub 契约没有该声明，不能仅凭工作流名称当作透明能力。幂等重放读取原任务并保留 UNKNOWN 显式重试边界，不接任意 HTTP 模板或工作流执行。
