# ADR 0074：账号角色库与固定项目角色节点

状态：接受，用户确认跨项目反复复用、文本/图片/可选声音、多造型和手动同步，要求开始实现且不考虑历史数据兼容。实现与验证进度见开发清单；不包含部署或真实数据重置授权。

## 决策

在现有项目角色档案之外增加账号级私有角色库。普通个人资产的 CHARACTER 用途分类继续表示一份素材，不能替代完整角色。账号角色拥有姓名、人设与外观文本、身份基准图、多造型和有用途的多视图图片、可选音频参考及指定音色；参考视频、造型参数化编辑、训练与跨团队共享不在第一版。

角色库媒体独立归档；本地上传、个人素材和项目精确版本先冻结来源，经可恢复命令存入账号私有空间。项目角色发布批量捕获固定版本，受理后只消费独立固定输入，来源项目或普通个人素材的后续变化不影响它。导入项目复制媒体字节，创建目标项目的独立 Asset/ArtifactVersion 和角色修订，不建立跨项目实时引用。库归档保留旧修订、媒体和已导入副本。

项目保存库来源锚点；库更新只提供新版本提示。用户先预览内容与受影响镜头，明确同步时再次验证库版本、项目角色 CAS 和预览摘要，异步完成媒体准备后在短事务中安装完整新修订。已有媒体草稿和 Task 保持原样，旧角色关联标记待复核。库和项目之间没有双向自动更新。

画布新增 CHARACTER 主体，引用同项目角色不可变修订，独立保存造型、有序参考图子集及外观/声音用途。它不是新的 Artifact.Kind。角色逻辑连接采用独立表，不冒充 sourceArtifactVersionId 或媒体输入连线；连接后仍须明确预览/应用，复用既有角色贡献追踪、媒体能力验证和任务冻结。删除节点只移除展示与逻辑关系；已应用输入按明确预览清理，历史任务和作品不被删除。复制固定配置，创建新节点身份，不复制连线。

普通参考图、视频首尾帧和供应商主体 ID 是不同的协议。只使用当前能力目录与适配器已经支持的路径，不虚构跨供应商主体 ID；首帧能力不被宣称为角色锁定。模型数量/模式/格式不支持时清楚拒绝，质量仍需用户复核。

## 工程后果

追加 V50/V51，生成对应 jOOQ 与 OpenAPI TypeScript。不改写历史 Flyway 文件，不为旧角色数据增加兼容分支。正式升级仍应先备份并按正常迁移流程执行；本次实现仅在空的专用 PostgreSQL 测试环境验证。

账号库和项目边界分别授权。固定媒体输入与私有文件元数据不进入导演/MCP的普通安全角色摘要。布局 CAS、节点选择 CAS、角色档案版本和目标草稿 CAS 分开；网络/文件操作不持有长数据库事务，幂等回执支持提交后响应丢失的显式核对。

详细范围见 [角色库设计](../CHARACTER-LIBRARY-DESIGN.md)。本决策扩展 [ADR 0055](0055-character-consistency-management.md)，保留其中的不可变修订、显式角色应用、复核与任务冻结约束。
