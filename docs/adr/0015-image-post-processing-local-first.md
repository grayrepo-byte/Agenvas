# ADR 0015：图片后处理本地优先

> 2026-09-30 修订：Compose server 镜像改为内置并校验 Depth Anything V2 Small INT8 权重；不再要求部署者手工安装模型。
> 2026-09-30 修订：三视图拆分为角色、脸部、道具和场景宫格四种冻结任务类型。
> 2026-09-30 修订：智能编辑加入可选显式蒙版与有序额外参考图；蒙版只交给声明支持该协议的 OpenAI 图片能力。

- 状态：Accepted
- 日期：2026-09-29
- 关联：[MVP-SPEC §6.9](../MVP-SPEC.md)、[ADR 0006](0006-direct-media-task-boundary.md)、[ADR 0014](0014-canvas-item-media-branches-and-versioned-image-inputs.md)

## 背景

画布图片卡片已有不可变版本、私有 Asset、持久媒体 Task、能力目录和 OpenAI/Google 参考图编辑，但工具栏中的图片后处理仍是占位。2026-09-29 的产品决定只做图片处理：能在自托管实例可靠完成的处理留在本地，必须依赖生成式图片模型的处理才发送到管理员配置的第三方能力。重新打光被明确归为 AI 图片能力，而不是普通亮度滤镜。去字幕属于视频范围，本轮排除。

> 2026-09-30 画笔标注改为用户直接绘制与保存，移出 AI Task 操作；该部分由 [ADR 0018](0018-local-brush-markup.md) 取代。

## 决定

1. 本地适配器 `LOCAL_IMAGE_PROCESSOR` 执行裁剪、90° 旋转、水平/垂直镜像和 2×/4× 双三次插值放大，不进行网络请求。它是不可由管理员修改或停用的操作专用能力，不出现在普通图片生成能力候选中，也不能被设为默认生成模型。
2. 深度提取在同一本地适配器中使用固定服务端路径的 Depth Anything V2 Small INT8 ONNX 和 ONNX Runtime CPU。只接受 Small 权重；该权重为 Apache-2.0，Base/Large/Giant 的非商业许可证不进入默认开源分发。Compose 的 server 镜像在构建期从固定提交下载 27.3 MB INT8 ONNX 与上游许可证，分别校验固定 SHA-256，并在镜像构建测试中执行一次真实推理；模型和许可证随后复制到不受数据卷遮挡的只读镜像路径，运行时不下载。`AGENVAS_DEPTH_MODEL` 只用于源码运行或显式替换受信任的兼容 Small 模型。模型缺失或不可读时仍在提交前以稳定原因码阻断，绝不输出伪深度图。
3. 智能编辑、重新打光、扩图、三视图、图层分离、表情调整、移除背景、局部擦除和视角调整只接受已启用且支持参考图的 `OPENAI_GPT_IMAGE_2` 或 `GOOGLE_NANO_BANANA_2` 能力。用户在操作面板中明确选择能力；图片和说明按现有固定适配器协议发送。智能编辑、重打光及普通编辑保持来源图片的最近支持画幅，扩图和三视图使用用户选择的目标画幅。智能编辑可按顺序追加同项目不可变图片版本；来源图始终是 Image 1，额外引用从 Image 2 起。用户可选择涂抹或框选局部区域，浏览器导出小于 4 MiB、带透明通道的 PNG 蒙版并作为私有 Asset 归档；服务端再次校验、冻结 Asset ID，再与第一张输入做同一 contain 变换后传给 Provider。显式蒙版只允许声明 `supportsImageMask=true` 的能力，当前只有固定 OpenAI 图片编辑协议；Google 仍可做提示词与参考图编辑，但不伪装成支持显式蒙版。重打光额外冻结预设风格、亮度、色温与归一化光源坐标；前端滤镜只做即时预览，最终效果始终由选定 AI 图片能力生成。
4. 本地与云端操作都创建持久 `IMAGE_GENERATION` Task。受理时从来源 CanvasItem 创建独立结果 CanvasItem，并保存一条固定来源 ArtifactVersion 的可删除 `MEDIA_DERIVATION` 关系；该关系仅表达结果来源，不进入媒体草稿。Task 绑定结果 CanvasItem、来源 ArtifactVersion、操作参数、能力版本与工作流摘要；结果归档为新 Asset 和不可变 ArtifactVersion，只固定到自己的结果 CanvasItem，来源 CanvasItem 始终保持原结果。晚到结果仅进入审计历史。通用派生与删除语义见 [ADR 0016](0016-media-nodes-are-single-results.md)。
5. 本地任务进入同一调用审计与用量账本，但费用来源为 `LOCAL_NO_COST`，金额为已知零且 `possibleExternalCost=false`。云端继续使用未知费用和 UNKNOWN 显式重试语义。
6. 七项扩展均按一次任务一个不可变图片结果实现。`THREE_VIEW` 必须冻结明确类型：角色输出同一角色等比例全身正面/精确侧面/背面，脸部输出同一头肩的正面/四分之三/精确侧脸，道具输出同一物体的正面/侧面/背面正投影，场景宫格输出同一空间的远景/反向/中景/关键细节 2×2 宫格；四类都要求跨视图身份、材质、色彩或空间连续。图层分离每次明确输出主体层或补全后的背景层，不把合成预览伪装成可编辑多层文件；表情调整只改目标表情；“画笔标注”仍表示让 AI 在结果图中画出可见标注，与智能编辑中仅作为输入约束、不会出现在结果里的透明蒙版严格区分；移除背景与主体层输出要求能力支持透明背景；局部擦除按文字描述移除目标并补全背景；视角调整使用明确的八种目标视角。参数、说明、额外引用、可选蒙版和能力版本全部冻结进 Task。

## 后果

2026-10-04 用户要求三视图创作提示词纳入统一提示词管理。四种输出各使用一个固定用途的内置 FUNCTION 条目：`image.three-view.character`、`image.three-view.face`、`image.three-view.prop`、`image.three-view.scene-grid`。管理员可编辑名称、说明和正文，不能删除或修改用途；V6 初始化四类英文正文，其中角色按用户后续要求使用正面半身大头照与全身站立三视图，16:9 纯白背景、影棚柔光、角色设定集风格、高分辨率和电影级质感，其余三类保留原正文。首次受理 Task schema 7 时读取当前条目，把最终正文及条目 key/version 冻结进任务；配置修改不影响在途执行、恢复或同键重放。三视图类型校验、目标画幅、来源版本、能力/权限和派生规则继续由程序执行，创作配置不能改变这些规则。其他图片后处理指令保持原消费方式，未注册的自定义功能提示词不会自动获得执行入口。

- 自托管 Compose 实例无需外部账户或额外安装即可执行确定性图片处理与深度提取；首次构建 server 镜像需要访问固定模型和许可证来源，之后运行时离线。
- 云端后处理复用现有密钥、端点约束、SSRF 防护、任务恢复和版本并发规则，不新增浏览器直连 Provider。
- OpenAI 官方接口把 mask 作为引导而非像素级硬约束；界面必须说明透明区域是编辑范围提示，不能承诺结果严格服从边缘。
- 每次图片后处理会立即增加一个结果节点和一条派生线；来源节点不再被后处理 Task 占用，可继续作为其他派生的起点。派生线可单独删除，删除不移除任一节点，也不改写为隐藏输入关系。
- 当前图层分离的业务结果仍是普通图片版本而非 PSD/分层工程文件；主体层与背景层需分别运行并从版本历史选用。
- 本地放大是可解释的像素插值，不声称为 AI 超分或细节重建；如未来引入本地超分模型，应发布独立能力版本并记录模型许可证与资源上限。
- ONNX 模型输入约定为单一 NCHW RGB 张量，输出为单通道相对深度；不符合约定的文件会失败，不动态加载自定义代码或插件。
- 实现期以固定提交的 8 位量化 ONNX 在 macOS arm64/ONNX Runtime 1.30.0 完成一次真实本地推理；该验证不等于不同硬件、图片类型或其他 ONNX 导出的兼容验收。


## 2026-10-04 视频处理扩展

用户确认视频节点增加深度提取、音频分离与 AI 视频高清，并要求管理员通过功能设置选择处理方式。扩展为视频操作专用的本地深度与音轨适配器，以及独立于生成默认模型的持久功能绑定。视频高清不提供插值替代，必须配置兼容 AI 能力；初始云端复用 RunningHub 已发布契约。ComfyUI 的现有图生视频模板不能作为视频后处理使用，其他服务仍需要受控的兼容实现。

本地深度复用已固定模型，限制 30 秒、200 MiB、3840×2160 输入像素数，输出不超过 518px 长边、12fps 的无音轨相对深度视频。音频提取第一音轨为双声道 48kHz PCM WAV，无音轨时阻断。固定 FFmpeg 参数、只读取已归档素材、有限执行时间与临时空间，不接受脚本或任意命令。深度模型缺失继续明确阻断。

视频结果创建同一 Artifact 下的独立节点；音频结果因为媒体类型改变而拥有新 AUDIO Artifact。两者都使用空白草稿、冻结来源版本和可删除派生线，来源结果不变。受理必须核对功能绑定版本与用户看到的能力版本，避免后台更新改变刚确认的工作流或费用。相同命令重放原任务，未知提交不自动重试。原图片放大与图片操作选择方式保持原规则。

## 2026-10-04 图片功能绑定修订

用户要求图片工具也可以在后台配置处理方式。本修订取代原“本地操作固定、云端在面板选模型”的选择规则：十五个图片生成任务操作拥有独立 IMAGE_ 功能绑定，六个本地操作初始保留既有处理，其余仅在迁移时沿用兼容默认模型，之后不随普通默认模型改变。管理员可停用新执行，内置本地能力本身仍不可修改。画笔标注继续直接绘制，不产生 AI Task。

裁剪/旋转/镜像只使用确定性本地适配器；图片放大和深度支持本地或 RunningHub 单图片工作流。生成式图片处理支持 OpenAI/Google 来源参考能力、ComfyUI 已有固定参考图片模板，或 RunningHub 单图片工作流；透明结果、额外参考、蒙版及画幅仍由已声明的协议能力约束。ComfyUI 固定参考编辑不等于超分、透明输出或蒙版编辑，不接任意工作流 JSON。RunningHub 的来源槽由应用固定，普通参数与完整契约冻结；放大倍率由实际工作流参数控制，本地插值倍率不会混入该任务输入。

受理要求功能设置与已展示能力版本，客户端不指定 capabilityId；未配置或冲突在创建派生节点前阻断。任务 schema 8 保存原请求以做严格幂等比较，重放优先读取原任务，不重新解析新绑定。前端不确定响应保持原键/请求，包括布局 CAS 后再次点击；设置改变只影响新命令。V8 迁移保留原 VIDEO_ 绑定，OpenAPI/生成客户端和 jOOQ 同步；旧客户端需更新，旧任务按冻结输入继续执行。
