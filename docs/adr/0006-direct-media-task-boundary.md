# ADR 0006：直接媒体任务不创建 AgentRun

状态：接受（2026-09-25）；2026-09-28 修订媒体并发策略。

## 背景

现有媒体计划、Task 和用量依赖 AgentRun，项目活动槽位也只指向 AgentRun；图片/视频 Artifact 的读路径假定已有当前媒体版本。直接点击卡片“运行”不需审批并可与其他卡片及 AgentRun 并行。若为每次直接点击创建 AgentRun 或共用唯一项目槽位，会混淆用户指令与 Agent 执行，且无法满足并行需求。

## 决策

- 图片/视频卡片创建时即创建稳定 Artifact；首次结果产生前允许当前媒体版本为空。工作草稿独立于 ArtifactVersion 持久化，有自己的版本和并发控制。卡片展示状态与当前选用结果分开。草稿不能作为可读媒体 Asset 或 Agent 媒体输入。
- 一次直接点击由持久 Task 承载，来源标记 `USER_DIRECT`；它固定草稿版本、能力版本、视频输入图片精确版本、目标 Artifact 和预期选用状态。直接任务不创建 AgentRun 或 ExecutionPlan。Agent 来源继续使用原有 Run、审批计划和 Task 路径。
- 同一卡片所有来源的未终结任务在数据库中互斥，排队及 UNKNOWN 也占用卡片。重复点击幂等返回原任务；UNKNOWN 的重试由用户显式发起。
- 媒体 Task 不设置项目级、能力级或适配器级产品并发上限；ComfyUI 不再有全局单槽门禁。READY Task 只在有界 Worker 尚不可用时持久等待，并由数据库短事务、租约、fencing epoch 与 `SKIP LOCKED` 保证跨 Worker 认领正确性。进程内执行器必须有资源上限，但该实现上限不是面向用户的容量额度。Task 的排队、受理、取消、用量预留/释放与结果归档继续沿用持久账本和 fencing 规则。

实施约束：同一卡片的排队、运行或未被替代的 UNKNOWN 任务仍互斥；用户为 UNKNOWN 显式创建的新尝试会替代该卡片上的原任务。UNKNOWN 不占任何跨卡片共享名额，因为这类共享名额已移除。原“拒绝为 UNKNOWN 创建新尝试、要求先核对原请求”的约束已于 2026-09-26 移除，见 [ADR 0005](0005-canvas-interaction-redesign.md)。能力目录尚无已知价格，直接任务当前按未知金额记录；引入价格配置后须按本决策补齐金额预留。

## 取舍与影响

曾考虑“草稿先有独立业务身份，首次生成后再转换为 Artifact”和“为每次直接点击创建通用 ProjectRun”。前者需要重绑画布主体并改变卡片身份；后者在一请求一 Task 的直接路径上增加运行实体和大范围迁移，却不提供额外的并行控制。本决策保留 AgentRun 的原有语义，让 Task 承载直接请求。2026-09-28 又撤回了项目三个、能力可配置和 ComfyUI 单槽三层共享容量门禁：它们增加设置、排队原因和 UNKNOWN 占位语义，却没有形成有效的产品价值。代价是系统不再替管理员执行 Provider 配额管理，部署者须通过 Provider 自身策略和进程资源配置控制负载；本机仍必须使用有界执行器。空版本、竞争认领、重复点击、UNKNOWN、跨卡片并行和旧结果归档均须以真实 PostgreSQL 验证。

## 2026-10-05 结果取回失败后的重试

已受理但 BLOCKED 的直连媒体任务也允许用户显式创建独立新尝试，沿用 UNKNOWN 的幂等键、expectedVersion、替代关联与独立用量预留规则。原请求 ID、任务与费用记录保留；被替代后不再占用卡片，不能因旧任务没有恢复入口而永久锁住生成。未受理阻断不占卡片，可修改草稿后运行。此决定不自动重新生成，也不取消权限、固定输入或配置的校验；详见 ADR 0025 的结果选择与新尝试修订。
