# ADR 0006：直接媒体任务不创建 AgentRun

状态：接受（2026-09-25）；领域边界已确认，具体表/API 迁移待实施设计。

## 背景

现有媒体计划、Task 和用量依赖 AgentRun，项目活动槽位也只指向 AgentRun；图片/视频 Artifact 的读路径假定已有当前媒体版本。直接点击卡片“运行”不需审批并可与其他卡片及 AgentRun 并行。若为每次直接点击创建 AgentRun 或共用唯一项目槽位，会混淆用户指令与 Agent 执行，且无法满足并行需求。

## 决策

- 图片/视频卡片创建时即创建稳定 Artifact；首次结果产生前允许当前媒体版本为空。工作草稿独立于 ArtifactVersion 持久化，有自己的版本和并发控制。卡片展示状态与当前选用结果分开。草稿不能作为可读媒体 Asset 或 Agent 媒体输入。
- 一次直接点击由持久 Task 承载，来源标记 `USER_DIRECT`；它固定草稿版本、能力版本、视频输入图片精确版本、目标 Artifact 和预期选用状态。直接任务不创建 AgentRun 或 ExecutionPlan。Agent 来源继续使用原有 Run、审批计划和 Task 路径。
- 同一卡片所有来源的未终结任务在数据库中互斥，排队及 UNKNOWN 也占用卡片。重复点击幂等返回原任务；UNKNOWN 的重试由用户显式发起。
- 项目与能力并发上限在数据库认领路径执行，跨 Worker 生效；调度器单轮认领数不是容量保证。ComfyUI 的全局单槽门禁继续叠加适用。Task 的排队、受理、取消、用量预留/释放与结果归档沿用持久账本和 fencing 规则。

实施约束：ComfyUI 原请求仍为 UNKNOWN 时，全局单槽持续占用；用户为该任务发起重试后，原任务被替代并让出单槽，替代任务随即可以派发。（2026-09-26 修订：原“拒绝为 UNKNOWN 创建新尝试、要求先核对原请求”的约束已随核对能力一并移除，见 [ADR 0005](0005-canvas-interaction-redesign.md) 的 UNKNOWN 重试简化。）能力目录尚无已知价格，直接任务当前按未知金额记录；引入价格配置后须按本决策补齐金额预留。

## 取舍与影响

曾考虑“草稿先有独立业务身份，首次生成后再转换为 Artifact”和“为每次直接点击创建通用 ProjectRun”。前者需要重绑画布主体并改变卡片身份；后者在一请求一 Task 的直接路径上增加运行实体和大范围迁移，却不提供额外的并行控制。本决策保留 AgentRun 的原有语义，让 Task 承载直接请求。代价是现有非空版本投影、Task/用量的 AgentRun 约束、媒体目标绑定和资源查询均须显式扩展，并以真实 PostgreSQL 验证空版本、并发认领、重复点击、UNKNOWN 和旧结果归档。
