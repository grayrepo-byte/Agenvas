# ADR 0077：文本节点作为公共提示词输入

状态：接受。

## 背景

文字节点已有可编辑、版本化的正文，但原画布只允许媒体输入连线。用户希望把共同的风格、场景或角色说明写在一个文本节点中，连接到多个生成节点，与每个目标自己的局部提示词合并使用。

## 决策

新增 `PROMPT_INPUT`，从同项目的文字 CanvasItem 连到图片、视频或音频 CanvasItem；工作流仍须声明活动的主提示词输入。复用现有右侧出口、卡片落点、服务器持久化连线及删除操作，不增加执行依赖，不触发自动生成。文字生成节点暂不作为目标。

建连时用 `sourceVersionId` 核对文字节点当前已保存正文版本，沿用 `sourceArtifactVersionId` 保存建连审计版本。与固定版本的 `MEDIA_INPUT` 不同，公共提示词在预检与生成受理时读取来源节点当时已保存的正文；未保存的编辑不参与。来源正文的新版本只影响后续运行。现有图片、视频、音频引用及标签的精确版本语义不变。

多个来源按连线 `createdAt`、UUID 字符串升序排列；浏览器保留服务端时间的小数精度。每段正文去首尾空白，忽略空白段，再接目标局部提示词，以空行分隔。工作流局部提示词为空时先使用已发布的默认提示词，再执行合并；所选风格最后追加。合并后的值重新接受能力的必填、条件字段及长度校验；没有活动主提示词的能力明确拒绝，不静默丢弃公共文本。

公共输入不占媒体槽位，不修改目标 `MediaDraft.prompt`、mentions 或参考素材。编辑器在顶部“模板”旁提供“公共提示词”标签入口，点击后展示只读的有序来源及合并预览；输入区不再单独占一行，局部编辑栏继续单独编辑；来源读取失败保留草稿并提供重试。断线或删除来源节点仅解除对应公共输入，其他公共来源、局部正文和媒体引用继续保留；刷新与 SSE 恢复按已保存的拓扑和正文重新投影。

预检哈希包含来源身份、精确正文版本与正文。受理后的 Task 和结果 `frozenInput.promptInputs` 保留同一份有序快照；`prompt` 保留局部结构化正文，`userRenderedPrompt` 保存合并后的用户输入，`renderedPrompt` 保存追加风格后的实际输入。Worker、排队恢复和相同幂等键重放不重新读取来源。文字是创作数据，不能授予权限或绕过既有媒体审批。

显式“复用历史输入”属于完整替换：把冻结的公共正文和局部提示词物化为当前可编辑提示词，并在同一事务移除目标当前的公共提示词连线，避免重复拼接或跟随已变化的来源。普通保存、切换结果版本和正常运行均不这样物化。节点复制继续沿用不继承拓扑的规则，公共提示词连线需明确重建。

## 实现与升级

沿用现有连接表；V55 仅扩展关系类型检查约束并更新注释，不改写旧连线或媒体内容。按一次性 PostgreSQL 重新生成 jOOQ，OpenAPI 同步新增枚举、快照类型及生成 TypeScript。新快照为既有媒体输入结构的附加字段，旧任务仍可恢复。

前后端应一同升级；旧服务端无法解析新增关系类型，回退须先评估包含公共提示词连线的项目。无依赖升级，无远程服务或付费 Provider 前提。

## 验证范围

定向 PostgreSQL、Mock 归档、前端交互与合成浏览器验收记录在开发清单。Mock 与假响应只能证明本地组合、冻结和请求路径，不能证明真实模型已接通或理解公共提示词的质量。
