# ADR 0019：媒体能力的默认参数、输入限制与估算价格

- 状态：接受
- 日期：2026-09-30
- 依据：用户要求补齐能力发布中的模型选项、API 地址、默认生成参数、价格、视频时长和参考图限制。

## 决策

固定适配器继续定义协议、支持的参数集合和硬上限。管理员可以为每个发布能力配置默认生成参数、在固定协议范围内收紧视频时长与参考图数量，并设置估算单价。配置保存于既有 `media_capability_version.spec_json.settings`，修改仍采用 CAS、不可变版本、映射摘要及幂等发布。

图片默认参数包括画幅、分辨率、画质、透明背景与生成数量；只接受当前适配器支持的参数。视频默认参数包括画幅及默认整数秒时长；默认时长必须处于配置后的时长区间。草稿明确保存的字段优先，未填写字段使用所选能力的默认值。已有草稿不被后台配置主动改写或裁剪；超出新限制时用户需要调整，服务端拒绝运行。受理任务固定有效参数、能力版本和价格。

估算价格由十进制字符串金额、CNY/USD 币种及计价单位组成。图片按张计价；视频可按个或按秒计价；最多六位小数。每个批量图片任务分别预留一张费用，界面展示整个批次的估算。价格缺失保留未知，显式零与未知区分。任务快照的 `mediaPricing` 供预留、结算及取消释放账本使用，`costStatus=ESTIMATED`、`costSource=ADMIN_CONFIGURED`，实际费用没有供应商报告时仍为空。它不代表供应商账单、自动扣款或花费封顶。本地处理继续为已知零。

沿用 ADR 0008：OpenAI 与 Google 可编辑协议兼容模型名称及 API 根地址；模型为空时使用内置默认。Google 平台和适配器在界面明确标注 Nano Banana 2。Seedance 仍使用已有固定模型、API 路径与结果下载约束，设置页明确展示只读模型和地址，不声称支持任意视频协议。

## 数据与升级

OpenAPI 增加 `model`（修正已有实现遗漏）、默认参数、限制和 `MediaCapabilityPricing`，同步生成 TypeScript。既有 JSON 行无需迁移，也没有 jOOQ 生成变更。未配置新增字段的历史能力保留编译上限、既有默认参数和未知价格；旧任务没有 `mediaPricing` 时账本继续保持未知。价格不进入任何凭证或 API Key 字段。

## OpenAI 图片 Token 估算（2026-11-04）

用户要求支持 OpenAI 图片按 Token 计费。`OPENAI_GPT_IMAGE_2` 沿用当前 Images API 的生成、multipart 编辑和 URL 编辑接口，管理员可选择既有按张 `pricing` 或新增 `tokenPricing`，两者互斥。Token 价格分别配置文本输入、图片输入、图片输出的每百万 Token 单价及 CNY/USD 币种，缓存文本/图片输入费率可选。沿用六位小数十进制字符串。按用户追加要求，新建且未定价的官方端点能力默认填入已核验的官方标准美元费率，已有配置不自动改价。显式切换到 Token 模式也可预填；人工修改及已保存的费率在模型切换时保留，当前编辑会话尚未修改的自动预设随精确模型更新，切为未知模型则清空自动费率。其他媒体协议暂不开放 Token 价格。

受理及 Agent 审批摘要固定 `mediaTokenPricing`，审批哈希包含该快照；已发出的请求不受之后修改价格影响。预留时 Token 数量和估算金额未知，不按字符、图片张数或分辨率伪造 Token。成功生成或取消后的晚到结果，在现有租约/fencing 事务内与不可变产物、任务结果和唯一结算账目一起保存真实用量。生成请求不自动重发；重复结算复用原 operationKey。确认未提交的失败继续释放预留，UNKNOWN 保留预留；取消不等于免费。

Images API 的 `input_tokens`、`input_tokens_details.text_tokens/image_tokens`、`output_tokens` 以及可用的总计/输出明细只保留非负且可表示为 int 的计数。不保存响应中的任意元数据。兼容网关额外提供的 `input_tokens_details.cached_tokens` 和 `cached_tokens_details.text_tokens/image_tokens` 可用于缓存核算，这些扩展不是官方 Images API 的必返字段。缓存命中从对应普通输入数量中扣除，避免重复计价。未报告缓存数量保留 null，金额只能按普通输入费率估算；明确报告正缓存量却无法按模态分配、缺少适用缓存费率、用量缺失/非法/总计矛盾、存在未支持的文本输出 Token，或金额超出既有 numeric(18,6) 时，金额保持 UNKNOWN，不妨碍归档结果。整笔费用相加后统一舍入到六位小数。

有可计算金额时仍为 `ESTIMATED/ADMIN_CONFIGURED`，`actualCost` 保持 null，实际扣费以供应商账单为准。配置、任务、晚到结果和用量使用既有 JSONB，无 SQL 迁移或 jOOQ 变化；不改写历史能力、任务或账目，不自动切换既有按张配置。设置页、画布运行提示和审批卡说明生成后按用量估算；未返回 usage 的兼容网关仍能生成，但费用未知。未扩展 Responses API 的主模型或 image_gen 工具计费。

预设仅匹配默认官方连接或精确 `https://api.openai.com/v1[/]`，以及 `gpt-image-2` / `gpt-image-2-2026-04-21`、`gpt-image-2.5-sunburst` / `gpt-image-2.5-sunburst-2026-09-08`、`gpt-image-2.5-flare` / `gpt-image-2.5-flare-2026-09-08`。2026-11-04 核验的标准处理美元/百万 Token 费率分别为文本输入 5、图片输入 8、图片输出 30；不是 Batch 价格。来源与核验日期显示在编辑器。官方说明 GPT Image 2/2.5 的缓存折扣只适用 Responses 图片工具，不适用直接 Images API，因此预设不填缓存折扣。缓存自定义字段只为明确返回明细的兼容网关保留；未知模型、代理和其他路径不猜价、不使用官方预设。旧模型页面的历史价格不据此推定当前可用性。预设的编辑来源标记仅保留在前端草稿，不写入 API。

依据：[OpenAI Images API](https://developers.openai.com/api/reference/resources/images/methods/generate)、[图片生成指南](https://developers.openai.com/api/docs/guides/image-generation)、[定价](https://developers.openai.com/api/docs/pricing)。本轮以本机合成 HTTP、真实 PostgreSQL 和前端定向回归验证；没有真实服务商付费调用。

## 验证

见 媒体能力配置证据（开发记录不随源码公开）。本轮没有真实云端付费调用；Mock 与假 HTTP 结果不证明真实供应商支持、效果或计费。

## 2026-10-02 扩展

AutoDL 支持同一工作流发布多个分辨率及逐档位估算价格；匹配档位优先、统一价格兜底、缺失保持未知。历史任务仍使用受理时的价格快照。其他固定视频协议未开放分辨率选择；具体规则与升级影响见 [ADR 0024 的后续决定](0024-autodl-comfyui-workflows.md#2026-10-02一个能力发布多个分辨率)。

## 设置页分区（2026-10-07）

按用户决定，`/settings/media` 的连接表与已发布能力表分别放入“媒体连接”和“已发布能力”两个页签，默认显示媒体连接，每次只显示一个面板。复用现有 shadcn/Radix Tabs，两个面板保持挂载，切换时保留连接与能力各行的未保存草稿、版本基线及保存反馈；能力发布仍从连接行进入。设置页摘要、模态表单、CAS 与权限规则沿用现有行为，无 API、依赖或数据库迁移。


## 设置页任务流重构（2026-10-21）

用户要求完整重构设置体验。连接与能力页签继续隔离管理任务；能力目录补充“选择连接后发布”入口，避免回到连接列表寻找发布动作。搜索和状态筛选仅隐藏目录行，保留每个编辑会话的草稿与 CAS 基线。普通能力把四个配置分区排为编号侧栏，手机转横向导航；保留原生校验并在错误出现时打开对应分区。

RunningHub 的长映射表改为按节点分组的响应式字段卡片，目标、输入、输出及预览分别作为可定位分区。连续分区保留挂载与浏览器原生校验；相较隐藏式向导，可在检查输出时随时核对输入，并为复杂技术映射提供独立高级区域。节点选择及字段暴露仍定义发布范围，不将它们降为临时显示筛选。自动发现期间禁止提交旧契约，仍允许填写能力名；显式采用服务器新版本时重建本地 JSON 与校验状态。

存储连接表单从常驻侧栏改为就地编辑模态，归档和中继用途独立于连接目录。LLM 配置与验证、系统分类、功能绑定及只读日志沿用相同层级和反馈。代价是多一次显式打开编辑窗口；收益是浏览配置时不需要同时处理凭证和用途表单。关闭清空临时密钥，保留实际修改的非密钥草稿；未经修改的编辑窗口重新打开采用当前版本。沿用现有业务接口、版本、幂等、权限及费用确认，不增加新执行或生成行为。

## 媒体管理信息层级重构（2026-11-03）

用户要求全面重构不直观的媒体管理页。页面首先展示图片、视频、音频的画布默认能力卡片，明确当前选择、缺失或不可用状态，并提供选择默认能力的入口。默认选择只列出已启用连接中的可用能力，以既有默认设置的版本提交；失败保留当前选择并显示错误，不自动替换不可用能力，已有草稿继续保留原选择。

目录默认展示已发布能力，并以独立页签管理服务连接；这一决定替代 2026-10-07 的“默认显示媒体连接”。页面通过“接入服务 → 发布能力 → 用于创作”解释连接、能力与画布的关系。能力目录增加类型过滤，结合关键词与启停状态定位条目。桌面目录采用约 48–56px 高的紧凑单行：能力表将能力名称、所属服务、模型、类型、输入范围、价格、状态及操作分为八列，服务连接表将连接名、平台、能力数、服务地址、凭证、状态及操作分为七列；长内容截断并通过 title 保留完整查看入口，手机保留卡片布局。编辑保持直接入口，启停、删除等次要操作收纳到独立操作列的更多菜单，删除仍需单独确认。代价是次要操作多一次展开，收益是目录浏览时更容易识别能力、来源与当前状态。

两类目录及编辑会话继续保持挂载，筛选只改变可见性，保留未保存草稿、CAS 基线及反馈。连接凭证、能力发布、默认选择和删除继续复用原有业务接口与版本规则，不增加 Provider 调用、依赖或数据库迁移；估算价格仍不代表实际账单。
