# ADR 0016：媒体节点固定单一结果，首次填充原节点，后续变更派生新节点

状态：由 [ADR 0017](0017-operation-specific-media-versioning.md) 取代（2026-09-30）；以下保留历史决定。图片和视频 CanvasItem 不再提供多版本选择。空媒体节点的第一次直接生成或图片上传把结果固定到当前节点，因为这是填充该节点的首个结果，不是修改既有不可变内容；一旦节点已有固定结果，后续生成、上传或后处理都不能覆盖它，而是先创建具备同类完整能力的结果 CanvasItem，任务只把新结果固定到该节点。底层 ArtifactVersion 继续作为不可变审计、任务恢复和精确输入引用记录，但不再是媒体节点上的版本管理界面。

媒体派生关系仅提示“这个结果从哪个节点发起”，不进入草稿或执行依赖，并允许用户删除。已有结果的来源节点再次运行时，新节点和 `MEDIA_DERIVATION` 必须在任务受理的同一事务中创建，使排队和生成期间就能看到派生线；删除后两个节点没有特殊关系，用户之后从图片来源重新连向结果节点时创建普通 `MEDIA_INPUT` 参考关系，而不是恢复派生关系。空媒体节点批量生成时，第一个输出使用当前节点，其余输出仍使用独立节点；由于受理时没有可追溯的来源版本，这些额外节点不伪造派生线。

这一决定用更多画布节点换取稳定引用和更简单的心智模型：已有引用永远指向不会原位变化的节点结果，分支在画布上直接可见；代价是 Artifact 仍需在后台保留不可变记录，且需要自动放置与节点整理能力。
