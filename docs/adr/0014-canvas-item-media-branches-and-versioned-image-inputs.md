# ADR 0014：CanvasItem 独立媒体分支与版本化多图输入

状态：媒体操作和节点历史按 [ADR 0017](0017-operation-specific-media-versioning.md) 修订；CanvasItem 草稿归属及精确输入引用继续有效。本决策替代 [ADR 0005](0005-canvas-interaction-redesign.md) 中 Artifact 级媒体草稿、图片仅文生图、视频单图输入及移除卡片不影响关系的决定，并替代 [ADR 0013](0013-contract-to-direct-generation.md) 中保留 `keyframeVersionId` 的决定。

## 背景

同一 Artifact 可以被多次放置到画布；如果媒体草稿和当前选用版本仍属于 Artifact，B1 与 B2 会互相覆盖工作状态，连线也无法判断目标是哪张卡片。单个 `referenceImageVersionId` / `keyframeVersionId` 又无法表达图片多参考、视频首尾帧、有序全能参考和纯文本视频。用户同时要求图片引用精确固定不可变版本、来源可叠加与独立移除、提示词可用结构化 `@图片` 标签，并让 Agent 通过另一种持久关系读取归档图片。

## 决策

1. **Artifact 共享身份，CanvasItem 独占工作上下文。** Artifact 只持有共享身份、分支版本历史和资源默认版本。每个媒体 CanvasItem 独立保存当前展示版本、媒体草稿、图片输入、来源和颜色分配；从资源库放置会从资源默认版本开始一个空草稿。复制 CanvasItem 前先保存完整草稿，成功后复制当前展示版本、提示词、参数、图片输入和颜色，输入改为手动来源；不复制任务或画布连线。

2. **版本历史是不可变分支图。** 新媒体结果追加到共享 Artifact 历史，并用 `baseVersionId` 指向发起运行的 CanvasItem 当时展示的父版本。成功结果只可能自动选用到发起运行的 CanvasItem，不修改其他 CanvasItem 或资源默认版本；资源默认版本只能在资源库中显式修改。切换历史结果不改写草稿；“使用此版本的输入”是独立的完整替换操作，不自动重建连线。

3. **图片输入由引用和来源分层表达。** 目标按精确 `ArtifactVersion` 去重并保存有序引用；一个引用可同时拥有手动来源和多条 CanvasItem 连线来源。添加入口在悬停、聚焦或点击时展示设备、资源库、画布和绘制四种来源；设备、资源库与画布选择形成手动来源，画布选择只列其他 CanvasItem 当前选用的已归档图片版本并按 `canvasItemId` 排除目标自身，同一 Artifact 的其他卡片不排除。P0 不提供绘制/涂抹能力，绘制入口明确禁用并标注暂未接入。连线以 `sourceCanvasItemId → targetCanvasItemId` 为端点并固定建立时的来源版本，不触发生成；按 CanvasItem 有向图拒绝直接或间接环。删除一种来源不影响其他来源，最后来源消失才删除引用及其标签。用户在草稿缩略图上点击关闭是“取消引入该图片”的明确即时命令，不再追加确认；服务端以草稿 CAS 原子删除该精确版本的全部来源、相关连线和全部结构化标签，任一冲突整体回滚。模式转换、移除来源卡片等其他跨目标或批量清理仍先展示影响并确认。

4. **媒体能力按输入模式声明限制。** 图片能力声明 `maxReferenceImages`；领域与能力合约支持有序多图，但适配器只有完成协议实现和测试后才能声明大于 1。当前 OpenAI GPT Image 2 上限为 4，使用重复的 `image[]` multipart 字段；Google Nano Banana 2 上限为 14，使用有序 `inlineData` parts；两者都从 Task 冻结快照读取全部引用并在网络前检查数量、单图与总大小。ComfyUI 图片适配器仍为 1。视频能力分别声明纯文本、首尾帧和全能参考模式及默认模式：无图片时草稿默认纯文本，有第一张图片时优先切换到能力支持的全能参考，否则使用其支持的图片模式；首尾帧模式独立声明是否支持尾帧，全能参考模式独立声明最大图片数，纯文本模式不接受图片。2026-10-03 修订：能力支持的图片输入模式在空素材时也可选择并保存；缺少运行所需素材只阻止运行，不阻止准备草稿。用户明确选择的模式在编辑和重新读取时保留，未指定模式的空草稿仍默认纯文本。能力或模型切换保留兼容参数；所有模式转换、参数重置和超额图片清理先显示影响并原子提交。后台能力更新不会静默裁剪旧草稿，只会把它标记为暂不可运行。

5. **提示词标签是结构化引用。** `@` 菜单只列出当前草稿已经添加的图片。标签固定图片版本身份，显示名随目标内顺序或视频角色呈现为 `Image N`、`Start Frame`、`End Frame`；标签带缩略图和稳定颜色，排序只改显示编号。删除文字中的单个标签不删除图片输入，删除图片输入会清除指向它的全部标签。运行时按结构化顺序稳定渲染提示词，并以相同顺序和角色提交图片。

6. **Task 与结果保存同一份冻结媒体输入。** 直接运行固定能力版本、父版本、提示词、参数、输入模式、精确图片版本顺序/角色和结构化标签。成功 ArtifactVersion 保存同一份只读来源快照；主编辑器只展示 CanvasItem 的“本次输入”，历史来源只在版本或任务详情中查看。删除旧的单图字段，不做双写。

7. **Agent 图片输入是独立关系。** 图片 CanvasItem 连向 Agent CanvasItem 时建立固定图片版本的 Agent 输入绑定，不进入媒体草稿、不提供 `@` 菜单，也不触发生成。一个 AgentInstance 最多有一个 CanvasItem。相同图片版本来自多张卡片时保留全部当前标题作为别名，但每轮只发送一次归档图片字节；模型配置仍限制最大图片数、单图大小与总大小。卡片移除只影响未来回合，已受理 AgentRun 继续使用冻结输入。

8. **本地开发数据直接清空。** 不迁移旧 Artifact 级草稿、当前版本或单图字段；清除项目、Artifact、版本、CanvasItem、草稿、连线、任务、Run、事件及相关用量，保留管理员账号、加密密钥和 Provider/模型设置。项目导出清单改为包含 CanvasItem 当前展示版本、独立草稿、图片引用及来源、颜色、连线、Artifact 版本图和资源默认版本。

9. **媒体原子参数和图片批次输出由任务内核负责。** 图片草稿结构化保存比例、分辨率、画质、透明背景、生成数量和是否新建节点；视频草稿结构化保存 `AUTO / 16:9 / 9:16 / 1:1` 比例，其中 `AUTO` 跟随项目画幅。参数在 Task 与结果来源中冻结，适配器必须读取冻结值而不是运行时项目新值。图片能力目录声明前四项实际支持范围，切换能力造成回退时必须确认。一次图片运行按数量创建 1、2 或 4 个独立 Task，每个 Task 单独计费、恢复和归档。关闭新节点输出时，结果进入同一 Artifact 历史且只有首个满足 CAS 的结果自动选用来源卡片；开启时，受理事务先为每个 Task 复制一个 CanvasItem 工作分支，任务只向各自目标自动选用，来源卡片不被任务占用。Provider 的单次多图返回能力不改变这一持久化边界。

## 后果

- 媒体草稿、运行、版本选择、复制、删除和连线 API 必须以 CanvasItem 为工作上下文，不能再通过 Artifact 反推唯一卡片。
- OpenAPI、数据库、jOOQ 生成代码、前端生成类型、Task 输入和所有媒体适配器都需要同步；未升级适配器继续限制为单图，不能静默丢弃额外图片。2026-09-28 的 OpenAI/Google 多参考升级复用已有合约和表结构，不新增 Flyway 迁移或生成类型。
- 同一 Artifact 的多个 CanvasItem 可以并行运行并产生分支版本；同一卡片的未终结媒体任务仍互斥。自动选用只比较有序图片版本、视频模式和首尾角色，来源数量变化但最终 Provider 输入不变不算输入变化。
- 同卡片批次在关闭新节点输出时是一次受理产生的多个并行 Task，而不是允许用户绕过互斥重复提交；幂等重放返回批次主任务且不能追加兄弟任务。开启新节点输出时互斥目标是新分支，来源卡片可继续编辑和再次运行。
- 画布拓扑成为持久业务关系而非 Artifact 投影；删除卡片、断线、同步版本和切换模式需要服务端事务与 CAS，前端不能先假装成功。

## 输入模式与运行条件分离（2026-10-03）

用户反馈必须先连接图片才能切换全能参考不合理。菜单原来把缺少图片作为模式禁用条件，草稿同步又会把没有输入的手动选择改回 TEXT。现在允许先选择能力支持的 GENERAL_REFERENCE / START_END，再按模式添加图片或音频；空输入可以保存，自动参数补全、提示词编辑和重新读取不覆盖明确模式。模式提示说明可以先选择，再补齐运行素材。

未支持的模式继续禁用，START_END 首帧和 GENERAL_REFERENCE 媒体/视觉输入要求继续在运行前校验，不发出不完整生成请求。默认未设定模式时选择 TEXT、从 TEXT 加入第一条输入时选择支持的图片模式、显式移除最后一条输入时回 TEXT 的现有行为保留。服务端既有草稿保存已接受空输入，无后端、API、数据库或依赖变化。
