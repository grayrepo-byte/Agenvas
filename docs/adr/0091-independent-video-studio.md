# ADR 0091：独立视频工作台及私有生成作用域

状态：接受（2026-11-22）。

## 决策

`/video-studio` 不要求选择项目，不复用画布媒体草稿，也不创建 CanvasItem 或 Run。每位所有者最多持有一个 `VIDEO_STUDIO` 项目，与 `IMAGE_STUDIO` 和普通 `CANVAS` 分开。工作台内部作用域不出现在项目列表，不能通过项目管理、快照、画布或 Run 入口访问；认证所有者仍可通过已有的私有素材读取端点读取已归档的文件。

一次显式生成受理固定一份命令快照与一个视频 Task。同所有者和幂等键的重放核对原请求摘要；Task 与归档版本仍是状态和结果真相，不复制执行状态，也不把供应商额外结果拆成新任务。历史按 `(created_at, id)` 倒序分页，回填提示词和明确回填完整设置均不触发生成。

只允许已发布的 Mock 和火山方舟 Seedance 2.0 能力中的纯文本和首尾帧模式。首帧必填，尾帧仅在能力支持时可选；精确固定本工作台的静态图片版本，不接受外部素材 URL 或跨作用域引用。有效画幅在受理时固定，不读取画布默认值。复用现有媒体 Task 的异步提交、查询、归档及用量规则，通过 `executionSurface=VIDEO_STUDIO` 区分节点无关的入口；继续遵循 [ADR 0066](0066-preserve-provider-video-audio.md)，归档并播放供应商返回的原视频和音轨。恢复只查原请求或完成原结果归档，不重新生成。

## 迁移及取舍

合并基线后的 V68 不改写既有画布、图片批次、Task 或素材。视频工作台用部分唯一索引仲裁并发首次进入；生成账本用固定用途和复合项目外键同时约束项目的所有者及用途，再以 `(project_id, task_id)` 外键禁止跨作用域关联 Task。沿用已有存储和权限边界，不抽象通用工作区，也不把生图专用批次或清理规则迁到视频工作台。

按 [ADR 0012](0012-jooq-persistence.md) 在一次性 PostgreSQL 上迁移并生成 jOOQ，不改旧迁移。升级和必要的旧版本恢复参见[备份与恢复](../operations/backup-restore.md#恢复顺序)；优先前向修复，不删表或修改 Flyway history。设计及验收范围见 [OpenSpec](../../openspec/changes/add-video-studio/design.md)。
