# ADR 0056：持久分镜板与分镜制作台

状态：接受；实际实现与验证范围见开发清单。

用户要求根据 [Topview、LibTV 差距分析](../research/topview-libtv-gap-analysis-2026-10-23.md) 完成分镜制作台。文字分镜已经能描述完整创作流程，但无法直接选用每镜结果、集中查看生产状态，也不能可靠表达修改第 3 镜后哪些已付费结果需要复核。决定增加项目级持久分镜板，以稳定镜头身份组织创作和制作关联，沿用现有画布内容与媒体任务。

本决定**替代 ADR 0054 中「不新增镜头身份、镜号仅为文档标识」这一边界**。ADR 0054 的导演文字创作方法、普通 TEXT 成果、精确版本读取、Run 冻结指令与既有审批保持适用；已有文字成果不会自动解析为分镜板，已有自定义导演指令与历史 Run 也不自动改写。

每项目至多一张板，镜头持有独立 UUID、板内唯一镜号、有序位置、场次、标题、画面描述、逐字台词、估计秒数、可选 TEXT 来源精确版本及媒体参考精确版本。关键帧、视频、音频的制作关联分别固定 CanvasItem 和可选结果版本，成片同样引用既有视频节点及精确结果；它们不成为新 Artifact 类型，也不将分镜板变成可执行 DAG。关联或导入只保存制作意图，不自动修改节点草稿、创建生成任务或读取最新版本替换固定引用。

采用全板 `expectedVersion` CAS 与追加式完整修订，先保证中小型分镜的原子保存、恢复和可追溯性。相比逐镜独立写入，这会使不同镜头的并发编辑也发生板版本冲突；客户端保留草稿并让用户检查当前板，不能静默合并或覆盖。V36 新建当前修订指针和不可变 JSONB 修订表，历史修订禁止更新及删除；jOOQ 按隔离生成流程同步。现有项目投影为空零版，首次保存才创建板，无需转换旧 TEXT、媒体或 Task 数据。

镜头创作字段变化由服务端递增该镜头修订，保留关联和已选结果并标记待复核；其他镜头修订与结果不变。用户审看后明确核销待复核，不能把「任务成功」当作语义复核通过。镜头内容、顺序、制作选用变化使已关联成片待复核，保留原成片与历史来源。生产任务继续冻结受理时的实际媒体草稿，分镜修改不会改写进行中的任务或历史输入；固定镜头结果也不随节点切换选用版本自动更新。

制作台以独立全屏界面提供镜头编辑、重排、删除、显式 JSON 导入、引用与结果选择、媒体预览和画布定位，集中投影已有 Task 状态及与关联节点匹配的 Agent 审批批次。用户明确准备节点时可创建填有画面或台词的独立媒体草稿，重试保留动作身份；媒体参考用途与生成时长仍须按能力确认，估时和制作参考不能无条件成为模型输入。Agent 审批仍是原固定批次的整体批准或拒绝，界面不能只批准其中某镜或扩大原授权。用户批量生产按阶段预检各目标、估算费用及未知费用，明确确认后通过既有节点直接运行入口逐项受理；受理失败或 UNKNOWN 保留逐项状态，不自动重新生成。关联本身不授权模型调用。

板写入与 `storyboard.changed` 项目事件同事务提交，SSE 只发送身份与版本；正常事件、快照重取与断线恢复均使独立板查询重新获取当前状态。脱敏项目导出 schema v10 同时包含角色档案、角色关联与安全贡献记录、分镜板及修订历史，仍只是 JSON 描述与素材清单，不承诺可恢复工程包或整片编辑工程。角色档案与应用边界沿用 [ADR 0055](0055-character-consistency-management.md)；分镜功能不增加自由时间线、自动字幕或声音一致性保证。

合并 develop 时保留已占用 V35 的角色迁移，本项尚未发布的迁移由原 V35 顺延为 V36；ADR 编号同时顺延，已发布迁移不改写。两项独立开发时的 schema v9 项目导出在合并后统一为 v10，读取方须识别新版本。合并后的实际检查另列开发清单，合并前专项记录不能代替本轮验收。
