# ADR 0005：画布交互与直接媒体运行

状态：接受（2026-09-25）；2026-09-26 修订 Agent 卡片呈现；2026-09-27 修订画布连线与删除交互。产品与领域边界已确认，实施与验收状态见任务清单；技术持久化决定见 [ADR 0006](0006-direct-media-task-boundary.md)。

## 背景与理由

现有工作区把创建、上传、对齐和导出放在左栏，图片/视频生成只能从关联镜头的 Agent 计划进入。用户希望直接在画布上编辑和运行媒体卡片，同时保留 Agent 的受控审批。菜单沿用项目现有的七类业务对象，不把参考图中的音频和 3D 入口误当作已支持类型。

## 画布交互

- 移除左侧创建栏。空白画布双击或悬浮“+”打开同一创建菜单，包含文字、图片、视频、角色、场景、镜头、Agent。卡片放在触发位置对应的画布坐标；菜单避让视口边缘，支持键盘与 Esc 关闭。
- 项目工作区采用深色点状背景；缩放控件在右下角。最初改造范围仅限工作区；2026-09-26 用户追加要求将 Beautiful UI 黑色风格扩展到项目、登录、初始化与设置页，当前页面范围见 [规格 6.1](../MVP-SPEC.md#61-页面路由)。
- 单选 Artifact 时底部显示对应类型的编辑区；空选隐藏；多选显示批量操作。Agent 直接在卡片内提供对话、历史与设置；长期配置指令与本次任务输入分别保存、提交。
- 顶部“资源”打开可搜索抽屉，可找回已移除的草稿与产物并重新放置；上传和导出也从顶部进入。选中对象的版本与引用放右侧。Agent 审批、关键帧、失败与 UNKNOWN 跟随当次 Run 嵌入对话；对应 Agent 卡片不在画布时保留全局处理入口。

## Agent 对话呈现修订（2026-09-26）

本修订替代原决定中 Agent 使用底部通用编辑区、待办主要位于全局区域的呈现方式。用户希望直接在画布上的 Agent 卡片完成 AI 对话与接管操作，因此将本次指令、公开回复、动作与审批放到同一处；代价是卡片需要管理对话、历史、设置与可滚动消息区，同时必须保留卡片移除后的处理入口。

- Agent 卡片使用黑色聊天界面，顶部切换“对话 / 历史 / 设置”，底部填写并发送本次任务。发送先显示内嵌运行前确认，用户明确确认后才创建 AgentRun。连续记忆与会话边界按后续 [ADR 0010](0010-persistent-agent-conversations.md) 修正：同一持久会话包含多条消息，新建会话才开始新的记忆。
- 只呈现成功模型回合的公开 `assistantText`、已提交工具执行的服务端业务摘要和持久任务状态。模型协议消息、完整工具参数/结果和私有推理不进入聊天；没有公开回复时不编造文本。工具动作保留提交时的业务状态，并明确这是历史记录；待审批提案不表示媒体已生成，当前进度以任务与审批卡片为准。
- 计划审批、关键帧选择、阻断和 UNKNOWN 重试嵌入所属 Run。Beautiful UI 的消息、任务行与审批示例负责外观，不决定业务状态、审批或执行。
- 输入绑定、模型与系统提示词版本预检、计划 hash、逐步骤确认、CAS、同项目单活动 AgentRun 与取消边界保持原规则。Agent 卡片移除不删除或取消其 Run；全局保底入口仍能处理缺少画布卡片的待办。

## 调用记录入口修订（2026-09-26）

用户明确要求长期待核对调用不占据画布提示区。本修订将原来的全局 UNKNOWN 横幅及其账本处理入口移到 `/settings/calls` 调用日志页，并去掉画布上的日志入口：调用日志只从侧栏导航进入，进入后可按当前项目筛选。日志支持时间、响应耗时、Trace ID 等审计信息，历史缺失值不补造；仍保留原请求核对与显式风险确认的新尝试。真正待审计划和关键帧操作、Agent 对话中所属 Run 的状态保持可操作，没有待审计划时不绘制空审批横幅。此处只改变呈现与审计入口，不改变 UNKNOWN 的任务状态、配额占用、用量预留和重试语义。

## 调用日志只读修订（2026-09-26）

上一节把 UNKNOWN 处理入口迁入日志页的决定在同一天被推翻。日志里的“待核对”不是持久状态，而是查询时对写回失败调用行的投影：只要关联任务不处于运行中或提交中，历史记录就会一直显示该标签；而 LLM 调用记录没有关联任务 ID，展开后不存在任何可操作入口。因此 `/settings/calls` 改为纯只读审计，调用结果标签改为“未知”，不再承载 UNKNOWN 核对与显式风险的新尝试。恢复动作只在所属 Agent 对话和媒体卡片编辑区进行；代价是卡片移出画布期间没有全局 UNKNOWN 入口，这一点由用户明确接受。任务状态、配额占用、用量预留和重试语义不变。

## UNKNOWN 重试简化（2026-09-26）

上一节保留的“原请求核对”在同一天被进一步移除。核对器只有 ComfyUI 一个实现，云端适配器不保存候选 ID、核对按钮对它们从不出现；而 ComfyUI 是本地生成、成本≈电费，核对省下的重复生成费用可以忽略。同时确认 ComfyUI 单槽门禁本就只把“未被替代的 UNKNOWN”计入占用，因此删掉“必须先核对”的硬拒绝后，用户一次重试即可让原任务让出名额——这反而消除了原设计里“核对查不到证据就永久卡住”的死锁。现在 UNKNOWN 只显示“结果未知”和一个重试按钮，不再有提交账本、原请求核对或重复成本勾选。

## 画布连线与删除交互修订（2026-09-27）

用户连续确认了一组画布交互调整，替代本 ADR“画布交互”一节里的原始连线行为：

- **连接点只保留右侧，且只在卡片选中时显示**：未选中卡片、卡片左侧落点与 Agent 输出组锚点都不绘制，避免双向端口的方向歧义。左侧落点仍是受控落点——不可见也不接收指针，由距离判定成立，手势靠近时才浮现。
- **落点按卡片判定**：从右侧出口拖出后，指针落在卡片任意位置松手即可建立关系，不再要求对准左侧连接点；手势中指针所在的卡片显示高亮外圈（可建立为强调色、不可建立为红色），源卡片自身不作落点。贴近连接点的精确落点仍然保留。
- **双击空白画布只打开添加菜单**，不再缩放画布。
- **删除键**：选中卡片按 Delete 或退格移除卡片，选中关系线按 Delete 或退格删除对应绑定或引用；Agent 输出组线由输出组决定、必填场景引用只能替换，两者不可选中也不可删除。移除卡片不连带删除绑定与引用——Artifact 与内容版本仍在，关系依然有效。删除先写服务端，投影确认后画布才变化。
- **点空白、拖出选框、平移与缩放画布都取消选中**；应用自己发起的视口移动（例如“查看输出”后的适屏）不清除选中。按住 Cmd（macOS）或 Ctrl 点击卡片是追加选择，不覆盖已有选中；选中的唯一权威是应用状态，React Flow 的选中变更只作为增量输入。
- **关系线不再写文字说明**（“输入”“Agent 输出组”“素材引用 · 角色”）：关系类型只靠颜色与线型区分，绑定指向历史版本时蓝线改为虚线；引用角色与绑定版本从卡片详情与 Agent 配置读取。

代价：画布更安静、手势更宽容，但历史版本与引用角色不再直接写在线上，拖到卡片之外不再建立关系。实现与验收状态见 [连接点证据](../evidence/T07-canvas-connection-handles.md)、[键盘删除证据](../evidence/T07-canvas-keyboard-deletion.md) 与 [节点选中证据](../evidence/T07-node-selection-and-image-ratio.md) 的 2026-09-27 小节。

## 选择与手形工具修订（2026-09-27）

按用户确认，将选择和画布平移分为两个工具：默认选择工具，空白拖动框选，节点拖动仍移动未锁定卡片；短按空格切换并保持手形工具，长按则临时切换，松开或窗口失焦恢复此前工具。按住空格期间开始的指针手势始终是临时切换，即使快速释放也不保持手形。手形工具拖动只平移画布，不移动或缩放节点，也不发起框选和连接。右上角添加按钮旁提供工具菜单，允许持久选择手形工具；V 返回选择工具。文本编辑、输入法组合与组合快捷键不触发工具切换。

这项决定替代此前未区分工具的拖动交互。两种模式避免选择和画布平移争用手势；代价是用户需通过空格或工具菜单进入平移。用户发起平移/缩放仍按既有规则清除选择，程序化视口移动保持选择。

实现同时对齐节点点击容差和拖动阈值，避免微移既不触发点击也不启动拖动的空档。验收范围见节点选中证据，不以模式切换宣称所有偶发选择问题均已解决。

## 媒体卡片

- 创建图片/视频卡片时即有稳定 Artifact 身份。媒体草稿单独持久化并短延迟自动保存；失败时保留本地输入。图片本轮只做独立文生图，参考图编辑后续再做。视频可先保存不完整草稿，运行前必须填写时长并选择同项目已归档图片的精确版本。
- 卡片展示的当前结果与底部工作草稿是不同状态。用户选用旧结果时，卡片展示旧结果，底部默认继续打开保留的草稿；从草稿点“运行”后卡片切到草稿占位，旧结果仍在历史。运行失败、取消或被拒绝时显示草稿占位和原因，旧结果由用户显式选回。
- 生成结果追加同一 Artifact 的新版本，不覆盖旧媒体。成功后底部保留本次提示词与参数供下次修改。任务固定点击“运行”时的输入；之后修改草稿不改写已受理任务。晚到结果若已不符合当前选用预期，只入历史，不覆盖新草稿或用户选择。
- 移除卡片只移除画布展示。已受理任务继续运行，结果留在项目资源；取消任务须单独操作。

## 运行、审批与并行

- 用户直接点击图片/视频卡片“运行”即受理媒体 Task，不需要 Agent、镜头或额外审批。按钮旁预先显示所选能力及预计费用或“未知”；一次点击直接提交。Agent 提出的付费媒体计划仍须人工审批，普通内容编辑工具沿用原规则。
- 不同媒体卡片可并行，也可与一个 AgentRun 同时运行；同一卡片跨手动与 Agent 来源至多有一个排队、运行或 UNKNOWN 任务。重复点击返回原任务。UNKNOWN 须由用户显式重试。
- 默认每项目最多三个占用中的媒体任务；每种能力设管理员可配置的全局上限。超出上限时持久排队，界面显示前方待处理数量、排队原因及位置可能变化。UNKNOWN 同时占项目与能力名额。ComfyUI 本轮保留现有全局单槽限制，其他能力可按上限并行。
- 点击“运行”时预留任务次数额度；已知价格再预留估算金额，未知价格明确标记。排队任务取消且未提交到 Provider 时释放未消耗预留；UNKNOWN 不自动释放。取消不承诺外部停止或退款。

## 实施状态

媒体空产物、独立媒体草稿、直接 Task 和 Agent 对话呈现已进入代码；具体通过的检查和未完成项以 [任务清单](../DEVELOPMENT-CHECKLIST.md)为准。Agent 公开动作读接口复用现有工具执行账本；持久会话的新增表、运行关联和旧数据迁移由 [ADR 0010](0010-persistent-agent-conversations.md) 规定，OpenAPI、Java 与生成 TypeScript 随实现同步。浏览器交互与真实 Provider 支持须分别验收，不能由组件测试、Mock 或本地假服务替代。
