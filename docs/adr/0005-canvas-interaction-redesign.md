# ADR 0005：画布交互与直接媒体运行

状态：接受（2026-09-25）；产品与领域边界已确认，尚未实施。技术持久化决定见 [ADR 0006](0006-direct-media-task-boundary.md)。

## 背景与理由

现有工作区把创建、上传、对齐和导出放在左栏，图片/视频生成只能从关联镜头的 Agent 计划进入。用户希望直接在画布上编辑和运行媒体卡片，同时保留 Agent 的受控审批。菜单沿用项目现有的七类业务对象，不把参考图中的音频和 3D 入口误当作已支持类型。

## 画布交互

- 移除左侧创建栏。空白画布双击或悬浮“+”打开同一创建菜单，包含文字、图片、视频、角色、场景、镜头、Agent。卡片放在触发位置对应的画布坐标；菜单避让视口边缘，支持键盘与 Esc 关闭。
- 项目工作区采用深色点状背景；缩放控件在右下角。项目列表与设置页本轮不改主题。
- 单选时底部显示对应类型的编辑区；空选隐藏；多选显示批量操作。Agent 长期配置指令与本次运行指令分别保存、提交。
- 顶部“资源”打开可搜索抽屉，可找回已移除的草稿与产物并重新放置；上传和导出也从顶部进入。选中对象的版本与引用放右侧，审批、失败与 UNKNOWN 放底部抽屉。

## 媒体卡片

- 创建图片/视频卡片时即有稳定 Artifact 身份。媒体草稿单独持久化并短延迟自动保存；失败时保留本地输入。图片本轮只做独立文生图，参考图编辑后续再做。视频可先保存不完整草稿，运行前必须填写时长并选择同项目已归档图片的精确版本。
- 卡片展示的当前结果与底部工作草稿是不同状态。用户选用旧结果时，卡片展示旧结果，底部默认继续打开保留的草稿；从草稿点“运行”后卡片切到草稿占位，旧结果仍在历史。运行失败、取消或被拒绝时显示草稿占位和原因，旧结果由用户显式选回。
- 生成结果追加同一 Artifact 的新版本，不覆盖旧媒体。成功后底部保留本次提示词与参数供下次修改。任务固定点击“运行”时的输入；之后修改草稿不改写已受理任务。晚到结果若已不符合当前选用预期，只入历史，不覆盖新草稿或用户选择。
- 移除卡片只移除画布展示。已受理任务继续运行，结果留在项目资源；取消任务须单独操作。

## 运行、审批与并行

- 用户直接点击图片/视频卡片“运行”即受理媒体 Task，不需要 Agent、镜头或额外审批。按钮旁预先显示所选能力及预计费用或“未知”；一次点击直接提交。Agent 提出的付费媒体计划仍须人工审批，普通内容编辑工具沿用原规则。
- 不同媒体卡片可并行，也可与一个 AgentRun 同时运行；同一卡片跨手动与 Agent 来源至多有一个排队、运行或 UNKNOWN 任务。重复点击返回原任务。UNKNOWN 须先核对或走明确风险的新尝试流程。
- 默认每项目最多三个占用中的媒体任务；每种能力设管理员可配置的全局上限。超出上限时持久排队，界面显示前方待处理数量、排队原因及位置可能变化。UNKNOWN 同时占项目与能力名额。ComfyUI 本轮保留现有全局单槽限制，其他能力可按上限并行。
- 点击“运行”时预留任务次数额度；已知价格再预留估算金额，未知价格明确标记。排队任务取消且未提交到 Provider 时释放未消耗预留；UNKNOWN 不自动释放。取消不承诺外部停止或退款。

## 实施状态

现有代码尚不支持无媒体版本的图片/视频 Artifact、独立媒体草稿或无 AgentRun 的媒体 Task。实现需同步 OpenAPI、Flyway、Java、生成 TS、前端与 PostgreSQL/浏览器验收。真实 Provider 支持须单独实测，不能由 Mock 或本地假服务代替。
