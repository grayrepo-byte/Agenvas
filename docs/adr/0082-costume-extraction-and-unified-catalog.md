# ADR 0082：服装提取与统一参考目录的来源隔离

用户要求图片工具栏提供 OpenAI 服装提取，以固定参考图与提示词统一去人物穿搭的展示方式，结果可选入库；随后明确服装应共用同一个列表，来源只在后台区分，三方源删除不能影响自建服装。当前沿用单管理员模式，不扩展用户管理。

提取复用现有图片后处理、持久 Task、派生结果节点和 OpenAI 多图编辑。原图是第一张输入，随应用交付的合成展示样式是第二张；内置提示词明确样式图不提供服装内容。任务固定提示词版本及样式身份/摘要，已发布样式文件不可覆盖；恢复不得静默改用新文件。功能单独绑定支持两图及 2:3 输出的 OpenAI 能力，默认未配置，安装不调用外部模型。

服装浏览合并三方与自建条目后统一筛选、分页和应用。三方继续使用 Git 来源快照和可重建缓存，自建条目使用独立永久图片归档和保存命令；后台 `THIRD_PARTY` / `SELF_CREATED` 来源决定读写与清理范围，不产生两套用户视图。将自建图片写入三方快照或缓存会让清理波及用户主动保存内容，因此不采用；仅预填智能编辑也不足以固定提取入口和样式输入。

保存固定来源版本并用节点 CAS 验证，通过现有媒体应用服务复制图片；导入固定目录版本和独立归档元数据，再创建目标项目自己的图片版本。两者在文件 I/O 外使用短事务和稳定命令身份。自建元数据改动、删除和导入冲突提供当前条目读取以恢复版本，保留编辑草稿；已完成项目复制不因后续草稿应用失败而重复导入。

初版删除使用目录墓碑，保留已接受命令所需 pin 与字节；没有自动 GC。尚未完成的保存/重放仍要求来源项目活动，已发布自建条目则独立于来源项目存续。V57 初始化功能和内置提示词，V58 增加自建条目与保存命令表；OpenAPI、生成 TypeScript/jOOQ 和前后端同批升级。模型真实视觉质量与 Mock/合成 HTTP 的流程验证分别验收。

合并站点优先目录后，保留 Omilic 的默认来源选择和首次读取顺序，避免为显示自建素材而短暂打开全部旧来源。默认服装读取显式携带 `includeSelfCreated`，把独立自建条目与默认站点合并后统一筛选和分页；用户手动指定三方来源时仍只浏览该来源，选择全部时合并全部。来源及缓存操作的生命周期隔离保持不变。
