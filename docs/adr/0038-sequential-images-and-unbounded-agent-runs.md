# ADR 0038：逐张观察图片与无累计次数上限的 Agent Run

图片预览曾在整个 Run 累计，先读五张设定图再读四张关键帧会超过八张的请求资源限制。用户确认应逐张读取并做好上下文，同时取消模型回合与累计工具执行次数上限。新 Run 固定策略 6 / 提示词 10 / 工具策略 3，`maxModelTurns` 和 `maxToolExecutions` 为 null；整个工具批次最多一张项目或 Skill 图片，多图批次原子回滚并进入参数修复。

模型看到图片后公开记录可见事实、连续性要点和精确引用，再读取下一张；新请求只附当前图的像素，旧图以文本观察和引用承接。为支持长任务，新请求保留初始输入、完整激活 Skill 主说明和近期完整工具配对，较早公开观察、状态、费用及引用做确定性有界投影；省略细节明确提示按精确引用重读，主说明合并不会授予工具权限。该取舍增加读取回合和可能的 LLM 用量，较早细节不保证始终驻留，重要进度应保存为持久创作卡片。

单次请求资源、超时、局部参数修复、取消、权限、媒体审批与 UNKNOWN 边界继续适用；八张、单图 2 MiB、合计 8 MiB 的底层图片保护保留，新协议实际只附一张。原检查点及工具账本不可变，历史数字策略和提示词保持冻结，旧 BLOCKED/FAILED Run 不自动恢复或重发媒体。此次无需数据库迁移；OpenAPI 与生成 TypeScript 的限制字段变为可空，前后端同步发布，后续新 Run 才使用新规则。此决定更新规格 §8.5–8.6 及 ADR 0037 的新运行图片上下文规则。
