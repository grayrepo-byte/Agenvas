# AutoDL ComfyUI 工作流固定协议适配

2026-10-01，用户要求接入 AutoDL ComfyUI 工作流，并明确指出参考资源实际需要 base64，不能依赖文档中的 URL 输入。此决定局部修订 [ADR 0002](0002-fixed-media-adapters-before-workflow-platforms.md) 暂不接入工作流平台的范围：新增 `AUTODL` 连接与 `AUTODL_COMFY_VIDEO` 固定 Java 适配器，共用既有 CanvasItem 草稿、版本化媒体能力和持久 Task，不引入脚本、任意 ComfyUI 图、远程工作流发现或 Agent 媒体工具。

使用受审查的 H3 工作流参数声明：同一提交/查询协议，通过版本化 `workflowId`、`videoResolution`、可选 `seed` 区分工作流；每个声明固定输入模式、必填参考、参考数量、时长、种子支持与精确分辨率枚举。首尾帧使用 `first_frame` / `last_frame`，其他参考使用分别从零编号的 `ref_image_N` / `ref_audio_N`。管理员可收紧上限，不能扩大工作流范围；资源按项目权限读取已冻结版本的归档字节，以带 MIME 的 base64 data URL 提交。

提交前记录尝试检查点，拿到 `task_id` 后持久保存并异步查询原 ID。响应丢失保持 UNKNOWN，只允许用户显式新尝试；下载失败或链接过期只查询原任务并恢复归档，不再次生成。结果仅从已确认的官方对象存储主机与 `/comfyui/outputs/` 下载，校验 DNS、MIME、字节上限并禁止重定向，下载不携带 Token。视频保留原音轨，由既有媒体解码与归档流程创建不可变 Asset/ArtifactVersion；不裁剪供应商返回的时长。

当前支持 14 个显式时长的 H3 工作流。自动按音频决定时长的单图对口型、需要视频参考的动作迁移、使用不同音频参数的 IndexTTS 尚未实现，后续扩展须有相应参数与媒体契约，不能套用 H3 声明声称兼容。V65 增加平台检查约束，既有数据保留，前后端同版本升级；验证与配置见 [AutoDL 接入说明](../autodl-comfyui.md)。

## 2026-10-02：一个能力发布多个分辨率

按用户决定，同一工作流能力可以发布多个受支持的输出档位，创作者在视频草稿中选择本次分辨率。`settings.videoResolutions` 保存非空、去重的可选档位，`settings.videoResolution` 表示默认档位且必须包含于可选列表；管理员只能收紧固定工作流声明的范围。草稿明确的 `parameters.videoResolution` 优先于默认值。未声明可选列表的历史能力保留原来的单一档位，不自动扩展范围。

视频价格支持 `settings.pricingByResolution`：每个已发布档位可独立设置十进制单价、币种及 VIDEO/SECOND 单位。匹配档位的价格优先，否则使用可选的统一 `pricing`；两者缺失时保持费用未知，显式零仍为零估算。当前只有 AutoDL 固定协议声明可选视频档位，因此其他视频适配器继续按已有统一价格估算，不能配置未生效的分辨率控制。局部扩展 [ADR 0019](0019-media-capability-defaults-limits-and-pricing.md)。

任务受理固定草稿选中的档位、精确供应商枚举及匹配的 `mediaPricing`，既有用量账本继续使用该快照。配置改价或移除档位不能改变历史任务或取消释放的估算；不兼容草稿保留选择、提示调整并拒绝运行。2026-10-04 用户决定修订：显式切换到不支持当前档位的能力时，前端直接重置为新能力默认值并与其他草稿整理一次性应用，不追加影响确认；兼容档位继续保留。新增字段沿用不可变能力 JSON 与草稿 JSON，无数据库迁移或 jOOQ 改动；前后端与生成 TS 合约需一起升级。验证见 专项记录（开发记录不随源码公开）。

## 2026-10-02：目录发现与管理员发布的数据定义

按用户要求，取消新视频工作流必须修改前后端枚举的限制。原决定中禁止远程发现的部分修订为：管理员可以匿名读取固定官方目录及输入元数据作为候选，通过 `workflowDefinition` schemaVersion=1 保存完整的受限输入定义，并显式发布新的不可变能力版本。导入失败可粘贴官方详情 JSON，或手工配置同一固定协议的定义；内置 14 条声明继续作为离线预设。目录刷新与预览不执行生成，也不保存能力。

定义只保存真实目标 ID、名称、模式、显式时长及提示词范围、连续图片/音频字段与必填数量、种子支持、精确分辨率枚举及默认档位，不保存远程图、节点映射、URL、脚本或请求模板。档位允许三至四位正整数加 `p`，每个档位/比例必须有唯一映射；上下限见规格 6.12。管理员配置的上限仍只能收紧该能力定义。不同输入/输出协议需要对应适配，不能把目录全量等同于已支持全量。

本次匿名核对 17 个公开目标：内置 14 个视频工作流的全部精确分辨率枚举与官方一致，没有发现静态声明漏项；另 3 个分别采用自动音频时长、视频参考或音频输出，仍不支持。候选定义是供应商公开元数据在获取时的快照，不保证供应商远程图不变；已提交任务继续使用原能力/连接版本，排队提交仍遵守现有能力变更预检。继续沿用能力 JSON，无数据库迁移或 jOOQ 改动。OpenAPI、生成 TS、前后端同步升级。见 [目录研究](../research/autodl-workflow-catalog-2026-10-02.md)与专项验证（开发记录不随源码公开）。
