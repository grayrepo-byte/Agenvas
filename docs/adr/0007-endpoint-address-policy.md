# ADR 0007：端点地址策略放行私网与代理 fake-ip

状态：接受（2026-09-26）。

## 背景

管理员配置的 LLM 端点与内置云媒体传输都要求 DNS 解析结果落在公网地址，用以阻止 SSRF：攻击者诱导管理员配置一个自己控制的域名，先解析到公网通过保存校验，之后重新解析到内网或云元数据端点，让服务端代为访问。

但这套规则把三类性质完全不同的地址同等拒绝：

- **云元数据端点**（`169.254.169.254`）：任何部署下都危险，读到的实例凭据可用于横向移动。
- **私网地址**（`10/8`、`172.16/12`、`192.168/16`、IPv6 ULA `fc00::/7`）：自托管部署把模型服务放在内网是完全正常的形态，项目自身也为本地 ComfyUI 保留了内网例外。
- **代理 fake-ip 段**（`198.18.0.0/15`、`2001:2::/48`）：Clash、mihomo 一类代理默认用它应答**所有**域名，于是开启 fake-ip 的开发者连公网 HTTPS 域名也存不进去。

实际后果是失败与服务本身无关，而用户只能看到"只接受明确的 HTTPS 公网端点；本机 HTTP 需部署者显式开启"——与真实原因（域名解析到保留段）毫无关系，排查成本极高。

## 决策

- **放行私网与代理 fake-ip 段**：`EndpointAddressRules.allowsSelfHosted` 统一判定 RFC 1918、IPv6 ULA、`198.18.0.0/15`、`2001:2::/48`。LLM 端点策略（`LlmEndpointPolicy`）与内置云传输（`FixedCloudDns`）共用这一份实现 —— 此前两份规则各自维护，且已经漂移。
- **保留云元数据拦截**：它属于 link-local，不在放行之列，任何部署下仍被拒。
- **保留 loopback 例外开关**：本机 HTTP 仍需部署者显式开启，且只认字面 `127.0.0.1`。
- **保留运行时 DNS 校验**：`SafeLlmTransport` 在每次连接时重新解析并按同一规则检查。这是防 DNS 重绑定的关键 —— 只在保存时校验，无法阻止域名在通过校验后被重新指向内网。

## 取舍与影响

曾考虑三种替代：完全不校验、仅保存时校验、维持现状只改错误文案。第一种会让跑在云主机上的自托管实例暴露于元数据窃取；第二种放过 DNS 重绑定；第三种不解决 fake-ip 这类真实阻塞，且规则本身把"不常见"误判成了"危险"。

代价是：部署者若把端点指向私网，服务端会真的去访问该地址，SSRF 防线相应收窄到"云元数据 + 非路由地址"。这与自托管定位一致 —— 配置端点的是部署者本人，他清楚自己的内网拓扑。若将来出现多租户形态（管理员不等于基础设施所有者），需要重新审视这一假设。
