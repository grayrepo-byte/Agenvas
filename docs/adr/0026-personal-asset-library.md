# 个人资产库与项目内容边界

状态：已接受并实施（2026-10-01，GitHub #24）；验收范围见专项证据。

用户要求把画布生成结果按角色、场景、道具、其他分类保存，并确认“我的资产”属于账号、可以跨本人项目复用。这些名称是资产用途分类，创作产物仍为 TEXT / IMAGE / VIDEO / AUDIO；本决策扩展个人内容管理范围，保留 [ADR 0013](0013-contract-to-direct-generation.md) 的直接生成与规划链路收缩边界。

新增 LibraryEntry 承载个人分类资产，固定用户明确选中的内容版本，并独立保存媒体；导入时创建目标项目自己的产物、文件与精确版本。现有 Asset 保持项目文件语义。相较直接引用原项目内容，该结构增加复制存储成本，但资产不依赖来源项目存续，项目输入也不需绕过跨项目权限边界。源工作卡片、草稿、连线与任务不随资产复制；资产改名、分类或删除不改写已经导入的项目内容。

实施细节、接口草案和验收见 [个人资产库设计](../superpowers/specs/2026-10-01-personal-asset-library-design.md)。演员库、合集、完整生成配方及团队共享不属于本次首版；已增加 `/api/v1/library` 与项目保存/导入/参考接口，以及 V67–V70 增量迁移。`LIBRARY_IMPORT` 为服务端专用内容来源，普通产物写入拒绝伪造。命令以固定输入、独立文件 pin、租约与 fencing 恢复；失败文件和完成 pin 使用持久清理队列。未调用真实 Provider。测试与限制见 #24 实施证据（开发记录不随源码公开）。

## 2026-10-02 扩展：媒体创作模板

用户确认增加图片/视频模板，保存可编辑提示词和可选参考图片，并区分个人模板与管理员维护的系统模板。沿用本 ADR 的内容复制边界：模板独立持有图片副本，应用时再导入目标项目自己的文件与不可变内容版本。相比保存来源项目 ID，该方案增加复制成本，但删除来源项目或模板不会破坏另一侧内容，也无需放宽项目资源权限。模板与个人资产条目各自管理元数据和作用域，复用媒体归档应用服务；系统模板共享的是模板内容，不是管理员项目的资源访问权。

模板应用只填充当前草稿，仍由用户继续编辑、完成预检并点击运行。纯提示词模板保留引用，带图模板经明确预览后整体替换引用；模型、参数和时长不属于模板配方。完整行为与验收范围见 [媒体模板设计](../media-templates-design.md) 和规格 6.15。
