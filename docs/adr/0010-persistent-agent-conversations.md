# ADR 0010：Agent 会话承载跨次发送的记忆

状态：接受（2026-09-26），修正 ADR 0005 中将一次 AgentRun 等同于一次对话的呈现边界。

用户明确要求同一会话多次交流带上既有上下文，只有新建会话才开始新的记忆。采用持久 AgentConversation 聚合多条有序 AgentRun；会话归属一个项目和 Agent，当前会话选择也持久化。每条消息仍有独立 Run，以维持既有预算、计划审批、幂等、任务恢复与取消生命周期，避免把已终结的 Run 重新打开并混用旧审批。

每次 Run 在项目/会话锁内固定历史水位和有界公开上下文。只沿用同会话终态 Run 的用户指令、已提交公开回复与动作/状态，不把旧协议元数据或私有推理拼接到新请求。超长会话做有标记的有界投影，原记录不删除；新建会话从空历史开始，Agent 配置及明确绑定照常适用。会话文字不提升权限：可继承的历史产物必须仍为该会话前序 Run 的当前选用非人工版本，并在新 Run 中固定精确版本；文字另固定修订 CAS，媒体使用 CanvasItem 的选用结果。显式绑定优先，其他会话隔离。

V45 为既有每条 Run 各建立一个单轮会话，保留原先互相独立的语义，不能把旧任务静默混成共享记忆。新接口支持幂等创建、选择和分页读取会话；Run 创建与运行前确认增加会话身份、轮次和版本检查。同项目仍只允许一个活动 Run；新建或切换会话不取消在途任务，也不消除 UNKNOWN。

升级时需同时发布后端与重新生成合约的前端。旧客户端省略会话字段时，服务端使用该 Agent 的当前会话；显式指定会话的客户端同时传预检版本，过期则返回冲突。V45 为 Run 增加非空会话外键与轮次，迁移后的数据库不能直接交给不写这些字段的旧后端。迁移前备份数据库；迁移本身保留已有 Run、任务、审批和媒体版本，不重跑任务。

代价是新增会话数据、复合外键和上下文快照，且客户端必须处理“查看的会话”和“正在运行的会话”不同的情况。跨会话检索、自动合并记忆及后台摘要模型不在本次范围。具体检查结果与尚未完成的浏览器/真实模型验证见开发清单。


## 发送直接启动修订（2026-10-03）

用户明确要求删除 Agent 的运行前确认。卡片点击发送或 Ctrl/Cmd+Enter 即授权本次模型调用：自动预检模型/工具能力、显式 Skill、精确输入及配置/会话版本，然后创建独立 Run，不再展示“返回修改 / 确认开始”。预检不可用、素材未就绪或版本冲突时保留草稿，用户修正后重新发送；准备期间改变输入或 Skill 不提交旧意图。创建响应丢失时，未改变的意图以原请求/幂等键重放，避免已占用项目槽位导致无法找回受理结果。

本修订覆盖 ADR 0005 的二次确认呈现及创作 Skill 设计中的运行前确认。后端授权、CAS、同项目单活动 Run、持久 Task、取消、UNKNOWN 与后续媒体批次批准沿用原边界。没有 API 字段或数据库迁移；前端与后端修复应一同发布，旧前端仍可通过原创建接口运行。

同时修复 Run 输入快照把节点媒体结果误当资源库默认版本的问题。绑定的精确媒体版本可以在资源库默认为空时固定；当前选中项按内容类型固定版本，文字使用资源默认版本，媒体使用 CanvasItem 的选用版本，空草稿只固定主体/种类。不会为了运行 Agent 写入或变更资源库默认版本。

## 媒体跨轮继承与模型等待修订（2026-10-04）

用户反馈导演已生成基础图片，但发送后续任务无法继续图生视频。媒体任务成功只选用目标 CanvasItem 的精确结果，Artifact 的资源默认版本允许为空；仅按资源默认版本查询同会话输出会漏掉这些已归档图片。跨轮继承因此按内容类型选择来源：文字保留资源默认版本与修订 CAS，图片、视频和音频使用当前项目仍在画布上的节点选用版本。Canvas 模块提供选用版本身份，Artifact 模块重新核验项目、所有者、内容类型、非人工来源及授权的前序 Run，不跨模块访问表常量。

同一版本在多个节点出现时去重，同一 Artifact 在不同节点选用的不同版本可分别继承；显式绑定优先，总输入仍有界。节点选用人工替换内容、其他会话或其他 Agent 的结果时不隐式授权旧结果；新建会话从新的记忆开始。继承不改资源默认版本、不切换节点结果，也不补写已经冻结的旧 Run。用户批准仍只覆盖新的固定媒体批次。

用户最终确认慢模型单次请求总体上限为 600 秒，传输层单次读取超时为 180 秒，并取消 Agent 整个任务的执行时长限制。执行器的单次模型等待、Spring AI SDK 与 HTTP 整次调用使用 600 秒，连接建立仍为 10 秒；持续流片段不延长整次调用，SDK 与传输层不自动重发。合并 main 时保留已确认的单回合技术故障恢复，由业务 Runtime 按规格 §12.6 的次数与首次失败后窗口重试，Worker 等待受剩余恢复期限约束；取消不进入重试。AgentRun 不设置累计执行或自然时长上限，替代此前规格中的累计活动时间与整个 Run 等待期限计划；每个媒体审批批次的等待和执行期限仍沿用 ADR 0028。文字节点模型调用使用单次调用规则，媒体 Provider 自身的超时保持原规则。无 API 字段、数据库迁移或依赖版本变更；新行为需更新后端，新任务重新冻结输入。


## 导演 Agent 与统一提示词管理修订（2026-10-03）

用户确认创建 Agent 直接落为画布卡片，删除创建抽屉；默认 Agent 改称「导演 Agent」。需求从卡片对话提交，创建本身不调用模型、不受理媒体任务。后台「提示词管理」统一维护多条 Agent 与功能提示词；选定 Agent 条目后复制名称与正文到新实例；已有实例及活动 Run 保留自己的配置。卡片设置仍可单独编辑名称、系统提示词和输入绑定，使用原 CAS。

默认创作流程为需求分析、剧情与镜头方案、人物/场景/必要道具图片、镜头图片、图生视频与结果整理。人物、场景、道具是普通 IMAGE 产物的标题分类，不恢复已撤回的专门类型或执行计划。每个有依赖的阶段等待前一阶段真实归档版本，视频通过明确的 mediaInputs 绑定精确图片版本；独立媒体可组成固定批次，每批仍需用户批准。提示词不能代替能力校验、授权或真实模型验收。

新 Run 固定系统规则版本 6，将实例冻结的创作系统提示词以 SystemMessage 传给模型，服务端规则仍明确约束权限、工具、预算与审批。历史版本 1–5 保留原规则与消息角色，恢复时不能读取最新默认值。内部 profileKey=creator 保持现有身份，不按显示名改变运行策略。

视频卡片展示图片引用缩略图、角色与版本，并可打开原图；显示结果时从选用版本的 frozenInput 读取，显示草稿时从当前 MediaDraft 读取。之后改草稿或资源默认版本不改写旧视频来源。

用户随后明确要求支持多种 Agent 及其他功能提示词，单例表方案撤回。采用统一 PromptDefinition：UUID 身份、全局唯一且不可变的 key、AGENT/FUNCTION 用途、name、description、content、builtIn、CAS version 与时间。内置条目可编辑但不能删除，以保障既有消费入口；自定义条目可新增和按版本删除。Agent 预设只决定创作名称/指令，不扩展受控工具、审批权限或同项目单活动 Run 边界。

后台管理员使用 GET/POST /api/v1/settings/prompts 及 GET/PUT/DELETE /api/v1/settings/prompts/{id}；修改、删除带 expectedVersion。普通认证用户通过 GET /api/v1/agent-presets 只读取 AGENT 名称及 key，不获得功能正文。画布添加菜单包含全部 Agent 预设，选中即直接创建卡片。创建接口增加可选 promptKey，未指定时使用 agent.director；FUNCTION 或不存在的条目不能用于创建 Agent。请求哈希固定所选 key；重放不重算提示词。已有显式名称/指令创建接口继续可用。

文字卡片直接生成使用内置 text.generate 功能提示词。新 TEXT_GENERATION Task schema 2 在受理时固定 systemPrompt、promptKey 与 promptVersion；Worker 只读该冻结输入，不读最新管理配置。历史 schema 1 Task 保留原固定规则，公开 Task 投影不显示创作系统提示词。增加其他功能条目不会自动获得执行入口，具体消费者须按用途接入；服务端安全规则及模型诊断协议仍在代码中受版本控制。

用户明确说明旧导演单例方案尚未同步到应用数据库，授权直接删除旧表定义及搬迁方案。删除未发布的 V5__director_agent_defaults.sql，直接新增 V5__unified_prompt_management.sql 创建统一表及 agent.director/text.generate 初始条目，不建旧表、不搬迁数据、不修改已发布 V1–V4。jOOQ 从实际隔离 PostgreSQL 重新生成，未执行用户应用数据库更新。没有旧单例接口或客户端兼容层；前后端和建表文件需同时发布。

## 创作配置与底层协议边界修订（2026-10-04）

用户发现模型收到可管理的导演提示词及代码中的英文系统规则，进一步明确底层系统协议不应由用户管理。保留程序维护的工具、审批、按需读取、历史来源与私有推理边界；管理员及卡片使用者只管理角色、语言、风格与创作流程。提示词文字不能授予权限，服务端实际执行工具允许列表、项目作用域、CAS、预算、参数校验和媒体批准。

新 Run 使用 systemPromptVersion=7：底层协议不再指定 Creator 身份、用户回复语言或导演图生视频与连续性流程，创作 SystemMessage 使用冻结卡片正文，不添加英文创作包装。仍保留独立协议和创作消息，含历史上下文时继续使用程序维护的来源说明。内置 agent.director 已有对应创作要求，不迁移或覆盖用户预设与卡片。历史 1–6 及已保存模型检查点沿用原消息；恢复、媒体续接和模型重试不读取最新配置。

代价是请求仍包含程序协议与创作配置两层；管理页并不编辑底层协议，但界面名称和说明明确可编辑范围。OpenAPI 增加提示词版本 7 并重新生成 TypeScript，前后端应同步更新以避免旧枚举或过期预检；无数据库迁移、依赖变更或用户应用数据改写。底层英文历史常量仍用于受理时已冻结的旧 Run，不能删除后让恢复静默改变语义。
