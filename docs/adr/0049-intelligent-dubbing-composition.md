# ADR 0049：分镜语义与声音活动共同驱动配音合成

用户需要按分镜和台词自动匹配现有配音，适配到视频中的位置并合成短剧，并明确要求利用原片波形变化。此次实现保留现有导演和 MCP，通过新增本地合成能力完成这一流程。

## 决定

现有导演读取剧本文字、不可变媒体提示词、输入来源和实际时长，判断镜头顺序及每镜对应的配音。`compose_video` 接收精确版本、有序镜头/台词和可选的镜内剧情锚点；画布位置、文件顺序和节点选择顺序不作为剧情顺序。依据缺失或冲突时说明具体问题，不能宣称已听懂未提供给模型的音频或看懂未提供的视频帧。

持久 Task 在数据库事务外解码原片第一音轨和配音，计算 20ms 音量包络、声音活动区间和首尾静音。声音活动只是时序线索，不是语音识别、说话人识别或口型检测。配音保守去除首尾静音，保留句中停顿；优先适配原片声音活动窗口，明确剧情锚点优先。没有可靠窗口或窗口不够长时使用时长排布，并在结果中标注回退依据。最多使用 1.15 倍保音高加速；无法完整容纳时失败，不截断台词。

默认合成时移除原声，但定位仍可使用原声。`BACKGROUND` 保留 15% 原声，其中可能含原对白；不声称已经分离人声和背景。输出新增独立视频产物与节点，保留逐句实际起止、裁切、速度、声音窗口与警告，源素材和当前选用结果不变。

本地 `LOCAL_VIDEO_COMPOSITOR` 复用媒体 Worker、租约、取消、归档、结果选择保护和零外部费用记录，不增加收费审批。内置 Agent 的云媒体生成审批保持原规则。导演受理的本地合成独立后台执行：Task 不占用 Run 调度生命周期，可信 `compositionRunId` 记录发起者并赋予同 Run 读取该 Task 的权限；结果版本保留来源 Run。停止导演不等于取消已受理合成，用户在结果节点取消。MCP 继续按用户 `MEDIA_GENERATE` 权限直接受理并记录命令账本；REST 使用 Session、CSRF 和项目鉴权。三种入口复用 `VideoCompositionService`。

## 边界与代价

- 最多 12 镜、30 句，成片不超过 60 秒；单个音视频源不超过 60 秒，去重后源素材不超过 1 GiB。第一版输出为 1280×720、30fps，其他画幅等比留边；每镜向下对齐完整视频帧，少于 34ms 的调整记录在时间表中。
- 使用现有 FFmpeg，不引入云识别服务、语音模型或运行依赖。固定参数数组、受控本地路径、私有临时目录、有限时间/空间、取消与心跳沿用现有安全边界。
- 音乐、音效与噪声可能干扰声音窗口判断；无声原片仍可按分镜/台词合成，但不能获得原声说话时间线。识别实际台词、说话人和画面事件需要后续独立的识别能力与验收。
- 不增加可编辑时间轴表。受理配方冻结到 Task，实际执行时间表写入不可变结果；重新编排创建新任务和成片。
- V31 只增加本地能力种子，不修改表结构、不重写旧数据。没有 jOOQ schema 变化。

这项决定更新 [ADR 0013](0013-contract-to-direct-generation.md) 当时移除成片自动化的范围：现在明确提供有界的配音合成，不恢复旧 ExecutionPlan 或固定三镜头流程。协议见 OpenAPI `VideoCompositionRequest` 和 MCP `compose_video`；验证状态见开发清单。
