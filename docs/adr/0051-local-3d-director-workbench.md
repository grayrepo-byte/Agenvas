# ADR 0051：本地 3D 导演台以拍摄版本保存场景

接受（2026-10-22）。用户要求调研开源画布的 3D 导演台并为画布增加支持。采用原生 Three.js、程序化人偶与有界几何场景，在现有 React 工作台内摆位、调整相机并拍摄 PNG；按需加载渲染代码，使用精确正式版本 `three` 0.186.1 / `@types/three` 0.186.0，不引入 R3F 或外部导演台 iframe。这样自托管与 Mock 模式都能独立构图，不依赖作者专属服务，也不把第三方项目代码的许可等同于其角色、贴图与模型资产的分发许可。调研与来源见 [开源导演台调研](../research/3d-director-workbench.md)。

不增加导演台数据库实体或专用 Task。场景是本次本地拍摄的可编辑来源，只有用户拍摄保存后，才通过现有上传版本接口以 `DIRECTOR_3D` 用途和受控 `directorScene` 一起归档为 USER ArtifactVersion；场景保存在不可变 `frozenInput.directorScene`。空图片首次拍摄填充自身，已有结果的拍摄沿 [ADR 0017](0017-operation-specific-media-versioning.md) 派生独立节点和空白媒体草稿。保存固定精确来源、CanvasItem CAS、素材和稳定目标 ID，相同命令可安全重放，来源变更拒绝新保存。该决定选择了较小的媒体版本闭环，代价是尚未拍摄的编辑只留在工作台会话内；关闭前确认放弃，JSON 导出提供临时保存，不能冒充服务器自动保存。

场景 schema 只包含版本、画幅、相机与最多 32 个程序化对象，前后端拒绝未知字段和越界数据；不加载 JSON 中的任意脚本、外部模型或素材地址。图片节点仍是 IMAGE CanvasItem，3D 是本地编辑入口与版本来源，不新增 ArtifactKind、节点执行图或隐式模型权限。后续若需要跨会话场景草稿、真实资产导入、骨骼、时间线或视频导出，应为实际持久化与资源预算重新设计，不能把本次截图协议扩展成任意场景执行入口。

已有图片的角度模式展示二维来源，并把相机方位、仰角、距离、焦距和构图要求转成既有 `VIEW_ANGLE` 图片功能输入。只有管理员配置能力且用户显式提交后才创建现有生成 Task；与本地拍摄保存分开处理。普通图片不会因进入导演台获得真实三维几何或背面信息，相机预览也不证明模型能准确重建未见内容。本次不提供连续运镜或视频输出；本地 PNG、Mock 受理与真实 Provider 的视角效果分别验收。
