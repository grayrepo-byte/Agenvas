# ADR 0057：镜头媒体提案与结果候选

状态：接受；实际验证范围见开发清单。

导演已经能直接写入分镜板，但媒体审批只按当前制作节点匹配。未绑定节点的镜头无法接收导演新提案，改换节点也会丢失镜头与旧批次之间的可见关系。用户要求提案关联具体镜头，审批状态和结果自动回到制作台，同时保留显式批准与选用。

决定在 `propose_media_generation` 的各项输出中允许成对提交 `shotId`、`expectedShotRevision`。服务端在项目事务锁内验证同项目当前镜头，冻结其真实 UUID、镜号、创作修订以及由媒体类型推导的 `KEYFRAME / VIDEO / AUDIO` 用途。模型不能提交镜号快照、用途、批准或选用断言；独立素材和历史提案继续允许没有镜头关联。

关联保存在原审批账本的固定目标中，不自动写分镜板制作关联。相比把新占位节点立即绑定到镜头，这保留了用户既有节点、付费结果和板修订，也避免拒绝清理空节点后留下自动建立的悬空绑定。制作台按当前镜头身份或已绑定节点查询原审批，未绑定节点的镜头也能显示完整固定批次；单镜入口不缩小整批审批范围。

用户批准时，在创建任何 Task 前重查关联镜头仍存在且创作修订和创意指纹一致。镜头 UUID 即使删除后重新加入，其修订也从历史最大修订继续推进，不能重置为 1；因此旧提案与旧结果不能因身份复用重新变成当前依据。额外固定指纹覆盖影响修订的画面、台词、时长、来源和参考。无关镜头修改、重排或单纯改镜号不阻塞；相关镜头已改稿或移除则整批失效，不提交任何新 Task。拒绝、过期和同一决策幂等重放不受后来改稿阻碍。此检查补充分镜语义，原草稿、目标、能力、费用、输入、期限和权限检查继续适用。

媒体状态和归档结果只做账本投影，不为状态变化追加分镜修订。终态逐任务结果明确记录输出索引、目标节点和冻结镜头关联，保留精确版本及额外结果；不能按媒体种类猜测多镜结果归属。镜头提案的归档结果不自动选用；用户在制作台明确选择候选后只修改本地草稿，再通过原全板 CAS 保存。分镜选用与画布节点的结果选用仍是不同记录，历史 `selected` 标志不代表分镜已经采用。

审批的最终 `result` 和模型续接仍只冻结一次。只读 `archivedResults` 另从可信任务输出投影已经归档的候选，覆盖同批部分成功、取消/超时/UNKNOWN 后的晚到归档；出现新文件不改变审批终态、不自动重启 Agent、不自动选用，也不转成重新生成。

生成期间改稿不修改已批准任务。结果按旧镜头修订归档，用户改选该旧依据候选时服务端仍保留待复核，只有用户明确确认适用才能核销；原选用在用户行动前保持不变。失败、取消、拒绝、过期和 UNKNOWN 都回到对应镜头，UNKNOWN 仍保留可能外部费用且不自动重提。节点移除不删审批历史，候选不可悄悄重建节点或重新生成。

显式选用不能切断导演审图及下一批引用。除既有当前画布选用与显式 Skill 精确输入外，可信 Run 上下文可读取该 Run 的已批准镜头任务所实际归档的精确版本，以及用户已经保存到分镜制作关联/成片选用的精确版本；两者的目标节点都须仍存在。前者核对服务端 Task、Run、固定显式选用标记和实际输出，后者核对持久分镜选用及当前节点归属；不能通过模型提供的 `sourceTaskId`、普通板来源/参考 ID、其他 Run 未选候选、未保存草稿或任意同项目版本取得权限。这些授权只覆盖读取和媒体引用，不批准下一批，也不授予目标写入权限。

沿用现有 JSONB 审批账本、项目事件、任务恢复和模型结果续接，不新增镜头任务表或独立调度器。HTTP 合约增补镜头关联与明确的结果字段，旧记录允许缺少新字段。V37 只升级精确默认导演指令，保留用户自定义、冻结 Run、媒体审批和分镜历史；无数据库结构变化。

部署须同批更新后端、Worker 与前端。镜头任务新增的显式选用输入标记由本版本 Worker 执行，旧 Worker 不认识该标记；有这类任务尚未归档时不能直接混跑旧 Worker 或假定降级后仍保留相同选用语义。迁移不修改已冻结请求和旧任务输入，不追溯改变普通媒体审批的选用行为。
