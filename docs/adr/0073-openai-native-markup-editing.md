# ADR 0073: OpenAI 原生标注引导编辑

## 决定

智能编辑新增可选“标注引导”，默认仍使用既有蒙版。入口复用智能编辑模态、笔刷、矩形、橡皮及撤销/重做；标注模式的矩形为描边，红色可见笔迹和文字指令一起指导模型。切换模式清空当前绘图前必须确认，提示词和额外参考图保留。后台绑定的模型由既有功能设置控制，不在编辑窗口隐式切换模型。

`markupAssetId` 指向同项目 READY PNG；与 `maskAssetId` 互斥，仅用于 SMART_EDIT。前端导出与浏览器显示原图一致尺寸的独立透明图层，不合成原图。后端在受理前、事务外读取并验证原图和标注，支持 JPEG/WebP/PNG 的 EXIF orientation；首图与标注均按方向归一化并重新编码为 PNG，剥除方向元数据；首图保持原始像素尺寸、不按输出画幅填白缩放。标注必须与归一化首图同尺寸、有透明像素且有可见笔迹；首图和图层最多 16,777,216 像素。应用沿用图片上传 20 MiB 上限（低于供应商 50 MB），发送的规范化 PNG 同样有界。额外图片维持冻结顺序，标注仅对应首图。

只有已明确核验的 GPT Image 2.5/2.6 Sunburst、Flare（含 2.5 的 2026-09-08 快照）PNG 能力公布 `supportsImageMarkup`。旧模型、任意别名、GIF、其他 Provider 不支持。服务端重复校验，不依赖前端元数据。任务的请求指纹和执行快照保存标注资产 ID；编辑会话固定来源版本和 CAS 基准，SSE 变化不替换原图或清空笔迹，冲突保留输入。旧请求未传标注时维持原请求指纹形状，原任务与原键重放仍有效。

multipart 向 `POST /v1/images/edits` 发送独立 `markup` 文件；既有中继模式发送 JSON `images` 与 `markup.image_url`，不得发送 mask 或 prompt_rewriter。标注中继必须为 HTTPS；准备失败在生成前拒绝，不换传输或重提；受理不确定继续 UNKNOWN。素材读取沿用 AssetService 的项目授权、归档及出站中继规则，不接受任意 URL/路径。无数据库迁移、新 Provider、新依赖或凭证配置。

原蒙版保留其输入协议与画幅变换；补像素回归并修复不透明白底合成抹除 alpha 的缺陷。本地画笔继续执行 BRUSH_MARKUP 保存，不创建 AI Task。

## 考虑的方式

- 选用现有智能编辑入口（采用）：功能绑定、费用、精确来源、结果派生和错误恢复共用；用户明确选择引导方式。
- 改造本地画笔保存：会改变既有不调用 AI 的语义，拒绝。
- 将原图与标注合成参考图：丢失原生 markup 语义，拒绝。

## 官方依据与核验边界

- https://developers.openai.com/api/docs/guides/image-prompting

2026-11-05 官方指南明确支持 2.5/2.6，示例使用 gpt-image-2.6-flare；API 字段说明仍只提 2.5，以更新后的指南和模型说明确定 2.6 支持。文档核验与合成 HTTP/Mock 测试不代表真实账户、兼容中转站或模型效果已验证。真实 API 验证情况在交付说明单列。


## 真实调用验证范围

2026-11-05 使用已有官方连接，在隔离数据库中完成 `gpt-image-2.6-flare` 的 markup、mask 各一次真实编辑（1024×1024、high、low complexity），经 HTTP 受理、任务、真实 Provider、归档及鉴权读取，重放没有增加生成尝试，来源保持不变。合成红色花瓶改蓝测试中，原生标注保留花瓶轮廓并移除标记；蒙版输出为填满选区的蓝色块，未保留花瓶形状。两者背景有细微变化，像素精确保留不作保证。蒙版传输修复与 API 成功不等于视觉效果已验收。

追加一次省略 complexity、使用模型默认强度的蒙版对照，保持相同原图、蒙版字节及冻结提示词；链路成功但花瓶仍变成填满选区的蓝色块，保形要求仍未通过。默认强度在该样例未改善结果，不能简单将失败归因于 low complexity，也不从单次对照推导模型普遍行为。三次生成均无重复受理，来源不变。未核对实际账单，未验证真实中继和兼容中转站。私有执行回执、合成输入输出及费用估算保存在仓库外受限目录，文档不保存实际账户、项目或任务身份。
