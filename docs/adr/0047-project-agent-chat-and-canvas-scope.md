# ADR 0047：项目导演聊天窗口与画布操作范围

用户要求取消节点形式的 Agent，改为右下角聊天弹窗，并能操作当前画布全部节点。AgentInstance 作为项目内名称、创作系统提示词、Skill、会话与运行的稳定身份保留。窗口独立于画布缩放，支持收起、展开、历史与设置；收起不取消任务，也不丢弃草稿。画布创建、资源恢复和音频对话入口均不再放置 Agent 节点。

同日按用户反馈收敛为每项目固定一个内置导演：移除主头部 Agent 选择器与从预设新建助手的入口，唯一新建操作为“新建会话”。用户进一步明确同意直接删除旧 Agent 及其已有会话、执行记录，因此一次性数据迁移 `V27__reset_legacy_director_history.sql` 清理全部旧 Agent、会话、Run、关联任务与公开执行记录，不保留历史助手兼容入口，也不合并旧记忆。生成产物、画布内容和媒体文件保留，清理不得连带删除素材或不可变内容版本。遇到未终态 Agent Run 或关联 Task（含 UNKNOWN）时中止迁移，待原任务完成归档后再升级；清理不重新调用 Provider。本次不改变 schema，无须重新生成 jOOQ。此决定替代此前保留旧助手与会话的产品规则；下文 V26 与旧协议的说明保留为此前实现的历史记录。清理后首次打开恢复或初始化默认导演配置，初始化不调用模型，后续重开恢复同一身份。这样消除日常创作中重复创建助手和选择身份的负担；代价是旧对话和执行历史不再可访问，旧 URL 不恢复已删除记录。

界面采用固定身份顶栏、单行会话导航、紧凑画布上下文、独立滚动的消息区、空态快捷任务和固定输入区。快捷任务只填入可编辑草稿；历史和设置页隐藏输入区，返回对话恢复草稿。默认导演创建后的长期配置仍按 CAS 保存，媒体审批、UNKNOWN 和活动 Run 返回入口继续保留，当前权限按下文动态全画布规则校验。后端通过 V27 升级迁移执行历史清理，内容保留与回滚验证见开发清单。实际数据库清理在部署升级时执行；升级前备份，回退已删除历史须恢复备份。

2026-10-22 用户进一步要求彻底删除多 Agent 残留。项目通过无正文 `PUT /projects/{projectId}/director` 在项目事件锁内恢复或初始化唯一导演，V28 对 `agent_instance.project_id` 加唯一约束。已有导演直接返回当前配置，不追加事件，不需要创建命令键或缓存首次响应。删除自由创建、助手列表、预设目录和按 Agent 筛选的跨会话运行列表；快照 `agents[]` 改为可空 `director`。V29 删除额外 AGENT 提示词，并只允许固定内置 `agent.director`；新提示词只可创建 FUNCTION。Skill 试用只选项目，不保留旧 `agentId` URL 选择兼容。项目导出清单升至版本 8，将 Skill 的 `agentBindings[]` 收为可空 `directorBinding`，由项目唯一导演隐含归属；不存在多助手绑定列表。保留会话、Run、Skill 和审批所需的稳定导演 ID，它们承担归属与 CAS 校验。此接口及 schema 变更须与前端同批部署，jOOQ 和 TypeScript 从最新迁移与 OpenAPI 重新生成；不保留旧客户端兼容层。

导演负责所属项目的整个当前画布。Run 的服务端 projectId 与 owner 定义动态操作范围，不再冻结发送时的节点名单；用户后来新增节点、切换选用版本或调整内容后，导演仍可读取最新目录并管理这些节点，节点来自人工还是任意 Run 不影响权限。读取、文字修订、节点管理、布局和媒体草稿均重新校验当前项目归属、锁定与 Task 互锁；写入前先读取最新状态，再以内容、布局或草稿对应的 CAS 提交，冲突不得覆盖。目录仍只分页提供最新元数据与草稿摘要，完整草稿、正文及图片按需读取，不把全画布内容自动发送给模型。当前选区只表示任务重点。

删除“查看产物”入口、产物归属专用计数、定位查询及 GET `/projects/{projectId}/agents/{agentId}/outputs`。导演不再按输出组、生成来源或用户绑定划分可管理内容；画布节点数与选中数仅作信息。Run 上下文移除顶层 `bindings`、`outputGroupId` 和冻结 `canvasScope`，会话保留公开文字交流与动作记忆，不再自动继承历史 Run 的产物绑定。

删除 `place_artifacts` 工具：动态权限覆盖整个当前画布后，该工具仅剩复用已在画布上的版本，没有独立副作用，继续保留会使模型误以为布局前必须先放置。文字通过 `create_text` 自动落到画布，复制当前节点用 `manage_canvas_node.DUPLICATE`，排列已有节点用 `arrange_items`；Skill 只读输入不会因此变成复制或布局目标。普通用户从资源库恢复节点的界面不受影响。

V26 的历史迁移行为是退休旧模型：删除 `AGENT_IMAGE_INPUT` 关系及 Agent CanvasItem，令剩余 CanvasItem 必须关联 Artifact，关系类型只保留 `MEDIA_INPUT` 与 `MEDIA_DERIVATION`；删除 `agent_binding` 表与 `agent_instance.output_group_id`。Agent 创建/更新和画布 API 同时移除旧绑定、输出组及 Agent 节点字段，并规范化历史创建助手的幂等响应 DTO。仅未修改的安装内置导演预设升级到当前画布措辞，用户自定义预设和实例指令不改写。AgentInstance、Skill 绑定、会话、Run、Task、审批和内容版本继续保留。迁移在项目行锁下连续递增 `event_seq`，为每个助手写一条 `agent.instance.changed`，并为每个受影响项目写一条 `canvas.items.changed`，让升级后的 SSE 补发刷新旧拓扑和助手配置。升级前备份数据库，迁移、后端、OpenAPI 及生成前端类型须同批部署；迁移后旧版后端不兼容，回退须恢复迁移前备份。

唯一的精确输入例外是用户明确选择的 `creativeSkills[].inputs`：按槽位固定的版本保持只读，不随画布当前选用版本改变，也不能据此授权编辑、布局或媒体生成目标。Skill 默认绑定仍是创作方法配置。媒体批次继续冻结目标、参数与精确输入，用户批准后才提交 Provider；UNKNOWN、取消、项目隔离、锁定及 Task 互锁保持原规则。当前 Runtime 只接受 policy schema 7 / system prompt 13 / tool policy 5，不提供旧绑定、旧输出组或旧工具协议的恢复兼容，不能通过重试把旧检查点升级为新权限。此次变更须同步部署后端、OpenAPI 与生成前端类型；删除旧范围模型的代价是旧客户端和旧协议执行不能继续作为当前运行入口。
