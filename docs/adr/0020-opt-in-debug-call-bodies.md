# 默认关闭的调用日志 debug 模式

2026-09-30，用户要求可通过系统设置开启原始调用记录，以排查当前元数据日志无法说明的请求和响应问题。决定增加持久化、默认关闭、仅管理员可写的 debug 模式；开关在调用开始时固定，采集真实 HTTP 地址与正文并按需读取，而不是把业务任务输入当作实际请求。正常列表及服务端结构化日志继续仅保存安全元数据；所有 header 均省略，正文凭证、签名参数与模型私有推理始终脱敏，Mock 不伪造网络请求。

开启可能保存完整提示词、素材和个人/业务数据，并扩大数据库及备份，所以设置必须展示风险。此决定替代规格中尚未实现的“按项目开启并设置短保留期”计划，采用用户指定的系统开关。关闭停止后续调用采集，已有正文保留、旧日志不补录；本次不实现自动清理历史的功能。正文不进入项目导出、SSE 或浏览器持久存储，读取受本人项目权限及 no-store 约束。为限制单次内存开销，每个正文采集上限为 64 MiB，超限、未读完或无法安全解析必须明确标注；不能为了补齐 debug 正文重提生成请求。采集写入失败不改变已有 Provider 结果或 UNKNOWN 恢复规则。

2026-10-01，用户进一步要求可配置保留期，并明确改为“调用日志与执行账本一起删除”。此决定替代上文不自动清理的阶段性范围：系统默认永久保留，管理员主动保存 30 天、90 天或 1–3650 的自定义整数天数后开始清理；缩短保留期影响已有历史，延长或改回永久不会恢复已删除记录。

清理以已结束的完整执行为单位：Agent Run 的调用日志、debug 正文、模型回合、工具执行及所属任务的 Provider 提交账本在同一事务删除；用户直连任务的调用日志、正文和 Provider 提交账本也一起删除。只有 Run/Task 已进入 SUCCEEDED、FAILED 或 CANCELED，完成时间、任务最近更新时间及调用时间均严格早于保留期边界，且没有有效租约，才允许清理。运行中、待处理、UNKNOWN 或其他仍可恢复的执行即使租约过期也保留；任一成员仍需保留则推迟整个执行，不能先删除一半。策略行与候选执行加锁，任务锁被其他事务持有时跳过整个 Run；任一步失败回滚全部删除。LLM 与 Task 模块通过各自应用接口删除所拥有的账本。

Task、Run 业务身份、用户指令和最终结果、用量及 HTTP 幂等记录继续保留，支持任务查询、结果来源与命令重放；画布、ArtifactVersion、Asset 不受清理影响。代价是旧对话的工具动作明细与原始模型检查点不再可查看，后续会话记忆也不再包含已清理的工具摘要。终态执行不能因为账本不存在而再次执行。删除旧账本同时消除了调用列表的旧账本投影，改回永久保留不会让旧日志再次出现，无需隐藏记录或兼容水位。后台每五分钟有界分批执行，启动后首次等待一分钟，恢复模式不启用调度。系统设置按常规、账户安全、调用日志、系统诊断分栏，保留策略及 debug 风险说明位于调用日志栏。

2026-10-01，用户随后明确改为手动执行，认为高频定时清理没有必要。此决定替代上面的定时执行方式：删除调用日志保留调度器，保存时长只更新策略，管理员在系统设置中点击“立即清理”、核对已保存的时长并确认后才执行。请求携带策略版本，每批在策略行锁内再次核对；规则变化返回冲突，避免按旧确认删除更多记录。保持单批完整执行的原子性及恢复保护，每次至多十批/每批 1000 个执行单位，返回实际清理数量和上限标记；达到上限只能再次手动执行。多个批次分别提交，因此后续失败或冲突不能恢复前面已完成的删除；界面明确说明未确认结果及可手动清理剩余记录，不自动重试。没有数据库模型变更，既有永久/30/90/自定义设置保留。

2026-10-01，用户再次明确要求未结束和结果未知的执行也纳入清理，并确认同时停止过期任务的本地执行。此决定替代先前对非终态的永久保护：所有状态按同一保留期判断，未完成执行以创建时间补足空完成时间，整个执行的任务活动和模型/工具/Provider 检查点均需早于边界。清理前把未结束 Run/Task 记为 CANCELED，任务保留 EXECUTION_HISTORY_CLEANED 原因、递增 leaseEpoch 并清空租约，释放仅该 Run 仍持有的项目活动槽；终态成员不改动。项目锁先于 Run/Task 锁，避免与事件事务反向锁死，任何成员锁被跳过则推迟完整执行。状态与项目事件和整组账本删除同一事务，失败一起回滚；旧 Worker、晚到结果和后台恢复不能继续这个执行，也不能凭缺失检查点重新提交。代价是放弃原请求恢复及核对，外部仍可能继续或计费，不承诺停止或退款；用量/幂等、业务身份和已有创作结果保留。界面与确认弹窗明确显示这一影响，手动执行、保存不清理、版本核验、永久默认和批次上限不变。没有新增数据库迁移或依赖。

2026-10-03，用户明确采用“流中汇总，结束后通过独立有界线程池异步入库”的流式 LLM 日志方案，并澄清只需查看模型响应，不需要前端进度。只汇总一份模型公开响应及首片段、首字、总耗时、实际 Usage 等模型调用指标，不采集展示输出及其延迟、批次数、字符数。流式路径的调用开始元数据仍先持久化；HTTP debug 检查点改为本次内存快照，结束时与语义响应、指标一起异步完成同一记录，替代流消费线程上的同步 debug/完成写库。正文仍受调用开始时的 debug 开关、脱敏与权限控制；安全指标始终记录，缺失 Usage 不估算，异常与本地取消保留部分响应，模型私有推理及原始 SSE 继续排除。V3 追加迁移清除旧日志中的重复输出和相关指标，将指标 Schema 升至版本 2，保留已有模型响应与用量。业务模型回合与用量账本不由该日志替代。选择普通日志的尽力保存以隔离数据库延迟，代价是进程退出、队列拒绝或写入失败时快照可能丢失、调用行可能未完成；只告警，不阻塞流、不重发模型、不引入 MQ。日志清理与异步完成在现存调用行锁上互斥，晚到写入不能重建已删除记录。


2026-10-03，用户随后要求普通及流式 LLM 的 debug 日志保留实际完整内容，并明确认证凭据继续隐藏。此决定替代上文对 LLM debug 的私有推理及原始 SSE 排除：实际 HTTP 请求/响应正文、SSE data 事件和 SDK 解析的模型文本、工具调用及元数据均可保存，包含 reasoning、analysis、thought 等字段及文本中的推理标签。鉴权字段、已知请求凭据、Cookie、私钥和带签名地址仍移除，所有 HTTP header 继续不采集；媒体 debug 原有过滤规则不变。日志默认关闭、开始时固定开关、本人项目管理员读取、no-store、关闭清除 Query 缓存、手动保留清理及异步尽力保存继续适用。公开 Agent 回答、项目 SSE、模型运行检查点、普通应用日志与项目导出继续过滤私有推理，不用 debug 协议替换恢复协议。

每个 HTTP 正文最多 64 MiB，模型协议汇总最多 1 MiB；超限或未读完标记部分内容，无法解析的 JSON / SSE data 省略该正文或事件，不能为了补齐日志重新调用模型。实际 SSE 保存 SDK 尚未映射的字段，模型协议汇总保存已收到的回复/工具前缀和观测到的属性；二者分别展示。界面默认恢复 Prompt / Completion 格式化视图，支持 Chat Completions JSON 与 schemaVersion=1 的模型汇总，未采集的请求不编造 Prompt。原文切换可查看完整已采集内容，实际用量缺失保持未记录。本次无数据库迁移或接口字段调整；更新 OpenAPI 描述、生成 TS 与四语言提示，前后端需同时更新。旧日志不补录，已经移除的内容无法恢复。
