# 默认关闭的调用日志 debug 模式

2026-09-30，用户要求可通过系统设置开启原始调用记录，以排查当前元数据日志无法说明的请求和响应问题。决定增加持久化、默认关闭、仅管理员可写的 debug 模式；开关在调用开始时固定，采集真实 HTTP 地址与正文并按需读取，而不是把业务任务输入当作实际请求。正常列表及服务端结构化日志继续仅保存安全元数据；所有 header 均省略，正文凭证、签名参数与模型私有推理始终脱敏，Mock 不伪造网络请求。

开启可能保存完整提示词、素材和个人/业务数据，并扩大数据库及备份，所以设置必须展示风险。此决定替代规格中尚未实现的“按项目开启并设置短保留期”计划，采用用户指定的系统开关。关闭停止后续调用采集，已有正文保留、旧日志不补录；本次不实现自动清理历史的功能。正文不进入项目导出、SSE 或浏览器持久存储，读取受本人项目权限及 no-store 约束。为限制单次内存开销，每个正文采集上限为 64 MiB，超限、未读完或无法安全解析必须明确标注；不能为了补齐 debug 正文重提生成请求。采集写入失败不改变已有 Provider 结果或 UNKNOWN 恢复规则。

2026-10-01，用户进一步要求可配置保留期，并明确改为“调用日志与执行账本一起删除”。此决定替代上文不自动清理的阶段性范围：系统默认永久保留，管理员主动保存 30 天、90 天或 1–3650 的自定义整数天数后开始清理；缩短保留期影响已有历史，延长或改回永久不会恢复已删除记录。

清理以已结束的完整执行为单位：Agent Run 的调用日志、debug 正文、模型回合、工具执行及所属任务的 Provider 提交账本在同一事务删除；用户直连任务的调用日志、正文和 Provider 提交账本也一起删除。只有 Run/Task 已进入 SUCCEEDED、FAILED 或 CANCELED，完成时间、任务最近更新时间及调用时间均严格早于保留期边界，且没有有效租约，才允许清理。运行中、待处理、UNKNOWN 或其他仍可恢复的执行即使租约过期也保留；任一成员仍需保留则推迟整个执行，不能先删除一半。策略行与候选执行加锁，任务锁被其他事务持有时跳过整个 Run；任一步失败回滚全部删除。LLM 与 Task 模块通过各自应用接口删除所拥有的账本。

Task、Run 业务身份、用户指令和最终结果、用量及 HTTP 幂等记录继续保留，支持任务查询、结果来源与命令重放；画布、ArtifactVersion、Asset 不受清理影响。代价是旧对话的工具动作明细与原始模型检查点不再可查看，后续会话记忆也不再包含已清理的工具摘要。终态执行不能因为账本不存在而再次执行。删除旧账本同时消除了调用列表的旧账本投影，改回永久保留不会让旧日志再次出现，无需隐藏记录或兼容水位。后台每五分钟有界分批执行，启动后首次等待一分钟，恢复模式不启用调度。系统设置按常规、账户安全、调用日志、系统诊断分栏，保留策略及 debug 风险说明位于调用日志栏。
