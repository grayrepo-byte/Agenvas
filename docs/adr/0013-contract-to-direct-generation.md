# ADR 0013：收缩到直连生成，移除镜头、角色、场景与执行计划

状态：接受（2026-09-27）。本决策作废 [ADR 0003](0003-integer-business-video-seconds.md) 与 [ADR 0005](0005-canvas-interaction-redesign.md) 的若干部分，见下文「作废的既有决定」。

## 背景

用户判断画布上的**角色、场景、镜头**三类节点没有用，明确要求连同对应功能一并删除，并接受这会让产品主干从「三镜头规划」改为「直连生成」。

这不是清理残留代码，而是一次**产品决策变更**：

- 三类产物此前是 P0 交付物，有完整内容 Schema、真实数据库外键（`plan_step` 到 `shot` 的外键）与已通过验收的专项测试（任务清单 T06 / T07 / T24，以及「手工完整操作一个三镜头项目」的 M1 门禁）。
- 「三镜头规划 → 图片审批 → 视频审批 → 按镜头顺序导出」是主规格的首版链路；「局部重做」是其中的独立条目。

因此按项目约束「产品决策变更时同步更新规格与 ADR」，本 ADR 与主规格、约束文档、任务清单同批更新。

## 决策

**1. 创作产物收缩为文字、图片、视频三类。** `Artifact.Kind` 只保留 `TEXT` / `IMAGE` / `VIDEO`，取消 `CHARACTER` / `SCENE` / `SHOT`。画布卡片继续以 `CanvasItem.subjectType`（`ARTIFACT | AGENT`）区分主体，与产物类型无关，不需要改动。

**2. 移除整条三镜头规划主干。** 删除执行计划领域（计划与步骤、计划审批、计划恢复上下文、媒体计划校验）、关键帧选择表与服务、以及镜头作用域的「局部重做」——它的唯一目标就是镜头，Run 创建请求上的重做参数同样移除。**「局部重做」因此退出首版范围。**

**3. 移除媒体导出，保留项目导出清单。** 仓库此前有两个都叫「导出」的东西，本决策后必须区分：

- **媒体导出**（按顺序拼接无声视频，强依赖镜头）→ 删除，连同 `Task.Kind.MEDIA_EXPORT` 与 `TaskOrigin.PROJECT_EXPORT`。
- **项目导出清单**（导出项目的非密钥配置、产物历史与媒体元数据，用于备份与迁移）→ **保留**，只移除其中已不存在类型的字段白名单分支。它服务于「可自托管」这个项目目标。

因此主规格首版链路中的「无声顺序导出」退出范围。

**4. Agent 工具目录从 14 收到 8。** 删除 `create_character`、`create_scene`、`create_shots`、`link_artifacts`、`propose_generation_plan`、`propose_export`。保留四个只读工具与 `create_text`、`revise_artifact`、`place_artifacts`、`arrange_items`。

**Agent 因此不再有任何媒体生成或审批能力**，本次不新增替代工具。媒体生成一律由用户在卡片上直连发起，与 [ADR 0006](0006-direct-media-task-boundary.md) 的既有划分一致。Agent 能力重塑留待后续独立变更。

**5. 移除「等待审批」运行状态与 Run 的媒体预算。** 六个工具删除后，`WAITING_APPROVAL` 已无任何生产方，整套两阶段审批机制成为死骨：`AgentRun.Status`、`RunAction.Status`、`ToolResultStatus` 中的该取值，以及 Run policy 的 `maxShots` / `maxImages` / `maxVideos` 一并移除。`WAITING_TASKS` 保留。

**6. 生成入口只有直连。** 图片/视频：卡片「运行」受理固定输入的 `USER_DIRECT` 任务；文字：文字卡片生成受理文本任务。两条路径原本就不经过 Run、执行计划或审批。

**7. 数据库迁移只增不改。** 新增一条迁移：收窄产物类型与任务种类/来源约束；硬删除三类产物行及其不可变版本、画布卡片与连线；删除其流水线产生的任务及依赖账本；drop 执行计划、计划步骤、计划审批、关键帧选择、导出提案、语义关系表与遗留一次性升级表；删除任务上指向计划的列与外键；把无计划可批的 `WAITING_APPROVAL` Run 结束并释放项目活动槽位；收窄 Run 状态约束。

**8. Mock 模式保留可用的 Agent 回合。** Mock 网关接受工具定义并只回文本（模型不调用工具是合法行为），因此 Agent 回合能正常开始与结束；它从不发出工具调用，也就不产生任何业务副作用。需要真实工具执行的验证必须使用配置模型或测试内的假网关。

## 作废的既有决定

- **ADR 0003**（创作和导出使用整数秒）：关于「镜头」时长范围与「导出区间」的部分作废——镜头与顺序导出都不再存在。视频创作时长仍为整数秒，其范围由媒体能力决定。
- **ADR 0005**（画布交互与直接媒体运行）：作废以下部分——创建菜单的「七类业务对象」（现为文字、图片、视频与 Agent 四类）；角色、场景、镜头的节点下方编辑区；「待审计划与关键帧操作嵌入所属 Run」；「Agent 提出的付费媒体计划仍须人工审批」；媒体卡片需先选关键帧才能生成视频的说法。该 ADR 关于连线交互、选择与手形工具、媒体卡片草稿与结果分离、直接媒体运行、并行与排队、调用日志只读的决定**继续有效**。
- **[ADR 0006](0006-direct-media-task-boundary.md)**（直接媒体任务不创建 AgentRun）：继续有效，并且**成为唯一的媒体生成路径**，其「具体表/API 迁移待实施设计」已由直接媒体与直接文本任务落地。

## 后果与遗留限制

- **Agent 收缩后只做文本与画布编排**：读项目上下文、创建与修改文字产物、把产物摆到画布上。它不再提出计划、不再触发生成、不再需要审批。
- **计划步骤任务与媒体导出任务被整批删除**：收窄后的 `task.kind` 已无法表示 `MEDIA_EXPORT`，因此**已完结**的导出任务也不能保留，其提交账本、调用记录与用量记录随外键一并删除——`issue #5` 只写了「删除媒体导出的待处理任务」，此处范围更宽，原因即上面这条约束。计划步骤的任务同样整批删除（其中「新媒体输出槽位」形态的任务没有产物目标，只能按 `plan_id` 识别）。
- ~~**`keyframeVersionId` 作为 VIDEO 内容字段名保留。**~~ 此项已由 [ADR 0014](0014-canvas-item-media-branches-and-versioned-image-inputs.md) 替代：本地开发创作数据整体清空后，视频改用可表达纯文本、首尾帧和有序多图的冻结媒体输入，不保留单图兼容字段。
- **用量数量 schema 仍带 `exportCount`，恒为 0**。它属于审计账本的既有 JSON 形状与合约，本次不改。
- **迁移不可逆**：三类产物行及其版本被硬删除，升级前应确认没有需要保留的资产。
- 规格、约束文档与任务清单中已验收的三类产物条目随本决策撤回；Mock 演示剧本（三镜头）随之删除，Mock 模式仍可脱离外部模型启动并跑通直连图文视频。
