# 本地字幕识别与交换模块

本模块使用本地 whisper.cpp 从固定音视频版本的第一条音轨识别可人工校正的字幕草稿。已提供识别适配、SRT/WebVTT 交换、校正校验、时间线映射、独立 Task、项目权限、API 和持久化，以及独立字幕校正组件。剪辑器已接入来源字幕校正，预览、MP4 烧录请求和成片 SRT/VTT 使用同一份时间映射；真实模型识别仍须单独验收。

## 本地引擎与模型

默认关闭，管理员可在系统设置启用，并单独触发官方Tiny模型下载。托管引擎由固定版本Linux镜像构建提供，模型持久卷、资源与恢复规则见[ADR 0086](../adr/0086-managed-local-asr-model-download.md)。实际外部下载和新镜像构建尚未验收。

手动部署仍可自行准备原生 `whisper-cli` 可执行文件和兼容的本地 GGML 模型，然后通过部署配置传入绝对路径。例如：

```yaml
agenvas:
  subtitles:
    local-asr:
      executable: /usr/local/bin/whisper-cli
      model: /models/ggml-base.bin
      timeout: 10m
      threads: 2
```

这些是部署者选择的路径示例，不表示镜像已经包含相应文件。手动模式不安装引擎、不下载或转换其模型。托管模式只响应管理员单独的下载命令；两种模式均不启动外部模型服务，不向其发送素材。不要配置 Shell 或 Python 包装脚本；执行器直接启动原生二进制，不经过 Shell，且不继承数据库、Provider 或其他进程环境凭据。引擎的标准输出和错误输出不进入普通日志或 API。

可用性检查只检查本地配置、可执行文件和可读非空模型文件，不能证明模型格式、语言覆盖或内存适配正确。缺少路径返回 `NOT_CONFIGURED`；不存在的引擎/模型具有独立不可用状态。错误向上游暴露稳定分类，包含未配置、不可用、繁忙、输入无效、无音轨、超时、失败、输出无效和临时空间超限，不包含原始进程输出或文件路径。

模型格式和命令行协议以 [whisper.cpp CLI](https://github.com/ggml-org/whisper.cpp/tree/master/examples/cli) 为准。配置的模型必须来自部署者信任的来源，保留版本、来源、校验和及适用许可证；引擎和模型的许可证均须分别核对，不因 Agenvas 的开源许可证而自动获得再分发授权。中文等非英语识别须选择支持相应语言的多语言模型；`.en` 模型限英语。请求支持明确的语言码或 `auto`，自动语言模式不把请求值冒充实际检测出的语言。模型具体识别效果、错字、音乐/静音中的幻觉均须人工复核，不承诺逐字准确、说话人分离或自动翻译。

## 资源与执行边界

- 同一应用实例固定一个识别槽位，包括音频解码；原生执行槽位已占用时返回 `BUSY`，专用 worker 每次只认领一个任务，不建立无界内存执行队列。不同来源的持久 `READY` Task 可以等待且可取消；同一草稿已有待执行或执行中的任务时拒绝重复受理。
- 强制 CPU 模式，默认 2 个线程，配置范围 1–4；每次只处理一个固定来源，不隐式提交其他媒体。
- 单个来源最长 10 分钟。默认总体超时 10 分钟，最大可配置为 30 分钟；解码、探测和识别共享总体截止时间。进程轮询检查取消和磁盘预算，执行中续接调用者提供的任务心跳；租约回调异常直接传播。
- 私有临时目录使用 `0700`，其中 16 kHz、单声道、16-bit PCM WAV 和识别输出总量上限 64 MiB，字幕文件上限 2 MiB。拒绝临时目录中的符号链接。成功、失败和取消均清理本次目录，不修改原素材、模型或用户缓存。
- 第一音轨解码保留源媒体时钟上的开头静音，允许音轨短于视频；音轨长度不能超出固定来源时长。解码不访问网络协议，不用音量活动或脚本文字代替语音识别。
- 应直接配置原生 CLI。进程取消时终止原生进程；系统允许时也清理其后代。部分受限运行环境禁止进程枚举，这时仍必须终止已启动的原生进程并保留原取消或超时原因。

原生模型内存不包含在 Java 堆内。当前 Compose server 的 1,536 MB 限额还承载 JVM、FFmpeg 及其他并行任务；单并发不等于该内存一定足够。模型大小、加载峰值、实际长音频以及与应用/合成并行时的内存均须在目标机器上测量；未做这些测量前不承诺默认容器可运行任意模型。官方模型资源参考见 [whisper.cpp](https://github.com/ggml-org/whisper.cpp#memory-usage)。不自动放宽容器内存限制。

## 字幕与时间模型

`SubtitleTrack` 固定 `sourceVersionId`、来源时长、请求语言和字幕列表。时间使用来源媒体的整数毫秒，区间包含起点、不包含终点。人工校正仍保留相同的来源版本，禁止越界、空文字、非法控制字符或单条超过 500 字符。一个来源最多 5,000 条；这不绕过合成接口当前部署的字幕数量限制。空列表是合法的无对白草稿。

SRT/WebVTT 支持 UTF-8 BOM、CRLF、多行字幕、重叠字幕；导出按时间稳定排序，不改写原草稿的顺序。WebVTT 支持提示标识、常见时间格式、`NOTE` 和时间行的显示设置；显示设置不进入编辑数据。文件中的文字作为纯文本处理，导出转义 `&`、`<`、`>`。未支持的文件结构、超出源时长的字幕和空行分隔的非法单条文字明确拒绝，不静默丢失或截断校正内容。

`mapSubtitleTrack` 每次从固定来源时间重新计算视频片段投影，按 30fps 成片网格考虑裁切、变速、重排、重复使用与不完整尾帧。`mapSubtitleTrackToAudio` 使用实际配音时间表中的静音裁切、位置、速度和结束边界。两者都拒绝来源版本不匹配，不能复用另一媒体版本的识别结果；映射不修改来源字幕草稿。

## 保存、任务与接口

V60 只新增 `subtitle_draft` 并扩大持久任务类型约束，保留原项目、媒体和任务数据；jOOQ 由一次性 PostgreSQL 执行迁移后生成。每个项目的每个固定来源版本拥有一份草稿，保存和文件导入携带 `expectedVersion` 并检查 CAS 更新行数。识别原始结果保存在 `SUBTITLE_TRANSCRIPTION` 的终态输出中，人工校正不改写该结果。

识别受理以项目范围内的 `Idempotency-Key` 幂等，固定来源版本、Asset、时长、语言和待应用草稿版本。在专用单槽执行器中读取已授权媒体并执行本地 ASR，耗时操作不持有数据库事务。识别使用既有 Task 租约、epoch、心跳和终态规则；本地推理没有外部提交和费用，过期租约可重新认领，旧 epoch 的任务与草稿写回在同一事务回滚。取消 READY/RUNNING 任务设置持久取消并推进 epoch，迟到结果不覆盖校正。

人工校正在识别期间仍可保存。完成时只有受理时固定的草稿版本和最近任务身份同时匹配才自动应用结果；否则 Task 仍保留成功识别结果并明确 `applied=false`。用户可显式把该结果放入校正草稿再保存。识别、取消和草稿事件不包含文件路径、引擎输出或字幕正文；`subtitle.draft.changed` 使用既有项目序号补发和缓存失效机制。

独立字幕组件使用 TanStack Query 保存服务端投影，按对话框隔离的 Zustand store 保留未保存的校正和 CAS 基线。`flush()` 在宿主窗口关闭、来源切换或导出前保存校正；非法时间、保存失败或冲突时返回失败并保留编辑内容，宿主必须阻止相应动作。冲突后的覆盖保存必须由用户明确选择。同一来源在不同片段/配音组合的查询缓存同步校正，并按 CAS 版本拒绝迟到的旧读取；任务终态须等待草稿刷新成功才解锁成片，后台刷新和刷新失败均阻止旧字幕导出。组件单次只渲染 50 条字幕；文件导入在读取前检查大小，并严格解码 UTF-8。

接口前缀为 `/api/v1/projects/{projectId}/subtitles`，使用 Session、CSRF 与项目所有者授权：

- `POST /`：按固定来源创建或重新打开草稿；重复打开不清空校正。
- `GET /?sourceVersionId=...`：按最多 100 个固定来源批量读取，整批最多 10,000 条/8MiB（含每稿 1KiB 元数据余量）；超额返回 `SUBTITLE_BATCH_TOO_LARGE`/413，不返回部分字幕。
- `GET /capabilities`：读取安全的本地可用性和协议边界，不返回路径。
- `GET /{id}`、`PUT /{id}`：读取或 CAS 保存校正。
- `POST /{id}/import`、`GET /{id}/export?format=SRT|VTT`：按来源时间导入/导出。
- `POST /{id}/recognition`：显式受理固定版本的识别任务。
- `POST /{id}/recognition/cancel`：取消该草稿固定的任务身份。
- 任务进度与独立结果复用既有 `GET /projects/{projectId}/tasks/{taskId}`。

接口权威定义见 OpenAPI。剪辑器在关闭、来源替换、移除相关输入和导出前调用 `flush()`；字幕保存或受理中的请求锁定编辑与关闭，后台识别本身仍可在关闭后继续。成片自动字幕等待固定来源的任务状态和实际配音时间表；用户可按来源排除字幕，避免多份对白重复叠加。手动成片字幕保持绝对时间。

## 当前验证范围

协议测试通过受控假执行器写入明确标记的合成字幕；真实 FFmpeg 生成并解码本地音频/延迟音轨视频。原生进程专项使用受控短进程验证超时、取消、环境隔离、输出抑制及临时空间限制。它们不是 Whisper 模型识别验收。

真实 PostgreSQL 验证独立草稿保存与重开、CAS、项目隔离、SRT/VTT 交换、幂等受理、取消、识别期间人工校正、租约恢复和旧 epoch 回滚。升级测试单独验证 V59→V60 保留原项目。前端独立组件通过受控 HTTP 测试保存与重开、失败保留、来源切换保护、显式冲突处理、受理/取消和文件导入；项目事件测试验证重复与游标缺口恢复。

真实 Chrome 生产构建验证三种尺寸的校正、保存失败与关闭重开，以及原生 SRT 文件读取和 SRT/VTT 下载正文。真实 FFmpeg/libass 在无网络、1536MB、2 CPU 的现有服务端镜像中生成94秒合成素材成片：91500–93500ms 的修订中文字幕在区间内出现，前后采样无文字。此项未调用 ASR，容器限制也不代表完整 Java 应用加识别模型的并行峰值已测。真实模型的中文准确度、静音/纯音乐、晚段对白、耗时/峰值内存及 amd64/arm64 识别兼容仍未运行；本机无可调用的 whisper.cpp 引擎和兼容 GGML 模型，仅有不同格式的 faster-whisper 缓存。

### 批量资源与恢复

浏览器顺序读取批次，并对本次全部来源累计检查 10,000 条/8MiB；超额需减少剪辑器中的来源或字幕量，不能通过拆批绕过或静默丢字幕。校正顺序保存，任意失败保留对应草稿。完整列表离开当前来源组合即回收；后台识别状态串行读取并剥离正文，只在用户点击采用结果时读取当前完整结果。任务受理后的草稿同步失败不会丢失已受理身份、取消入口或导出阻塞。来源内 TAB 转为成片中的空格、CRLF/CR 转为 LF，原来源草稿不变。预算是有界协议与缓存策略，不是浏览器或整个应用峰值内存实测。


## 托管模型设置与代理

在“系统设置 → 通用 → 本地语音识别”保存启用后，再单独点击“下载模型（30.7 MiB）”。页面显示Tiny多语言量化模型的中文/口音/静音误识别限制、固定来源、MIT、SHA-256、进度和安全失败码，并提供取消、显式重试和本地检查。检查不下载、不推理；模型已保存不等于资源或真实识别验收通过。手动模式不显示托管下载按钮，不把未知模型标记为已校验Tiny。

托管入口为管理员Session/CSRF保护的 `/api/v1/settings/local-asr`，GET读取、PUT保存开关，POST `/download`、`/cancel`、`/check`。默认关闭；升级的手动部署也需明确启用一次。`agenvas.subtitles.managed.mode` 默认为AUTO：模型路径等于托管目录模型名时采用托管模式，否则使用已有手动路径。部署者可明确配置MANUAL；不会下载或覆盖自配模型。

Docker默认卷 `asr-models:/opt/agenvas/asr` 保存完整模型、许可证、单个私有下载暂存和卷锁。已完成模型保留；失败/取消清理本次暂存。过期执行租约转为INTERRUPTED并清理可独占的暂存，需用户重试。已明确受理但尚未认领的QUEUED仍可以执行。下载不自动改为断点续传。备份此缓存可避免重新下载，但不能替代业务数据库和素材备份。

复用部署者现有公共下载代理配置。可在私有Compose override的server.environment内设置，例如：

```yaml
AGENVAS_PUBLIC_DOWNLOAD_PROXY_TYPE: HTTP
AGENVAS_PUBLIC_DOWNLOAD_PROXY_HOST: host.docker.internal
AGENVAS_PUBLIC_DOWNLOAD_PROXY_PORT: "7890"
```

也支持该配置的HTTPS、SOCKS5和可选DoH；端口和可达宿主由部署者按Clash实际配置决定，不猜测或自动启用代理。原始宿主环境变量不会自动进入Docker，须明确传给容器。沿用ADR0079，不过滤私网/Fake-IP或增加CDN域名名单；仍有URL格式、无凭据请求、重定向次数、超时、精确大小与SHA-256限制。实际代理连接与官方模型下载尚未验证。

真实验收仍待另行授权：模型32152673字节，来源为ADR0086固定HF修订；Linux引擎使用官方v1.9.5固定Git提交。执行动作包括单独构建 `whisper-build` 目标（会获取Git源码并安装cmake/g++/git/ca-certificates工具链）、独立容器内下载/校验模型及非隐私中文/静音/音乐/晚段对白推理。源码Git对象和apt工具链的实际下载量尚未测，授权前需据实际缓存和包清单列明；不能把32MB模型当作全部构建下载量。不得因此自动构建、部署或重启现有服务。还需测Linux双架构、资源限制失败、持久卷重开、并行FFmpeg/JVM的RSS峰值和耗时。
