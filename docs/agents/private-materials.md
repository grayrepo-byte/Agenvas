# 开发资料与公开内容

真实 Provider 排障、使用真实素材、创建开发证据、提交变更，以及发布或重建仓库前，读取本指南。这里只规定开发资料的处理方式；产品安全行为以规格与 ADR 为准。

## 开发与排障

- API Key、Token、Cookie、认证请求头、加密主密钥、数据库密码、私钥及带凭据的下载地址均属于敏感信息。真实值通过服务端配置或仓库外私有文件传入；源码、测试夹具、文档、提交信息及 Issue/PR 使用占位符或明确标注的合成数据。编码、加密或过期不代表可以公开。
- 只读取任务必需的配置字段，输出前脱敏；不打印完整环境变量、凭据文件或认证请求头。真实凭据不放入命令行参数、URL 或发往第三方扫描服务的请求。
- 扫描器使用脱敏输出；报告只列文件、行号、风险类型与处理结果，不复述敏感值。

## 保存开发证据

- 真实调用回执、原始日志、HAR、数据库备份、项目导出、用户素材和开发截图默认保存在仓库外私有目录。目录权限为 `0700`，文件权限为 `0600`，或采用平台等价权限。
- 只清理本任务创建的临时文件；用户现有数据与备份按用户授权处理。
- 新增文档或产物前核对 [`.gitignore`](../../.gitignore)。不通过 `git add -f` 或放宽忽略规则提交被排除的开发资料；`.env.example` 使用空值或不可用占位符。

## 整理公开内容

- 公开文档只保留协议、行为、合成示例及验证范围。真实项目/任务/资产 ID、账号与账单、个人邮箱/姓名、本机目录和实际部署地址替换为占位信息。官方公开 API 地址、公开工作流/应用 ID 可作为协议示例，但不与私人执行记录混用。
- 同步规格、ADR 或验收状态时，保留脱敏行为摘要，移除私人证据链接；不重新提交已清理的回执和截图。
- 拟提交截图、媒体或其他二进制时，优先使用 Mock/合成素材，并检查可见内容与元数据中的账号、凭据、私有素材、路径和定位信息。图片经过这些检查后才能判定可公开，文本扫描无命中不能代替检查。

## 提交、发布与重建

1. **提交前**：检查本次差异和新增文件的凭据与隐私信息；图片同时检查画面和元数据。逐项复核凭据扫描命中，区分测试值和真实信息；不能用宽泛白名单屏蔽未确认的命中。
2. **发布或重建前**：检查待发布文件、拟保留的 Git 历史与引用、提交作者/提交者姓名邮箱，以及拟公开的日志和附件。报告据实列明未扫描的范围。
3. **重建时**：从脱敏目录初始化，不复制旧 `.git`、Git bundle、私有备份或运行记录。

## 发现泄露

先阻止可疑内容进入提交或发布，完成脱敏后复查。`.gitignore` 不影响已跟踪文件，删除当前文件也不清除历史。

真实凭据曾被提交或发布时，说明暴露范围并建议撤销或轮换；不得擅自调用供应商验证密钥有效性。历史重写、仓库重建及远端操作按用户授权执行。
