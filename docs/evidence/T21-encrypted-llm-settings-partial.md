# T21 管理员 LLM 配置：部分实现

2026-09-23。Flyway V28 增加单一活动配置与不可变历史版本；管理员 `GET/PUT /api/v1/settings/llm` 使用 `expectedVersion` 做并发控制。写入前校验端点、模型 ID 与 Key；Key 通过独立部署主密钥使用 AES-256-GCM、随机 nonce 和版本关联数据加密。读取只返回掩码，响应禁止缓存。React 设置页不使用浏览器持久存储或 Query mutation 保存 Key，成功后清空输入。默认只允许公共 HTTPS 端点；本地 HTTP 仅在显式开启后接受精确 `127.0.0.1`。

配置写入测试使用真实 PostgreSQL：鉴权和 CSRF、内网/元数据地址拒绝、数据库密文和篡改拒绝、保留旧配置、预期版本冲突、并发只成功一次。前端定向测试覆盖单次提交和保存后清空输入。全量构建/测试结果以本次交付汇报为准。

后续进展：configured 模式的 `ChatGateway` 现在优先读取活动数据库版本；Run 创建时在策略快照中固定模型配置来源与版本，回合请求在事务内拒绝来源或版本漂移（包括两种来源碰巧同为版本 1）。未验证的数据库配置不发出模型请求。假 HTTP 服务与 PostgreSQL 测试验证数据库配置解密后动态构造 Spring AI 客户端，并使用所选模型、端点及凭证；测试中的能力标记仅由 fixture 直接写库，产品 API 不提供这种捷径。

2026-09-23 再进展：`POST /api/v1/settings/llm/diagnose` 要求管理员会话、CSRF、指定版本和明确的可能计费确认。它只用合成 nonce、无业务副作用的测试工具，通过“模型请求工具 → 服务端手工回填原 tool_call_id → 下一轮响应包含 nonce”完整往返后，才对仍活动的配置版本做 CAS 能力标记。假 HTTP＋真实 PostgreSQL 测试覆盖鉴权、费用确认、版本冲突、成功双回合、失败不放行及重复已验证调用不重新计费。Spring AI 客户端的出站请求走独立 OkHttp 防护：只允许配置的原始主机/端口和 Chat Completions 路径，逐次 DNS 解析结果必须为公网地址或显式启用的精确 `127.0.0.1`，禁代理、禁重定向与连接自动重试；单元测试覆盖重定向、错误路径/端口、元数据地址、100.64/10 以及本机例外。新增 OkHttp 4.12.0 直接依赖，与既有 Spring AI 解析版本一致。OpenAPI 加法新增诊断路径/请求及 422、502 响应，前端生成类型同步；旧客户端不使用新路径不受影响。

2026-09-23 续：主密钥支持 `keyVersion` 对应的显式历史解密密钥环；新配置只用当前密钥加密，旧配置可保留原 keyVersion 解密，缺失历史密钥返回稳定的 `CREDENTIAL_KEY_VERSION_MISSING`。LLM Run 从持久快照取来源与版本，数据库中已验证的旧配置可继续按旧端点/旧凭证调用；活动配置轮换不会替换旧 Run 的模型。环境变量配置无持久旧版本，变更后仍阻断。单元测试验证新旧主密钥、认证篡改、缺失旧密钥；假 HTTP＋PostgreSQL 测试验证活动版本变更后旧模型仍使用旧凭证。Compose 已透传当前 keyVersion 与历史密钥环；操作说明见 README。
