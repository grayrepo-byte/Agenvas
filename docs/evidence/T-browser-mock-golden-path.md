# 浏览器 Mock 三镜头黄金路径：阶段性证据

2026-09-23。使用与现有 `agenvas` Compose 项目隔离的 `agenvas-browser-e2e` 项目、独立 PostgreSQL/Asset 卷和本机 18080/18088 端口，构建当前代码并确认三个服务健康。浏览器以 1440×900 桌面视口打开本机 Web；此尺寸满足当前画布编辑的 1280px 门槛。测试管理员与项目只创建在隔离实例中。

浏览器实际完成：登录 → 创建横屏项目 → 添加 Creator Agent → 输入三镜头指令并检查运行范围 → 确认运行 → 审批三张图片计划 → 分别选择三张已归档图片的精确关键帧版本 → 审批三段视频计划 → 在顺序导出 UI 按镜头 1、2、3 加入视频 → 提交导出 → 页面显示“已完成”与“下载 MP4”链接。图片与视频卡片均显示演示标记；计划审批前不自动提交媒体任务。实际下载该导出 Asset 的 HTTP 状态为 200，文件 91,178 字节；FFprobe 显示 H.264、1280×720、15.000 秒，只有视频流、无音轨。

浏览器验收发现并修复两个问题：React Flow 卡片只有 CSS 宽高、没有 `initialWidth`/`initialHeight` 时会在真实浏览器保持 `visibility:hidden`，导致保存成功但画布空白；修复后重建 Web 容器、刷新项目，Agent 卡片在截图与可访问性树中实际可见。视频阶段 Task 已存在时不再显示图片关键帧选择面板；该条件有前端组件测试，尚未在新构建容器中重演视频进行二次浏览器验收。

前端 `tsc --noEmit`、ESLint、Vitest（25 项）和 Vite build 通过；构建仍提示主 JS 包超过 500 kB。此路径使用确定性 Mock 模型与 Mock 媒体，并非真实 LLM/ComfyUI；浏览器下载点击受本机浏览器检查工具瞬时错误影响，未取得浏览器下载管理器记录，因此另用同项目已登录 HTTP 会话下载实际 MP4 并探测媒体属性。不能据此勾选真实 Provider、故障恢复或发布门禁。

验收后已关闭临时浏览器标签并复原视口，只对本轮 `agenvas-browser-e2e` 项目执行 Compose `down -v`，移除其三个容器、网络和两只测试卷；原有 `agenvas` 项目的三个服务再次核对为健康。`docker compose config --quiet` 与 `git diff --check` 通过。
