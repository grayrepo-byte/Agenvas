# T28 SSE 反复连接与释放（阶段性）

2026-09-24。`ProjectEventStreamPostgresIT` 在真实 Tomcat＋PostgreSQL 17.11 上完成管理员登录后，通过 Java HTTP 客户端进行三轮各 20 条同项目 SSE 连接；每条读取一条持久事件后关闭响应流。每轮以管理员可读的 `agenvas.sse.connections.active` 指标检查，必须在 45 秒内回到 0 后才继续下一轮。匿名指标仍返回 401，指标不含项目/用户/连接 ID 标签。定向 `./mvnw -q -Dit.test=ProjectEventStreamPostgresIT verify` 退出码 0，60 次连接均未触发 64 连接上限或遗留活动订阅者。

首次以 25 秒为观察窗的测试失败：20 条关闭的客户端流中，仍有 6 条计为活动。延长至 45 秒后连续三轮均归零，说明服务端可能需下一次心跳/异步写入才感知被动断开，不能宣称立即释放。没有为通过测试而改短主规格规定的默认 15 秒心跳；周期性数据库补发与有界发送队列保持不变。

随后执行全量后端 `./mvnw -q verify`，退出码 0；Surefire/Failsafe XML 报告未发现失败或错误，`git diff --check` 通过。

这证明本机 60 次真实 HTTP 生命周期未出现持续增长的订阅者计数，不是长期 JVM 堆、文件描述符或代理连接的压力测试，也未覆盖浏览器预览资源。T28 的完整内存稳定性门禁仍未完成。
