# 本地成片资源预算

本地剪辑默认支持 10 分钟、60 镜、300 句配音和 2000 条字幕。不同源素材合计默认 2 GiB，单个音视频仍最多 10 分钟；成片输出仍最多 500 MiB。默认编辑器选择 720p，支持的最高分辨率由服务端决定。此能力不调用模型或外部生成服务。

登录后的剪辑器从 `GET /api/v1/projects/{projectId}/video-compositions/capabilities` 读取实际预算，并用于添加、时间线裁切、预览和导出检查。读取失败可以重试，草稿保留。超过当前时长或素材预算必须调整配方，不会静默删镜头、截断对白或字幕。输出大小取决于内容复杂度，服务端编码中仍可能因空间、文件大小或超时失败。

在 Spring Boot 配置中使用以下属性，或采用对应的大写下划线环境变量。值在应用启动时校验，超出绝对上界直接拒绝启动。

| `agenvas.video-composition.limits` 下的属性 | 默认值 | 范围 |
| --- | --- | --- |
| `max-duration-ms` | 600000 | 100–600000 |
| `max-shots` | 60 | 1–120 |
| `max-lines` | 300 | 0–600，所有镜头合计 |
| `max-subtitles` | 2000 | 0–5000 |
| `max-source-bytes` | 2147483648 | 1–8589934592 |
| `max-output-bytes` | 524288000 | 1024–524288000 |
| `max-scratch-bytes` | 2147483648 | 1048576–8589934592 |
| `min-free-bytes` | 67108864 | 0–8589934592 |
| `timeout` | PT15M | PT0.001S–PT1H |
| `preview-timeout` | PT30S | PT0.001S–PT2M |
| `scratch-root` | JVM 临时目录 | 部署者指定的绝对可写本机路径 |
| `max-resolution` | 2160P | 720P / 1080P / 2160P |

例如 `AGENVAS_VIDEO_COMPOSITION_LIMITS_MAX_DURATION_MS=180000` 限制成片为三分钟；`AGENVAS_VIDEO_COMPOSITION_LIMITS_MAX_RESOLUTION=1080P` 隐藏并拒绝 4K 导出。保持 `max-scratch-bytes` 足够容纳整片双声道 float PCM（每分钟约 22 MiB）、当前原声/配音 PCM、规范化画面和输出，过低会明确失败。空间保留只是每次检查时的可用量，不预留整个文件系统；其他程序写满磁盘仍会使导出失败并清理本次临时文件。

仓库四份 Compose 配置把私有成片 scratch 放在现有数据卷的独立目录，默认最高 1080p，符合当前 1536 MB 内存的保守部署。要允许 4K，可设置上述 `MAX_RESOLUTION=2160P`；同时在 Compose override 中评估并增加 server 的内存、CPU 与磁盘。其他预算通过 override 的 `environment` 或 Spring 配置传入。修改预算需要重启应用；剪辑器重开会读取新配置，正在编辑的旧页面仍以服务端最终受理校验为准。

画面逐镜处理，最终编码只读取一份画面序列和一条已混合 PCM。成片每进程串行，声音预览最多两个并发；与其他任务或多个应用实例共享机器时仍需额外资源。取消、超时、配额或编码失败会清理当前作业的临时目录；进程或宿主机直接崩溃留下的目录需运维确认无活动作业后清理。不要自动删除其他实例的工作目录。

不修改历史 Flyway 迁移、不增加数据库表。已固定的内容、任务和幂等键继续使用原身份；协议上界内的已受理请求可重放原回执。降低部署预算可能使历史任务的显式重试被当前资源检查拒绝，不会因此重新调用 Provider 或创建隐式生成尝试。版本固定、UNKNOWN 与人工确认规则保持。

真实验证范围与未覆盖组合以开发清单为准。10 分钟、120 镜、600 句、5000 字幕、8 GiB 和 4K 是各维度的配置上界，不表示最大组合已通过压力测试。
