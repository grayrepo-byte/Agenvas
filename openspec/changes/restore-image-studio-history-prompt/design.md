# Design

## Context

动机见 [proposal.md](proposal.md)，行为见 [工作台增量规格](specs/image-studio/spec.md)。桌面历史栏和窄屏历史抽屉已共用历史卡片点击处理；每条记录包含不可变的请求提示词。编辑栏使用账户内存草稿；待受理命令有单独的冻结请求，并暂时锁定编辑。历史浏览在等待期间仍可用。

## Goals / Non-Goals

**Goals:** 复用已有历史卡片、编辑栏和草稿更新路径；将回填绑定到明确的用户操作，不绑定查询结果或当前批次变化。

**Non-Goals:** 不引入多级撤销、草稿库、额外网络读取或持久化；不改变「回填参数」的全量恢复语义，也不改变首张揭晓的归属。

## Decisions

1. **在历史卡片被激活时，直接从卡片所在的批次取原提示词。** 桌面和窄屏复用同一处理。卡片必须对应至少一张已归档图片；不等图片字节或详情请求。该动作更新预览选择和编辑栏提示词，给用户一个可编辑副本，不修改原批次。相比监听当前批次变化，点击事件不会把初始化、轮询或切换同批变体误认为用户要求回填。没有图片的记录或编辑栏锁定期间，只切换预览，不排队补做回填。
2. **撤销只回退最近一次实际改变的提示词。** 把旧文本与现有账户内存草稿一起保留一份，包括空字符串。点击提示词相同的卡片不替换撤销记录；连续点不同历史时，撤销回到最后一次有效回填前的文字，不改变主图或其他参数。用户继续手改提示词、显式回填全量参数或提交生成时清除这次回填的撤销入口，避免把新的编辑误当成误点来覆盖。不用浏览器原生撤销，因为程序写入受控输入时不能依赖原生撤销栈。
3. **保持当前浏览节奏。** 「撤销回填」放在编辑栏附近，不限时、不弹确认框、不自动抢焦点；手机仍关闭历史抽屉，依现有行为归还焦点，不强制唤起软键盘。新增文案走四语言目录。

## Risks / Trade-offs

- 回填只改文字，当前模型或参考图可能与历史设置不同 → 明确保留「回填参数」，需要复现原配置时仍由用户显式选择。
- 历史详情、轮询与编辑可能交错 → 只用用户点击时已可读的批次提示词写草稿，不让稍后的响应再次赋值；组件和浏览器验收覆盖快速切换后继续编辑以及单次生成边界。

## Migration Plan

仅发布前端变更，无数据迁移或配置升级。回滚前端即可恢复原历史浏览行为，原始批次与归档文件不受影响。
