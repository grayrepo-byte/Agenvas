# Design

## Context

`ImageStudioService` 已证明工作台可以用内部项目承载现有资产、任务、事件与用量，而不创建画布节点（ADR 0090）。现有 `DirectMediaTaskService` 的视频受理与画布草稿、节点目标和选用绑定；它不能直接作为独立工作台入口。`MockVideoAdapter` 可离线生成真实 MP4，`ArkSeedance2Adapter` 已能将 `START_FRAME` / `END_FRAME` 映射到供应商帧角色并轮询原请求。

## Goals / Non-Goals

**Goals:** 保持所有权、任务幂等及不可变结果边界；复用现有视频能力、工作器和播放能力；让新入口和已有画布、生图行为可独立验证。

**Non-Goals:** 不把工作台抽象成通用编辑器或将已有历史迁移进新表；不复用画布草稿受理、不增加供应商协议、出站地址或公开素材端点。

## Decisions

### 1. 类型化内部作用域，不用画布或复用图片作用域

增加 `ProjectPurpose.VIDEO_STUDIO`，用增量迁移为每个所有者建立唯一的同类作用域。用户项目和生图工作台原有数据不变。用独立的 `video_studio_generation` 记录一次命令：归属项目和所有者、命令键、规范请求摘要、不可变设置快照、关联 Task ID 和时间。每条命令只对应一个视频 Task；视频或原生额外输出不追加 Task。历史用稳定的 `(created_at, id)` 游标分页，由现有 Task 状态与归档版本投影，不再保存一份任务状态。

优先提取只有两处实际复用的项目创建与归档规则；保留图片的表、接口和快照格式。共用图片作用域会扩大历史、清理和引用的权限组合；共用画布节点则会带来隐藏节点、选用语义和布局副作用。新增作用域保留现有外键和媒体授权，普通项目列表、管理、画布和 Run 仍只接受 `CANVAS`。

### 2. 独立受理，冻结现有媒体工作器认识的输入

`/api/v1/video-studio` 提供 `context`、`frames`（multipart）、`generations`（提交、分页）及按 ID 详情。上下文暴露能力 ID/版本、可用模式、尾帧支持、有效时长范围及默认值、画幅和实际可配置参数。只接受已发布、启用且适配器位于 `MOCK_VIDEO` / `ARK_SEEDANCE_2_I2V` 白名单的能力。模式取发布声明与 `TEXT` / `START_END` 的交集，再按缩紧后的图片上限判定可用角色。Mock 和 Seedance 现有路径没有独立分辨率选择，不显示或接受无效果设置。有效画幅在受理时确定；需要解析 `AUTO` 时使用 `16:9`，不读取画布或用户项目默认值。

帧图复用实际解码、静态图片限制和私有资产上传；字节处理不持有生成受理事务。服务端以固定的版本验证所有者、`VIDEO_STUDIO` 项目、`IMAGE` 类型和资产身份；`TEXT` 不接受输入；`START_END` 只接受一张 `START_FRAME` 和受支持时的一张 `END_FRAME`。工作台表单切换时先计算不兼容项并确认，再更新草稿；服务端不依赖前端验证。

短事务中先按所有者与命令键核对原快照摘要，然后校验当前能力版本，创建命令、VIDEO 产物目标、Task、固定绑定、用量预留和事件。同键重放不受后续配置变更影响，异体冲突。遵循已被消费端支持的整数秒任务冻结格式（当前 `VideoDuration` 支持到 v7），分别固定业务时长、规范化的 `mediaInput`、Provider 有效参数和价格。增加显式 `executionSurface=VIDEO_STUDIO`；开始提交及归档时校验此面只接受 `VIDEO_GENERATION` 和正确作用域，不接受画布节点、来源节点或 Run。将媒体验证限于该面允许的角色，复用已有媒体任务编排而不模拟画布 `MediaDraft`。

Seedance 继续使用原协议和角色映射，视频工作台帧图归一化和请求画幅使用同一固定比例，旧画布保持自身规则。不发送 `generate_audio`，保留返回音轨（ADR 0066）。Mock 使用离线演示渲染器；其素材校验与冻结快照支持两帧，但既有 Mock 画面不模拟模型的尾帧过渡。两种帧角色的实际出站请求通过隔离假 HTTP 验证。

### 3. 沿用异步状态与归档，只输出私有版本

`MediaExecutionWorker` 执行原有租约、提交检查点、轮询、归档和用量规则。云端已受理只用原请求 ID 查询或刷新过期下载；供应商受理不确定保留 `UNKNOWN`。已有字节或 Task 稳定归档身份只用于完成原归档；无恢复证据时明确阻塞或待核实，不调用生成。复用 `TaskService` 归档主结果或额外／晚到结果的不可变版本，并扩展 archive-only 路由识别工作台类型；图片的一次性完成检查点保持图片专用。有了 VIDEO 资产后通过现有私有 `/content`、`HEAD`/Range 与海报端点读取，复核所有者和作用域，禁止透传原始供应商 URL。浏览器用轮询查询工作台详情，而不是开放画布快照或 SSE 给内部项目。由视频探测提供真实宽高和媒体毫秒时长，与冻结的请求整数秒区分。

### 4. 复用工作台布局和视频播放，不直接复用生图状态机

新增独立 `VideoStudioPage` 与 `/video-studio` 路由，复用 shadcn、工作台中轴布局规则、历史抽屉、现有视频播放与 `MediaPreviewDialog` 的视频路径。用 TanStack Query 管历史和详情，编辑草稿与受理未确认命令隔离到当前所有者。仅明确点击含视频历史时回填提示词，按来源保留一次撤销；显式回填完整设置读取来源最新详情并核对帧可读性，不被晚到响应覆盖新草稿。过期能力需用户选择当前可用设置再生成。采用静态封面、现有同源播放器、明确播放指令，切换历史或放大播放器时暂停或卸载旧实例；在浏览器媒体错误时重载私有资源而不调用生成 API。窄屏保留可见标签和默认不唤起软键盘。避免把图片首张揭晓、数量控件或大量图片专用分支搬入视频。

## Risks / Trade-offs

- [目前 Mock 的时长解析只支持既有冻结 schema；新工作台不能借用图片请求的 schema] → 将业务命令快照与 Task schema 分开，用离线合成 MP4 和断点恢复专项验证，而不仅验证 Mock HTTP 回执。
- [Seedance 模式正确但首尾帧归一化比例仍可能来自项目默认值] → 对横、竖比验证出站帧尺寸及角色参数一致，回归既有画布请求。
- [长视频回传和历史容易触发无关读取与带宽浪费] → 历史列表只读封面；播放器按需读取支持 Range 的归档，关闭或换项停止上一条声音；不自动转码或缓存整段视频到前端内存。
- [鉴权、过期 URL 或归档重试可能造成误重发、越权或重建用量] → 用真实 PostgreSQL、隔离异步假服务和真实媒体文件覆盖重复提交、跨账户以及故障恢复；区分假服务通过与真实付费验收。

## Migration Plan

使用新增 Flyway 脚本扩充项目用途约束和唯一索引，新建带同作用域约束的工作台记录表；不重写旧 migration、Task 或媒体。按 ADR 0012 在一次性 PostgreSQL 重新生成 jOOQ，OpenAPI 同步生成 TypeScript，同一版本部署前后端。升级前备份数据库及素材；回退时先停止新入口和工作器，保留新记录与归档，优先前向修复。需要退回不认识新作用域的旧服务时，按运维流程用配套旧镜像及一致性备份恢复，不通过删表或改 Flyway 历史回退。
