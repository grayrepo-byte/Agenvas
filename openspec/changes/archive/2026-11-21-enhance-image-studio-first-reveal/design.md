# Design

## Context

动机见 [proposal.md](proposal.md)，行为见 [工作台规格](specs/image-studio/spec.md)。`ImageStudioPage` 已区分本次提交与历史浏览，并按批次记住所选不可变版本；编号和「已出图」来自 `studioGallery` 的归档结果。当前 `StudioBatchResults` 在出现活动结果时直接替换取景框，`ResultPhoto` 再处理原图加载，缩略图则只是背景，无法报告何时可显示。

## Goals / Non-Goals

**Goals:** 将服务端结果可用和浏览器图片可显示分开；以同一舞台的两层呈现衔接取景框与首张照片，不增加生成等待时间。

**Non-Goals:** 不为动画向服务端请求进度，不等待整个批次，不为动效预取所有原图，不抽象成全站动效框架。

## Decisions

1. **只为用户正在看的新请求启用一次揭晓。** 从显式生成开始建立当前页面内的揭晓资格；收到回执后绑定到该批次，回执已经带图也按同一规则处理。用户切去历史、主动改选其他变体或离开工作台时结束这次自动揭晓资格，晚到的图片事件不得拉回主图；不持久化资格，不从历史状态推断资格。比起对所有首次加载播放，这能把动效限定在用户刚发起的动作上。
2. **用真实图片可显示的事件触发，不以归档计数或计时器触发。** 归档结果立即计入已出图张数并填入对应胶片；生成扫描退出，取景框显示正在加载预览。复用胶片的私有缩略图加载状态，同时正常加载当前候选的私有原图；有效缩略图或原图先可显示即可揭晓，不给每个结果额外预载原图。多个结果在同一轮返回时，哪个先可显示就选哪个；如果同时可显示或已在缓存中，按胶片顺序决胜。图片回报按批次和不可变版本核对，忽略已离开或已改选的候选。揭晓后固定该版本，后续结果只更新胶片；缩略图到原图是同版本清晰度提升，不再播放揭晓。
3. **一个主舞台，两层交叉淡入淡出。** 复用现有动效 token 和 CSS，两层在同一取景区域定位，取景框退场与照片出现约 240 ms，同时对应编号短亮一次；不加白闪、整图缩放、滑移或人为停顿。照片保持完整比例；不为动画插值布局尺寸。退场层是纯视觉，不抢焦点或重复朗读。系统减少动态效果时省略淡入淡出与编号短亮，不等动画结束才显示图片。
4. **资源失败不改写生成状态。** 缩略图失败但原图仍在载入时保留取景框，原图成功即可直接完成揭晓；缩略图可见但原图失败时保留缩略图并说明原图不可用。已有归档结果，但既没有可显示的图片也没有正在载入的候选时，显示预览不可用，不恢复扫描、不改计数、不自动重新生成。若之后另一张图可显示，只有仍有揭晓资格且未选中其他变体时才可触发首张揭晓。

## Risks / Trade-offs

- 已缓存资源可能早于常规加载通知可用 → 冷缓存和热缓存都覆盖，不能让取景框卡在等待，也不能闪过空舞台。
- 多图乱序或历史切换可与图片加载同帧发生 → 验收覆盖暂留取景框、非 `01` 先显示、第二张不替换、切走不抢回，以及晚到的原图不重播。
- 主图区在窄屏遇到横竖图比例变化 → 取景框和照片在同一舞台叠放，浏览器定向验收检查不先留白、不裁切，不遮挡胶片或编辑区。

## Migration Plan

仅发布前端变更；无需数据或配置迁移。回滚前端版本即可恢复原展示，已有批次和结果不受影响。
